03. 주요 용어

03. 주요 용어

가이드라인을 읽고 작성할 때 필요한 용어를 확인하세요.

용어를 클릭하면 상세 설명과 활용 방법이 나옵니다. 여러 용어를 함께 펼쳐 비교할 수 있습니다.

프레임워크에 대한 이해

1.GapZer0 프레임워크

국내 정보보호 요구사항과 NIST CSF 2.0의 보안 목표를 연결한 Control 체계입니다. ISMS-P와 CSF의 매핑 및 개인정보 보호법 검토를 바탕으로, 공통 요구사항과 보완할 사항을 15개 보안 영역·121개 Control로 정리했습니다.

이렇게 활용하세요

Control 이행 안내에서 조직에 필요한 영역을 찾아보고, 각 Control의 적용 조건을 확인하세요.

2.보안 영역

보안 목적과 활동의 성격이 유사한 Control을 묶은 분류입니다. 가이드라인에서는 ISO/IEC 27002:2022의 운영 역량(Operational Capabilities)을 참고한 15개 영역을 사용합니다.

이렇게 활용하세요

예를 들어 Identity and Access Management는 신원 확인·인증·접근권한 관리를 다룹니다. 영역 이름은 영어로 표시되며 각 영역 소개에서 범위를 확인할 수 있습니다.

3.Control(통제)

특정 보안 목적을 달성하기 위해 조직이 수행해야 하는 활동의 단위입니다. 정책이나 기술 설정뿐 아니라 운영·점검·개선 활동도 포함합니다. 하나의 Control에는 여러 이행 활동이 들어갈 수 있습니다.

이렇게 활용하세요

자가 진단은 질문별이 아니라 121개 Control별로 수행합니다. 한 활동만 확인하지 말고 해당 Control의 Implementation Guide 전체를 검토하세요.

4.Control ID · Control Name

Control ID는 Control을 구분하는 식별번호이고, Control Name은 Control의 활동을 나타내는 이름입니다. 예를 들어 GOV-C-01은 Governance 영역의 Common Control이며 이름은 ‘전략 결과 검토·방향 조정’입니다.

이렇게 활용하세요

문서·자가 진단·Excel에서 같은 Control을 찾을 때 ID를 사용합니다. Excel을 다시 불러오려면 제공된 ID를 변경하지 마세요.

5.Control Class(통제 유형)

ISMS-P와 NIST CSF 2.0의 매핑에서 Control이 맡는 역할에 따라 Common·Enhancement·Local로 나눈 분류입니다. 이행 수준이나 중요도를 나타내는 등급은 아닙니다.

이렇게 활용하세요

ISMS-P 인증을 준비할 때도 Common·Local뿐 아니라 Enhancement에 포함된 ISMS-P 요구사항을 함께 확인해야 합니다.

6.Common

ISMS-P와 NIST CSF 2.0에서 보안 목적과 요구사항이 충분히 겹치는 부분을 통합한 Control입니다. 두 기준에 공통으로 필요한 활동을 하나의 Control로 정리합니다.

이렇게 활용하세요

예: GOV-C-01은 관리체계 점검·경영진 참여와 위험관리 전략의 결과 검토·방향 조정이라는 공통 목적을 연결합니다. 여기서 Common은 GapZer0의 Control 유형을 뜻합니다.

7.Enhancement

ISMS-P의 관련 요구사항만으로 충분히 다루지 못하는 CSF의 보안 목표를 보완하는 Control입니다. 기존 국내 요구사항과 추가로 필요한 활동을 함께 살펴봐야 합니다.

이렇게 활용하세요

ISMS-P Limitation에서 부족한 부분을, CSF Coverage에서 보완하려는 결과를 확인하세요. ‘추가 Control’이라는 이유만으로 국내 준수사항까지 제외하지 않습니다.

8.Local

CSF의 Subcategory에 직접 매핑되지 않지만 국내 인증과 개인정보보호 요구사항을 유지하기 위해 마련한 Control입니다. 매핑된 CSF 항목은 N/A로 표시됩니다.

이렇게 활용하세요

예: LCM-L-01은 ISMS-P의 개인정보 수집·이용 요구사항을 반영합니다. CSF 매핑이 없다는 뜻이며, 조직에 적용되지 않는다는 뜻은 아닙니다.

Control 이행 안내

9.Control Objective

Control을 통해 달성하려는 보안 목적과 기대 결과입니다. 활동을 수행하는 이유와 달성하려는 상태를 설명합니다.

이렇게 활용하세요

개선 후에는 조치를 완료했다는 사실뿐 아니라 이 목적을 달성했는지도 확인하세요.

10.Control Statement

Control의 목적을 달성하기 위해 수행해야 하는 핵심 요구사항입니다. Objective가 ‘달성하려는 결과’라면 Statement는 ‘수행해야 할 사항’을 설명합니다.

이렇게 활용하세요

요구사항을 먼저 이해한 뒤 Implementation Guide에서 구체적인 수행 방법을 확인하세요.

11.적용 조건

Control이 필요한 대상·상황·업무 특성 등을 설명하는 항목입니다. 조직의 적용 범위와 실제 환경을 대조하여 해당 여부를 판단합니다.

이렇게 활용하세요

아직 이행하지 못했거나 자료가 부족한 상태와 적용되지 않는 상태는 다릅니다. 적용 제외로 평가할 때는 제외 사유와 판단에 사용한 자료를 기록하세요.

12.Control Owner

Control의 이행과 유지에 책임을 지는 부서 또는 역할입니다. 가이드라인에 제시된 역할을 참고해 실제 조직의 업무 분장에 맞는 책임자를 정합니다.

이렇게 활용하세요

자가 진단의 ‘조치 담당자’는 개별 개선조치를 수행하는 담당자입니다. Control 책임자와 같을 수도 있지만 항상 같은 것은 아닙니다.

13.Stakeholders

Control 수행에 참여하거나 협조하는 관련 부서·역할입니다. 정보를 제공하거나 실행·검토·협의에 참여합니다.

이렇게 활용하세요

접근권한 관리에서는 정보보호 담당자 외에도 인사 부서, 시스템 관리자, 업무 책임자 등의 협업이 필요할 수 있습니다.

14.Implementation Guide

Control을 실제로 이행하기 위한 주요 활동과 구체적인 실행 방향입니다. 조직의 업무 절차와 시스템 환경에 맞게 적용합니다.

이렇게 활용하세요

자가 진단의 직접적인 점검 기준입니다. 여기에 제시된 활동이 실제로 수행되는지 Evidence와 함께 확인하세요.

15.Evidence

Control의 이행 사실을 확인하는 데 사용할 수 있는 자료입니다. 정책·절차·승인 기록·설정정보·로그·점검 결과 등이 포함됩니다. 가이드라인의 Evidence는 어떤 자료를 살펴볼지 안내합니다.

이렇게 활용하세요

문서가 있다는 사실만 확인하지 말고 적용 대상·기간·현재 운영 상태와 일치하는지 살펴보세요. 실제로 확인한 자료는 자가 진단의 ‘확인한 증적’에 적습니다.

16.매핑된 ISMS-P · CSF 항목

Control과 연결된 원본 인증기준 또는 CSF 항목입니다. 매핑은 두 기준의 목적·활동·범위를 비교해 서로 대응하는 항목을 연결하는 작업입니다. CSF의 Subcategory는 구체적인 보안 결과를 설명하는 하위 항목입니다.

이렇게 활용하세요

기존 인증 업무와 Control을 연결하거나 설계 근거를 확인할 때 사용합니다. 매핑되었다는 사실만으로 모든 요구사항의 이행이 보장되지는 않습니다.

17.Gap

비교하는 두 기준 사이에서 충분히 대응하지 않거나 추가 보완이 필요한 차이입니다. 프레임워크 제작에서는 ISMS-P와 CSF 요구사항의 차이를 분석했습니다.

이렇게 활용하세요

기준 간 Gap과 조직의 이행 부족은 구분하세요. 자가 진단에서는 조직이 Control을 어느 정도 이행하는지 확인하고 미흡한 사항을 개선합니다.

18.ISMS-P Limitation

Enhancement Control에서 기존 ISMS-P 요구사항만으로 충분히 다루지 못하는 부분을 설명합니다. 해당 Control에 추가 보완이 필요한 이유를 보여줍니다.

이렇게 활용하세요

ISMS-P 전체가 부족하다는 뜻이 아니라, 연결된 CSF 목표와 비교했을 때의 구체적인 차이를 읽는 항목입니다.

19.CSF Coverage

Enhancement Control을 통해 충족하거나 보완하려는 CSF의 보안 결과와 범위를 설명합니다.

이렇게 활용하세요

ISMS-P Limitation과 함께 읽으면 ‘어떤 차이가 있고, 이 Control로 무엇을 보완하는가’를 파악할 수 있습니다.

자가 진단과 기록

20.자가 진단

각 Control의 Implementation Guide와 실제로 확인한 자료를 바탕으로 조직의 현재 이행 상태를 스스로 점검하는 활동입니다. 평가 범위·기간·담당자·평가일을 정하고 Control별 결과와 근거를 기록합니다.

이렇게 활용하세요

현재 양식은 121개 Control을 기준으로 합니다. 별도 평가 질문에 답하거나 Design·Implementation·Operating Effectiveness별로 나누어 평가하는 방식이 아닙니다.

21.평가 결과

충족·부분 충족·미충족·적용 제외의 네 가지 결과 중 하나를 선택합니다.

이렇게 활용하세요

충족: 적용되는 활동을 모두 이행하고 현재 운영 상태를 반영하는 증적으로 확인할 수 있음.

부분 충족: 핵심 활동은 이행하지만 일부 활동이나 증적에 보완이 필요함.

미충족: 핵심 활동 또는 대부분의 활동을 이행하지 못함.

적용 제외: 적용 범위와 조건을 검토한 결과 해당하지 않으며 사유를 기록함.

판단에 필요한 정보가 부족하면 결과를 선택하지 않은 상태로 저장합니다. 이 미평가 상태는 다섯 번째 평가 결과가 아닙니다.

22.평가 근거

현재 상태를 어떻게 확인했고 왜 해당 결과를 선택했는지 설명하는 기록입니다. 현황과 미흡한 사항, 적용 제외 사유 등을 적습니다.

이렇게 활용하세요

예: ‘권한 검토는 수행했으나 퇴직자 2명의 권한 회수 완료 기록을 확인하지 못함.’ 미충족이고 확인한 자료가 없으면 그 사유를 여기에 적습니다.

23.확인한 증적

해당 평가 결과를 판단하기 위해 실제로 확인한 자료입니다. 자료 이름, 보관 위치 또는 링크, 버전·대상 기간 등을 기록합니다.

이렇게 활용하세요

예: ‘접근권한 검토대장 / 내부 문서함 경로 / 2026년 3분기’. 자료 파일 자체를 사이트에 올리는 항목은 아닙니다.

24.개선계획

미흡한 사항을 어떻게 개선할지, 누가 언제까지 수행할지 정한 기록입니다. 개선조치·조치 담당자·완료 예정일·진행 상태로 구성됩니다.

이렇게 활용하세요

부분 충족·미충족이면 네 항목을 작성합니다. 진행 상태는 예정·진행 중·완료 중 선택합니다. 조치 완료 후에는 증적과 평가 근거를 갱신하고 다시 평가하며, 결과가 자동으로 충족으로 바뀌지는 않습니다.

25.브라우저 저장

작성 내용을 서버가 아닌 현재 기기의 브라우저에 보관하는 기능입니다. 같은 기기·브라우저·사이트 주소에서 이어서 작성할 수 있습니다.

이렇게 활용하세요

브라우저 데이터를 삭제하거나 다른 환경에서 접속하면 기존 기록을 이용하지 못할 수 있으므로 Excel로 별도 보관하세요.

26.Excel 템플릿 · 불러오기

‘평가 기록’ 시트의 상단에는 평가 기본정보를, 아래에는 Control별 기록을 작성합니다. 9개 열은 Control ID·Control Name·평가 결과·평가 근거·확인한 증적·개선조치·조치 담당자·완료 예정일·진행 상태입니다.

이렇게 활용하세요

빈 템플릿에는 121개 Control이 포함됩니다. 작성 내용을 다운로드하면 하나라도 입력한 Control만 포함됩니다. 제공된 .xlsx 양식의 시트 이름·항목 위치·열 구조·Control ID를 유지하세요. 불러오기를 확정하면 현재 평가 전체가 교체되므로 먼저 백업합니다.
