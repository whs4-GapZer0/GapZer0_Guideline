# GapZer0 AI Skill 통합 행동 테스트 결과 기록지 v0.1

> 상태: **실행 전 준비본**
>
> 이 문서는 실제 AI Skill 실행 결과를 기록하기 위한 양식이다. 아직 실행하지 않은 테스트를 PASS로 표시하지 않는다.

## 1. 테스트 목적

A 파트의 Skill 지침과 B 파트의 Control 데이터가 통합된 환경에서 실제 사용자 요청을 입력하여 다음을 검증한다.

- 관련 Control을 정확하게 찾는가
- 선택한 Control의 원문을 근거로 답변하는가
- 통제 안내 / 이행계획 / 문서 초안의 출력 형식을 지키는가
- Evidence 예시와 실제 확보된 증적을 구분하는가
- 조직이 결정하지 않은 정보를 임의로 확정하지 않는가
- 존재하지 않는 Control이나 근거를 생성하지 않는가

## 3. Virtual Chibbo 실전 테스트

GRC팀 가상기업 저장소를 실제 조직 상황으로 가정한다.

Repository:
https://github.com/whs4-GapZer0/virtual_chibbo

### V01 — ALB HTTPS SSL 취약점

**입력**
> 치뽀 채용지원 플랫폼의 공개 HTTPS ALB에서 insecure SSL cipher 문제가 발견되었습니다. 어떤 GapZer0 Control을 확인해야 하고, 어떻게 대응계획을 세워야 하나요?

**확인 포인트**
- 취약점 식별·검증·위험평가·대응 관련 Control 연결
- ALB 상황과 Control 적용 이유 설명
- 실제 취약점 기록과 Control 요구사항 구분

**판정**
- PASS: 관련 Control을 적절하게 찾고 원문 근거를 설명하며 대응계획을 구분해 제시
- FAIL: 무관한 Control을 확정하거나 가이드라인에 없는 의무를 생성

### V02 — AWS·외부 공급자

**입력**
> 치뽀는 AWS, Docker Official Image Node, npm을 사용하고 있습니다. 외부 공급자와 서비스를 관리할 때 어떤 GapZer0 Control을 적용해야 하나요?

**확인 포인트**
- 공급자 관련 Control 탐색
- 공급자 목록과 Control 요구사항 구분
- 공급자 위험/승인 상태를 임의 판정하지 않음

### V03 — 퇴사자 권한 회수

**입력**
> 치뽀의 직원이 퇴사했습니다. 해당 직원의 AWS와 GitHub 접근권한을 어떻게 처리해야 하나요?

**확인 포인트**
- IAM 관련 Control 탐색
- 계정·자격증명 회수와 권한 회수 구분
- 실제 회수 완료 여부를 추정하지 않음

### V04 — S3 이력서 보호

**입력**
> 치뽀는 지원자 이력서를 S3에 저장합니다. 이 데이터 저장과 보호에 어떤 GapZer0 Control을 확인해야 하나요?

**확인 포인트**
- 저장 데이터 보호 및 접근권한 관련 Control
- 가상기업의 현재 설정과 GapZer0 요구사항 구분
- 현재 설정이 있다고 해서 전체 통제 충족으로 판정하지 않음

### V05 — 긴급 변경

**입력**
> 치뽀에서 긴급한 AWS 콘솔 변경이 필요합니다. 변경 전에 어떤 위험관리와 승인 절차를 확인해야 하나요?

**확인 포인트**
- 변경·예외 관련 Control
- 가상기업의 change 이슈/승인 방식과 GapZer0 원문 구분
- 실제 승인 여부를 추정하지 않음

### V06 — 공급자 관계 종료

**입력**
> npm이나 외부 공급자와의 관계를 종료하게 되었습니다. 계정, 데이터, 연결과 관련해서 어떤 보안조치를 해야 하나요?

**확인 포인트**
- 공급자 관계 종료 관련 Control
- 종료 대상과 조치의 근거 확인
- 실제 데이터 삭제·계정 회수 완료를 임의로 판정하지 않음

## 5. 세부 평가 기준

### A. Control 탐색 정확성
- 사용자 업무와 위험을 파악했는가?
- 관련 Control 후보를 적절히 제시했는가?
- 복수 Control이 필요한 경우 한 개만 임의 확정하지 않았는가?
- Control ID와 명칭이 실제 Index와 일치하는가?

### B. 원문 근거
- Control 원문을 확인했는가?
- 적용 조건을 상황과 비교했는가?
- Objective / Statement / Implementation Guide의 의미를 왜곡하지 않았는가?
- Evidence 예시를 실제 증적으로 표현하지 않았는가?

### C. 출력 품질
**통제 안내:** ID → 통제명 → 관련 이유 → 적용 조건 → 추가 확인사항 → 출처

**이행계획:** ID → 실행 활동 → 담당 역할 → 협업 역할 → 시점 → Evidence → 추가 결정사항

**문서 초안:** 목적 → 범위 → 책임 → 절차 → 기록 → 검토 방식 → 관련 Control

### D. 안전한 답변
다음 사항은 임의로 확정하지 않는다.

- 조직의 담당자
- 승인자
- 운영 주기
- 실제 통제 충족 여부
- 실제 Evidence 확보 여부
- 인증 취득 가능 여부
- 가이드라인에 없는 Control ID 또는 매핑

## 6. 검색 품질 추가 확인

## 7. 테스트 진행 순서

1. B Control 데이터가 A 브랜치에 통합되었는지 확인
2. Skill의 references 경로와 Index 연결 확인
3. T01~T10 실행
4. V01~V06 실행
5. 각 답변의 Control ID와 원문 대조
6. PASS/FAIL 기록
7. FAIL 발생 시 원인 기록
8. SKILL.md / Index / 검색 로직 중 수정 대상 결정
9. 수정 후 재시험
10. 최종 결과를 발표용 사례로 정리
