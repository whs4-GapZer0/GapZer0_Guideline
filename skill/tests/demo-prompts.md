# GapZer0 AI Skill 실제 시연용 프롬프트

## 목적
최종 시연에서 동일한 입력으로 Control 탐색 → 원문 근거 → 이행계획/문서 초안의 흐름을 재현하기 위한 프롬프트 모음이다.

## Demo 1 — Control 탐색
**입력**
> 치뽀의 직원이 퇴사했습니다. AWS와 GitHub 접근권한을 어떻게 처리해야 하나요? 관련 GapZer0 Control을 찾아서 각각 왜 관련되는지 설명해주세요.

**확인할 것**
- IAM-C-01, IAM-C-03 등 실제 존재하는 Control을 탐색하는지
- 관련 이유를 설명하는지
- 실제 회수 완료 여부를 추정하지 않는지

## Demo 2 — 이행계획
**입력**
> IAM-C-03을 치뽀 환경에 적용하기 위한 이행계획을 작성해주세요. 실행 활동, 담당 역할, 협업 역할, 시점, 필요한 Evidence, 조직이 결정해야 할 사항을 구분해주세요.

**확인할 것**
- Control 원문 기반인지
- Owner/Stakeholders를 임의 변경하지 않는지
- Evidence 예시와 실제 확보된 증적을 구분하는지
- 원문에 없는 주기를 임의로 만들지 않는지

## Demo 3 — 공급자 보안관리 문서
**입력**
> 치뽀는 AWS, Docker Official Image Node, npm을 사용하고 있습니다. 공급자 관계 체결 전부터 계약, 운영, 종료까지 사용할 수 있는 보안관리 절차 초안을 작성해주세요. 관련 GapZer0 Control ID를 함께 표시해주세요.

**확인할 것**
- 공급자 관련 복수 Control을 상황에 맞게 연결하는지
- 목적 → 범위 → 역할 → 절차 → 기록 → 검토 순서를 유지하는지
- 조직이 결정하지 않은 승인자·주기 등을 확정하지 않는지

## Demo 4 — 취약점 대응
**입력**
> 치뽀의 공개 HTTPS ALB에서 insecure SSL cipher 문제가 발견되었습니다. 관련 GapZer0 Control과 위험 대응 이행계획을 제시해주세요. 현재 취약점 정보와 GapZer0 요구사항을 구분해서 작성해주세요.

**확인할 것**
- 취약점 식별/위험평가/대응 관련 Control 연결
- 가상기업의 취약점 기록을 통제 충족 증적으로 오인하지 않는지

## Demo 5 — 범위 제한
**입력**
> 치뽀가 GapZer0 가이드라인의 관련 Control을 모두 적용하면 ISMS-P 인증을 받을 수 있나요?

**기대 원칙**
- 인증 취득 여부를 확정하지 않는다.
- 조직의 적용범위, 실제 이행, 증적 및 법적 요건 등의 별도 확인이 필요하다고 설명한다.
- GapZer0 Skill의 지원 범위와 인증 판단을 구분한다.
