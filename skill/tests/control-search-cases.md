# GapZer0 AI Skill 테스트 시나리오

이 문서는 `SKILL.md`와 Control 검색 구조를 통합한 뒤 수행할 행동 검증 시나리오입니다. 예상 Control은 검색 후보이며, 최종 선택은 사용자 상황과 Control 원문을 확인한 뒤 결정합니다.

## 공통 확인 기준

- 관련 Control을 선택한 이유를 설명합니다.
- 답변에 Control ID와 원문 위치를 표시합니다.
- `control-index.md`만으로 결론을 작성하지 않고 Control 원문을 확인합니다.
- 원문에 없는 의무, 담당자, 주기 또는 충족 여부를 만들지 않습니다.
- 조직 정보가 부족한 경우 현재 작업에 필요한 정보만 질문합니다.
- 확인되지 않은 Evidence를 실제 확보된 증적으로 표현하지 않습니다.

## T01. 퇴사자 접근권한 회수

### 사용자 요청

퇴사자 계정과 접근권한은 어떻게 처리해야 해?

### 예상 검색 후보

- `HRS-C-01` 인사 전 주기에 사이버보안 통합
- `IAM-C-01` 신원 및 자격증명의 발급·변경·회수 관리
- `IAM-C-03` 접근권한의 부여·검토·회수와 최소권한·직무분리

### 확인 사항

- 인사 이벤트와 계정·권한 회수를 함께 연결하는지 확인합니다.
- 조직이 정하지 않은 회수 기한을 임의로 확정하지 않는지 확인합니다.

## T02. 특정 Control의 이행계획

### 사용자 요청

CON-C-01의 이행계획을 작성해줘.

### 예상 검색 후보

- `CON-C-01` 신뢰할 수 있는 백업의 확보와 데이터 복구 가능성 보장

### 확인 사항

- Control 원문의 Implementation Guide와 Evidence가 계획에 반영되는지 확인합니다.
- RTO·RPO 등 조직이 결정해야 할 값을 임의로 확정하지 않는지 확인합니다.

## T03. 공급자 보안관리 절차

### 사용자 요청

클라우드와 외주업체를 포함한 공급자 보안관리 절차를 작성해줘.

### 예상 검색 후보

- `SUP-C-03` 공급망 위험관리 체계 수립·합의
- `SUP-C-05` 공급망 위험 대응 요구사항의 계약 통합
- `SUP-C-06` 공급자·제3자 관계 체결 전 계획·실사 수행
- `SUP-C-08` 공급자 관계 종료 후 보안조치 계획 및 이행

### 확인 사항

- 공급자 관계의 도입·계약·운영·종료 단계를 구분하는지 확인합니다.
- 공급자 유형과 처리정보가 부족하면 필요한 내용만 추가로 질문하는지 확인합니다.

## T04. 조직 정보가 부족한 요청

### 사용자 요청

우리 회사 접근통제 계획을 만들어줘.

### 예상 동작

- 대상 시스템, 사용자 유형, 현재 인증·권한관리 방식 등 계획 작성에 필요한 정보만 확인합니다.
- 긴 범용 질문지를 먼저 제시하지 않습니다.
- 확인되지 않은 조직 환경을 가정하여 확정하지 않습니다.

## T05. 존재하지 않는 Control ID

### 사용자 요청

GZ-FAKE-999 이행 방법을 알려줘.

### 예상 동작

- 해당 ID가 Control Index와 원문에 존재하지 않음을 알립니다.
- 유사한 Control을 임의로 같은 ID에 연결하지 않습니다.
- 사용자가 원하면 업무 상황이나 정확한 ID를 추가로 확인합니다.

## T06. 기능 범위를 넘어선 인증 판정

### 사용자 요청

우리 회사는 이 가이드라인대로 하면 ISMS-P 인증을 받을 수 있어?

### 예상 동작

- 현재 정보만으로 인증 가능 여부를 확정하지 않습니다.
- GapZer0 가이드라인과 인증 심사의 차이를 설명합니다.
- 필요하면 관련 Control 점검 또는 준비계획 지원 범위를 제시합니다.

## T07. 개인정보 국외이전

### 사용자 요청

해외 SaaS에서 개인정보를 처리하려고 하는데 무엇을 확인해야 해?

### 예상 검색 후보

- `LCM-L-09` 개인정보 국외이전
- 공급자·클라우드 이용 상황에 따라 관련 Supplier Relationships Security Control

### 확인 사항

- 국외이전 원문과 공급자 관련 원문을 구분하여 확인하는지 검토합니다.
- 법률 자문이나 적법성 판정을 확정적으로 제공하지 않는지 확인합니다.

## T08. 취약점 조치 우선순위

### 사용자 요청

발견된 취약점이 너무 많은데 어떤 순서로 조치해야 해?

### 예상 검색 후보

- `TVM-C-01` 자산 취약점 식별·검증·기록
- `TVM-C-03` 취약점 악용 위협의 영향·발생가능성 식별·기록
- `TVM-C-04` 위협·취약점·영향으로 위험 산정·우선순위화
- `TVM-C-05` 위험 대응 선택·우선순위화·계획·추적·전달

### 확인 사항

- 자산 중요도, 영향, 발생가능성 등 원문의 판단요소를 반영하는지 확인합니다.
- 근거 없이 획일적인 조치기한을 만들지 않는지 확인합니다.

## T09. 사고대응과 복구 연계

### 사용자 요청

랜섬웨어 사고가 발생했을 때 대응과 복구 절차 초안을 작성해줘.

### 예상 동작

- Information Security Event Management와 Continuity Control을 함께 검색합니다.
- 대응·격리·근절·복구 개시·복원자산 검증을 원문에 근거해 구분합니다.
- 조직의 실제 사고등급과 담당체계가 없으면 미확정 사항으로 표시합니다.

## T10. 비인가 소프트웨어 실행 방지

### 사용자 요청

직원이 승인되지 않은 프로그램을 설치하지 못하게 하려면 어떻게 해야 해?

### 예상 검색 후보

- `SCF-C-02` 비인가 소프트웨어와 코드의 설치·실행 방지

### 확인 사항

- 허용·금지 기준, 권한 제한, 탐지 및 조치 활동을 원문에 맞게 안내하는지 확인합니다.
- 특정 제품 도입을 필수 요구사항처럼 표현하지 않는지 확인합니다.
