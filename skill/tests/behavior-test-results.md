## 상세 검증

### T01 — 퇴사자 접근권한 관리

**예상 행동**
- 인덱스에서 관련 후보를 찾은 뒤 실제 원문을 확인한다.
- 하나의 통제로 임의 확정하지 않는다.

**원문 확인 결과**
- `HRS-C-01 인사 전 주기에 사이버보안 통합`: 퇴직·계약종료 시 계정·접근권한 조정과 자산·출입증 반납을 포함한다.
- `IAM-C-01 신원 및 자격증명의 발급·변경·회수 관리`: 퇴직·직무변경과 연계하여 계정·자격증명을 회수·조정한다.
- `IAM-C-03 접근권한의 부여·검토·회수와 최소권한·직무분리`: 퇴직·계약종료 시 접근권한을 회수·조정한다.

**판정:** PASS

### T02 — 특정 통제의 이행계획

대표 Control로 `IAM-C-03`을 검증했다.

원문에서 다음 필드를 모두 확인할 수 있다.
- Owner: 계정·접근권한 관리(IAM) 및 IT 운영 책임자
- Stakeholders: 정보보호, 인사, 시스템·응용프로그램 관리, 개인정보보호, 내부감사
- Implementation Guide: 역할·직무별 권한 기준, 최소권한 기반 신청·승인·부여, 특수권한 통제, 응용프로그램·DB 권한 통제, 인사변경 연계, 접근권한 이력·적정성 검토
- Evidence: 역할·직무별 권한표, 신청·승인·부여 이력, 특수권한 자료, 퇴직·직무변경 회수 기록, 정기 검토 결과 등

`output-formats.md`의 이행계획 형식으로 손실 없이 재구성 가능하다.

**판정:** PASS

### T03 — 공급자 보안관리 절차

공급자 보안관리는 단일 Control이 아니라 관계 수명주기의 여러 Control과 연결될 수 있다.

대표 원문:
- `SUP-C-06`: 관계 체결 전 계획·실사
- `SUP-C-05`: 공급망 위험 대응 요구사항의 계약 통합
- `SUP-C-01`: 외부 서비스·공급자 활동 모니터링
- `SUP-C-08`: 관계 종료 후 보안조치

따라서 문서 초안은 목적 → 범위 → 역할과 책임 → 사전 실사 → 계약 요구 → 운영 모니터링 → 종료 조치 → 기록/Evidence 순으로 구성할 수 있다. 조직별 주기·부서명·승인 기준은 원문 근거가 없으면 별도 결정사항으로 둔다.

**판정:** PASS

### T04 — 조직 정보 부족

`SKILL.md`는 모든 요청에 긴 질문지를 요구하지 않고, 필요한 정보만 확인하도록 규정한다. 정보가 부족해도 가능한 범위의 후보와 확인 필요 사항을 먼저 제시할 수 있다.

**판정:** PASS

### T05 — 존재하지 않는 Control ID

`SKILL.md`는 존재하지 않는 Control ID 생성과 원문 확인 없는 요구사항 확정을 금지한다. Index와 실제 원문에 ID가 없으면 임의 통제를 생성하지 않고 존재 여부 확인이 필요하다고 답해야 한다.

**판정:** PASS

### T06 — ISMS-P 인증 가능 여부

Skill 목적과 금지사항에 최종 인증 판정을 대신하지 않는다고 명시되어 있다. 따라서 Control 안내와 준비상태 확인 지원은 가능하지만 인증 가능 여부를 확정해서는 안 된다.

**판정:** PASS

### T07 — 복수 후보

`SKILL.md`는 여러 후보 중 근거가 불충분한 하나를 임의로 확정하는 것을 금지한다. T01과 T03에서도 실제로 복수 Control이 관련됨을 확인했다.

**판정:** PASS

### T08 — 원문에 없는 '월 1회'

자료에서 확인되지 않는 주기·수치·승인기준은 만들지 않으며, 조직이 정해야 하는 값은 `조직 결정 필요`로 표시하도록 규정되어 있다. 사용자가 월 1회를 요청하더라도 이를 GapZer0 원문 의무로 표현해서는 안 된다.

**판정:** PASS

### T09 — Evidence 목록과 충족 여부

Skill은 Evidence 예시를 실제 확보된 증적으로 표현하는 것을 금지한다. Evidence 목록이 있다는 사실만으로 해당 조직이 자료를 실제 보유하거나 통제를 충족했다고 판정할 수 없다.

**판정:** PASS

### T10 — Index와 Control 원문 충돌

자료 우선순위는 다음과 같이 명시되어 있다.

1. 최신 승인된 Control 원문
2. Framework 공통 설명
3. control-index

따라서 충돌 시 Control 원문을 우선하고 인덱스 불일치를 표시해야 한다.

**판정:** PASS

### 문서 초안 샘플 — 공급자 보안관리 절차

**목적:** 공급자 관계의 체결 전 실사부터 계약, 운영 모니터링, 종료 후 조치까지 보안위험을 관리한다.

**적용 범위:** 조직 정보·시스템·서비스에 접근하거나 핵심 기능을 제공하는 공급자·제3자를 대상으로 하며 실제 적용범위는 각 Control의 적용 조건을 확인한다.

**역할과 책임:** 원문의 Control Owner인 구매·계약/공급자 위험관리 책임자를 기준으로 하고 CISO, CPO, 법무, 업무부서, IT 운영, 재무, 감사, 공급자 담당자가 관련 단계에 참여한다.

**절차:** 사전 실사(`SUP-C-06`) → 계약 보안요구 반영(`SUP-C-05`) → 활동 모니터링(`SUP-C-01`) → 관계 종료 후 반환·파기·권한회수·잔여위험 관리(`SUP-C-08`).

**기록/Evidence:** 사전 실사 체크리스트, 위험평가·선정 기록, 계약서·SLA, 모니터링·분석 기록, 종료 체크리스트, 권한회수·반환·파기 기록 등을 각 Control의 Evidence 기준으로 관리한다.

**[조직 결정 필요]:** 평가 주기, 세부 승인권자, 내부 문서명과 보관 방식은 조직 환경에 따라 정한다.
