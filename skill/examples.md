# GapZer0 AI Skill 사용 예시

아래 예시는 현재 통합된 121개 Control Index와 실제 Control 원문을 기준으로 검증한 대표 시연 예시이다.

## 예시 1. 관련 Control 안내 — 퇴사자 접근권한

**사용자**
> 퇴사자의 접근권한을 어떻게 관리해야 하나요?

**관련 Control**
- `HRS-C-01` — 인사 전 주기에 사이버보안 통합
- `IAM-C-01` — 신원 및 자격증명의 발급·변경·회수 관리
- `IAM-C-03` — 접근권한의 부여·검토·회수와 최소권한·직무분리

**[가이드라인 근거]**
퇴직·계약종료 정보를 관련 부서에 전달하고 계정·자격증명·접근권한을 회수 또는 조정하며 처리 결과를 확인·기록한다.

**[확인 필요]**
대상 시스템, 외부인력 포함 여부, 개인정보처리시스템 여부, 현재 인사정보와 계정관리 절차의 연계 방식을 확인한다.

**시연 포인트**
하나의 Control을 임의로 고르지 않고 인사 이벤트, 자격증명, 접근권한 관리에 해당하는 실제 Control 원문을 함께 확인한다.

## 예시 2. 이행계획 — IAM-C-03

**사용자**
> IAM-C-03의 이행계획을 작성해줘.

| 구분 | 내용 |
|---|---|
| 대상 Control | `IAM-C-03` — 접근권한의 부여·검토·회수와 최소권한·직무분리 |
| 목표 | 직무와 업무 필요성에 따라 최소권한을 부여하고 권한의 생성·변경·검토·회수 전 과정을 관리 |
| 실행 활동 | 역할·직무별 권한 기준 정의 → 최소권한 기반 신청·승인·부여 → 특수권한 별도 통제 → 응용프로그램·DB 세부 권한 통제 → 인사변경과 권한 수명주기 연계 → 권한 이력·적정성 검토 |
| 담당 역할 | 계정·접근권한 관리(IAM) 및 IT 운영 책임자 |
| 협업 역할 | 정보보호, 인사, 시스템·응용프로그램 관리, 개인정보보호, 내부감사 |
| 시점 | 권한 신규 부여·변경·검토·회수, 직무변경·퇴직·계약종료·임시권한 만료 시 |
| Evidence | 역할·직무별 권한표, 권한 신청·승인·부여 이력, 특수권한 자료, 퇴직·직무변경 권한 회수 기록, 정기 접근권한 검토 결과 |

**[조직 결정 필요]**
원문에 고정된 값이 없는 세부 검토 주기와 내부 승인기준은 조직 정책·위험·적용 법적 요구를 확인하여 정한다.

**시연 포인트**
Owner, Stakeholders, Implementation Guide, Evidence를 실제 Control 원문에서 가져오며 원문에 없는 주기를 임의로 추가하지 않는다.

## 예시 3. 실무 문서 초안 — 공급자 보안관리 절차

**사용자**
> 공급자 보안관리 절차 초안을 작성해줘.

### 1. 목적
공급자 관계 체결 전 실사부터 계약, 운영 중 모니터링, 관계 종료 후 조치까지 공급자 관련 보안위험을 관리한다.

### 2. 적용 범위
조직 정보·시스템·서비스에 접근하거나 핵심 기능을 제공하는 공급자·제3자를 대상으로 하며 실제 범위는 각 Control의 적용 조건을 확인한다.

### 3. 역할과 책임
**[가이드라인 근거]** 대표 관련 Control의 Owner는 구매·계약/공급자 위험관리 책임자이며 CISO, CPO, 법무, 업무부서, IT 운영, 재무, 감사, 공급자 담당자가 Stakeholders로 참여한다.

### 4. 업무 절차
1. `SUP-C-06` — 관계 체결 전 서비스 중요도·데이터·접근권한·하위공급망을 파악하고 실사·위험평가를 수행한다.
2. `SUP-C-05` — 위험평가 결과에 따른 보안의무, 사고통보, 감사·점검, 재위탁, 종료·반환·파기 조건 등을 계약에 반영한다.
3. `SUP-C-01` — 공급자 접근과 서비스 활동을 모니터링하고 이상행위를 분석·대응한다.
4. `SUP-C-08` — 관계 종료 시 정보·자산 반환·파기, 계정·인증수단·원격연결 회수, 서비스 전환과 잔여위험을 관리한다.

### 5. 기록 및 Evidence
사전 실사 체크리스트, 위험평가·선정 기록, 계약서·SLA, 접근·감사 로그, 보안경보·분석 기록, 종료 체크리스트, 권한회수·반환·파기 기록 등을 각 Control의 Evidence 기준으로 관리한다.

### 6. 검토 및 개선
운영 중 발견한 이상행위와 미조치 사항을 위험평가·계약조건 개선에 반영하고 종료 후 미해결 사항은 잔여위험으로 추적한다.

### 7. 관련 Control
- `SUP-C-06` 공급자·제3자 관계 체결 전 계획·실사 수행
- `SUP-C-05` 공급망 위험 대응 요구사항의 계약 통합
- `SUP-C-01` 외부 서비스와 공급자 활동에서 발생하는 보안 이상 및 침해 징후 탐지
- `SUP-C-08` 공급자 관계 종료 후 보안조치 계획 및 이행

**[조직 결정 필요]**
평가 주기, 세부 승인권자, 내부 문서명과 보관 방식은 조직 환경에 따라 정한다.

## 예시 4. 범위 초과 요청

**사용자**
> 우리 회사는 ISMS-P 인증을 받을 수 있어?

**Skill 응답 원칙**
GapZer0 Skill만으로 최종 인증 가능 여부를 확정하지 않는다. 조직의 적용 범위와 실제 이행·증적을 확인하지 않은 상태에서는 인증 여부를 단정할 수 있으며, 관련 Control 확인과 준비상태 점검을 지원하는 범위로 답한다.

## 시연 순서

1. 퇴사자 접근권한 질문으로 관련 Control 탐색을 보여준다.
2. `IAM-C-03`을 지정하여 원문 기반 이행계획 생성을 보여준다.
3. 공급자 보안관리 절차 요청으로 복수 Control을 연결한 문서 초안을 보여준다.
4. 인증 가능 여부 질문으로 Skill이 범위를 넘는 판단을 하지 않는지 보여준다.
