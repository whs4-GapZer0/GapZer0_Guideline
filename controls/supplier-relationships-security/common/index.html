Supplier Relationships Security - Common Controls

SUP-C-01

Control Name

외부 서비스와 공급자 활동에서 발생하는 보안 이상 및 침해 징후 탐지

Security Domain

Supplier Relationships Security

Control Class

Common

Control Objective

외부 서비스 제공자와 공급자의 활동에서 발생하는 보안 이상과 침해 징후를 지속적으로 탐지하여 외부자 또는 외부 서비스로 인한 사고를 조기에 식별하고 대응합니다.

Control Statement

클라우드·위탁·유지보수 등 외부 환경의 활동을 적시에 파악하지 못하면 침해 발견이 지연될 수 있습니다. 조직은 공급자의 접근과 서비스 활동을 모니터링하고 이상행위를 분석하여 필요한 대응으로 연계해야 합니다.

적용 조건

적용 시점

외부자가 조직 정보·시스템·시설에 접근하거나 외부 서비스가 핵심 기능을 제공하는 동안 적용합니다.

적용 대상

공급자, 수탁자, 클라우드·유지보수·원격지원 사업자 및 관련 서비스에 적용합니다.

관련 법령

  • 「개인정보 보호법」 제26조 — 개인정보 처리업무를 외부에 위탁하는 경우 위탁 문서화·공개·수탁자 관리 등 관련 의무가 적용됩니다.

Control Owner

구매·계약/공급자 위험관리 책임자

Stakeholders

CISO, CPO, 법무 담당자, 업무부서, IT 운영 담당자, 재무 담당자, 감사 담당자, 공급자 담당자

매핑된 ISMS-P 항목

  • 2.3.3 외부자 보안 이행 관리
  • 2.10.2 클라우드 보안
  • 2.4.5 보호구역 내 작업
  • 2.6.6 원격접근 통제

매핑된 CSF 항목

  • DE.CM-06 — External service provider activities and services are monitored to find potentially adverse events

Implementation Guide

1. 모니터링 대상 식별

공급자의 접근범위·서비스·취급정보·업무 중요도를 파악하여 모니터링 대상을 정합니다.

2. 탐지 기준 수립

비정상 접속, 과도한 권한 사용, 비인가 변경 등 공급자 관련 이상행위 기준과 보고 경로를 정합니다.

3. 활동 모니터링

원격접속·감사·클라우드 로그와 보안경보를 수집·검토합니다.

4. 분석·대응

이상행위의 영향과 사고 여부를 분석하고 차단·조사·공급자 조치요구로 연계합니다.

5. 정기 검토

반복 이상행위와 미조치 사항을 공급자 위험평가·계약조건 개선에 반영합니다.

Evidence

  • 공급자·서비스 목록: 모니터링 대상과 중요도를 확인합니다.
  • 접근·감사 로그: 공급자 활동의 실제 모니터링을 확인합니다.
  • 보안경보·분석 기록: 이상징후의 탐지·분석을 확인합니다.
  • 사고·후속조치 기록: 탐지 결과가 대응으로 연결됐는지 확인합니다.

SUP-C-02

Control Name

외부 의존성 파악·전달

Security Domain

Supplier Relationships Security

Control Class

Common

Control Objective

조직이 의존하는 외부 산출물·역량·서비스와 그 중요도를 파악하고 관련 부서에 전달하여 외부 의존성으로 인한 위험을 관리합니다.

Control Statement

외부 의존성을 알지 못하면 장애·침해·계약변경 시 업무영향을 판단하기 어렵습니다. 조직은 공급자·클라우드·외부 서비스와 내부 업무·자산의 의존관계를 식별하고 최신 상태로 공유해야 합니다.

적용 조건

적용 시점

외부 서비스 도입·변경·갱신 및 정기 자산·공급자 검토 시 적용합니다.

적용 대상

핵심 업무·정보자산·시스템과 연결된 공급자·외부 서비스에 적용합니다.

관련 법령

  • 「개인정보 보호법」 제26조 — 개인정보 처리업무를 외부에 위탁하는 경우 위탁 문서화·공개·수탁자 관리 등 관련 의무가 적용됩니다.

Control Owner

구매·계약/공급자 위험관리 책임자

Stakeholders

CISO, CPO, 법무 담당자, 업무부서, IT 운영 담당자, 재무 담당자, 감사 담당자, 공급자 담당자

매핑된 ISMS-P 항목

  • 2.3.1 외부자 현황 관리
  • 2.10.2 클라우드 보안
  • 1.2.1 정보자산 식별

매핑된 CSF 항목

  • GV.OC-05 — Outcomes, capabilities, and services that the organization depends on are understood and communicated

Implementation Guide

1. 외부 의존성 목록화

공급자·서비스·데이터·인터페이스와 담당자를 식별합니다.

2. 내부 업무와 연결

각 외부 의존성이 지원하는 업무·자산·서비스와 중단 영향을 연결합니다.

3. 중요도 분류

대체 가능성, 데이터 접근, 중단 영향 등을 기준으로 중요도를 정합니다.

4. 관계부서 공유·갱신

의존성 정보를 자산·BCP·위험관리 담당자와 공유하고 변경 시 갱신합니다.

Evidence

  • 외부 의존성 목록: 공급자와 내부 업무 연결을 확인합니다.
  • 서비스·자산 구성도: 기술적 의존관계를 확인합니다.
  • 중요도 평가 기록: 분류 근거를 확인합니다.
  • 공유·변경 이력: 최신 정보의 전달·유지를 확인합니다.

SUP-C-03

Control Name

공급망 위험관리 체계 수립·합의

Security Domain

Supplier Relationships Security

Control Class

Common

Control Objective

공급망 위험관리의 전략·목표·정책과 운영체계를 수립하고 주요 이해관계자와 합의하여 일관된 공급망 보안관리를 수행합니다.

Control Statement

부서별로 공급자를 개별 관리하면 평가·계약·모니터링 기준이 달라질 수 있습니다. 조직은 공급망 위험관리의 범위, 원칙, 책임, 보고체계를 공식화해야 합니다.

최고경영자(CEO)와 경영진은 공급망 위험관리 정책·전략·목표를 승인합니다. 구매·계약 및 공급자 위험관리 책임자는 실무 수행·보고 및 승인사항의 이행 책임을 유지합니다.

적용 조건

적용 시점

공급망 위험관리 체계 구축·개정, 중요 공급자 도입 시 적용합니다.

적용 대상

조직의 정보·서비스에 접근하거나 핵심 기능을 제공하는 공급망에 적용합니다.

관련 법령

  • 「개인정보 보호법」 제26조 — 개인정보 처리업무를 외부에 위탁하는 경우 위탁 문서화·공개·수탁자 관리 등 관련 의무가 적용됩니다.

Control Owner

구매·계약/공급자 위험관리 책임자

Stakeholders

최고경영자(CEO), 경영진, CISO, CPO, 법무 담당자, 업무부서, IT 운영 담당자, 재무 담당자, 감사 담당자, 공급자 담당자

매핑된 ISMS-P 항목

  • 2.3.1 외부자 현황 관리
  • 1.1.5 정책 수립
  • 3.3.2 개인정보 처리업무 위탁

매핑된 CSF 항목

  • GV.SC-01 — A cybersecurity supply chain risk management program, strategy, objectives, policies, and processes are established and agreed to by organizational stakeholders

Implementation Guide

1. 범위·목표 정의

관리할 공급자 유형, 위험목표와 적용기준을 정합니다.

2. 정책·절차 수립

선정·계약·운영·변경·종료 단계별 요구사항을 문서화합니다.

3. 역할·보고체계 확정

구매·보안·법무·현업의 책임과 승인·보고 경로를 정합니다. 최고경영자(CEO)·경영진이 직접 검토·승인할 정책·전략·목표와 실무 책임자가 승인할 수 있는 운영 사항을 구분하여 문서화하고, 구매·계약 및 공급자 위험관리 책임자의 수행·보고·승인사항 이행 책임을 구분합니다.

4. 승인·전달

최고경영자(CEO)·경영진이 공급망 위험관리 정책·전략·목표를 검토하고 승인합니다. 검토 의견과 승인 결과를 기록하고 관련자에게 시행기준을 전달합니다. 구매·계약 및 공급자 위험관리 책임자는 승인사항을 운영 절차에 반영하고 이행 결과를 보고합니다.

Evidence

  • 공급망 위험관리 정책·전략: 범위·목표·원칙을 확인합니다.
  • 절차·R&R: 단계별 수행책임을 확인합니다.
  • 승인·공지 기록: 최고경영자(CEO)·경영진의 공급망 위험관리 정책·전략·목표 검토·승인과 관련자 대상 전달 및 후속 이행을 확인합니다.
  • 사안별 승인권자와 승인 범위: 경영진이 직접 승인할 사항과 실무 책임자가 승인할 수 있는 사항, 수행·보고 책임의 구분을 확인합니다.

SUP-C-04

Control Name

공급망 참여자 역할·책임 수립·조정

Security Domain

Supplier Relationships Security

Control Class

Common

Control Objective

조직과 공급망 참여자의 보안 역할·책임·권한을 명확히 정의하고 상호 조정하여 책임 공백과 중복을 방지합니다.

Control Statement

공급망에서는 사고통보·접근통제·취약점 조치 등의 책임이 모호해질 수 있습니다. 조직은 내부 부서와 공급자의 책임경계를 계약과 운영절차에 명시하고 변경 시 조정해야 합니다.

적용 조건

적용 시점

공급자 선정·계약·변경·갱신 및 책임변경 시 적용합니다.

적용 대상

구매·보안·법무·현업과 공급자·수탁자 담당자에 적용합니다.

관련 법령

  • 「개인정보 보호법」 제26조 — 개인정보 처리업무를 외부에 위탁하는 경우 위탁 문서화·공개·수탁자 관리 등 관련 의무가 적용됩니다.

Control Owner

구매·계약/공급자 위험관리 책임자

Stakeholders

CISO, CPO, 법무 담당자, 업무부서, IT 운영 담당자, 재무 담당자, 감사 담당자, 공급자 담당자

매핑된 ISMS-P 항목

  • 2.3.2 외부자 계약 시 보안
  • 3.3.2 개인정보 처리업무 위탁

매핑된 CSF 항목

  • GV.SC-02 — Cybersecurity roles and responsibilities for suppliers, customers, and partners are established, communicated, and coordinated internally and externally

Implementation Guide

1. 공급망 활동 식별

평가·접근·변경·사고·종료 활동을 목록화합니다.

2. 책임경계 정의

활동별 책임자·수행자·승인자와 공급자 책임을 정합니다.

3. 계약·절차 반영

책임과 보고기한·연락체계를 계약·SLA·운영절차에 반영합니다.

4. 변경 시 조정

조직·서비스·공급자 변경 시 책임 공백을 재검토합니다.

Evidence

  • RACI·책임표: 역할과 책임경계를 확인합니다.
  • 계약·SLA: 공급자 책임의 공식 반영을 확인합니다.
  • 연락망·변경 기록: 운영 중 책임의 유지관리를 확인합니다.

SUP-C-05

Control Name

공급망 위험 대응 요구사항의 계약 통합

Security Domain

Supplier Relationships Security

Control Class

Common

Control Objective

공급망 위험평가 결과와 보안 요구사항을 계약·협약에 반영하여 공급자가 조직이 요구하는 보안 수준을 이행하도록 합니다.

Control Statement

평가에서 확인된 위험이 계약상 의무로 연결되지 않으면 실제 이행을 요구하기 어렵습니다. 조직은 접근통제, 사고통보, 점검권, 재위탁, 종료조치 등 필요한 보안 요구를 계약에 반영해야 합니다.

적용 조건

적용 시점

신규 계약, 갱신, 중요 서비스 변경 시 적용합니다.

적용 대상

조직 정보·시스템에 접근하거나 서비스를 제공하는 외부자 계약에 적용합니다.

관련 법령

  • 「개인정보 보호법」 제26조 — 개인정보 처리업무를 외부에 위탁하는 경우 위탁 문서화·공개·수탁자 관리 등 관련 의무가 적용됩니다.

Control Owner

구매·계약/공급자 위험관리 책임자

Stakeholders

CISO, CPO, 법무 담당자, 업무부서, IT 운영 담당자, 재무 담당자, 감사 담당자, 공급자 담당자

매핑된 ISMS-P 항목

  • 2.3.2 외부자 계약 시 보안

매핑된 CSF 항목

  • GV.SC-05 — Requirements to address cybersecurity risks in supply chains are established, prioritized, and integrated into contracts and other types of agreements with suppliers and other relevant third parties

Implementation Guide

1. 위험 기반 요구사항 도출

사전평가 결과와 접근·데이터 범위에 따라 계약 요구를 정합니다.

2. 계약조항 반영

보안의무, 사고통보, 감사·점검, 재위탁, 종료·반환·파기 조건을 명시합니다.

3. 예외 승인

반영하지 못한 요구는 위험·대체조치·승인자를 기록합니다.

4. 이행 추적

계약상 요구의 실제 수행과 위반·개선조치를 관리합니다.

Evidence

  • 위험평가·요구사항 목록: 계약 요구의 근거를 확인합니다.
  • 계약서·SLA: 보안 요구의 법적·계약적 반영을 확인합니다.
  • 예외·승인 기록: 미반영 위험의 Control을 확인합니다.

정보·시스템·서비스에 접근하거나 핵심 기능을 제공할 후보 공급자에 적용합니다.

외부 서비스 사고는 공급자 정보와 조치 없이는 원인분석·복구가 지연될 수 있습니다. 조직은 사고통보, 증거제공, 대응·복구 책임과 연락체계를 사전에 정해야 합니다.

Common

공급자 관계 종료 후 남을 수 있는 계정·데이터·장비·연결·의존성을 제거하거나 통제하여 잔여 위험을 수용 가능한 수준으로 관리합니다.

Control Statement

계약이 끝나도 계정, 데이터 사본, 원격연결 등이 남으면 침해위험이 지속됩니다. 조직은 종료 전에 반환·파기·권한회수·서비스 전환과 확인절차를 계획해야 합니다.

적용 조건

적용 시점

계약 만료·해지, 공급자 교체, 서비스 종료 시 적용합니다.

종료되는 공급자·수탁자와 관련 계정·데이터·장비·연결·서비스에 적용합니다.

Stakeholders

매핑된 CSF 항목

  • GV.SC-10 — Cybersecurity supply chain risk management plans include provisions for activities that occur after the conclusion of a partnership or service agreement

Implementation Guide

1. 종료 체크리스트 수립

계정·권한·데이터·장비·연결·문서·하위공급자를 식별합니다.

2. 반환·파기·회수

정보와 자산을 반환·파기하고 계정·인증수단·원격연결을 회수합니다.

3. 서비스 전환

대체 공급자·내부 운영으로 안전하게 이전하고 업무연속성을 확인합니다.

4. 잔여위험 확인

완료 증적을 검토하고 미해결 사항은 위험등록·추적합니다.

Evidence

  • 종료 체크리스트: 종료 대상과 조치상태를 확인합니다.
  • 권한회수·연결해제 기록: 접근 제거를 확인합니다.
  • 반환·파기 확인서: 정보·자산의 잔존 여부를 확인합니다.
  • 잔여위험 기록: 미해결 위험의 추적을 확인합니다.
