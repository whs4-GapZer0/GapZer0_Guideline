System and Network Security - Common Controls

System and Network Security - Common Controls

SNS-C-01

Control Name

네트워크·환경의 비인가 논리적 접근과 사용 방지

Security Domain

System and Network Security

Control Class

Common

Control Objective

사내에서 직접 운영하는 서버·네트워크(온프레미스), 클라우드, 무선 및 원격 환경에서 조직의 네트워크와 정보시스템으로 이어지는 네트워크 연결·로그인 등 논리적 접근 경로를 식별·통제하여, 인가된 사용자·단말·서비스만 업무상 필요한 범위에서 접근하고 사용할 수 있도록 합니다. 이를 통해 외부 침입, 우회접속, 과도한 내부 접근 및 설정 오류로 인한 중요정보·개인정보 노출 위험을 줄이고, 네트워크와 기술 환경이 조직의 위험 수준에 맞게 보호되는 상태를 유지합니다.

Control Statement

조직의 업무는 온프레미스 네트워크뿐 아니라 클라우드, 무선 네트워크, 원격접근, 외부 공개 서버 등 다양한 연결 환경에 의존합니다. 이러한 환경에서 접속 경로와 네트워크 경계가 명확하게 식별되지 않거나 영역 간 접근정책이 과도하게 허용되면, 비인가자가 내부 네트워크에 접근하거나 하나의 침해 지점을 이용해 다른 시스템으로 이동하여 중요정보에 접근할 수 있습니다.

관리용 원격접속, 무선 접속장치(AP), 클라우드 관리 화면, 공개 서버와 같은 접점은 업무 편의성을 높이는 동시에 조직의 네트워크로 진입할 수 있는 새로운 경로가 될 수 있습니다. 이 Control은 네트워크와 정보시스템의 논리적 경계를 명확히 하고, 업무 목적과 자산 중요도에 맞는 접근통제와 안전한 접속수단을 적용하여 비인가 접근과 사용을 방지하도록 합니다. 접근 경로와 보안정책은 시스템·서비스 및 운영환경의 변화에 따라 지속적으로 검토하고, 불필요하거나 과도한 접근과 우회 경로를 제거해야 합니다.

적용 조건

적용 시점

조직이 네트워크·정보시스템을 구축·운영하거나 통신 구간·접속 경로·접근정책을 변경하는 경우 적용합니다. 클라우드·무선·원격업무·외부 공개 서버 도입과 운영에도 적용하며, 개인정보처리시스템이 포함된 경우 관련 접근통제 의무를 함께 적용합니다.

적용 대상

관리체계 범위 내 사내·클라우드·무선·원격 네트워크, 서버·보안시스템, 관리용 접속과 시스템 간 통신 경로 및 관련 담당부서에 적용합니다. 아래 개인정보 보호 법령은 개인정보처리시스템에 적용되는 근거이며, 그 밖의 환경은 조직의 보안정책과 해당 업무의 법적 요구사항에 따라 관리합니다.

관련 법령

  • 「개인정보 보호법」 제29조 — 개인정보처리자의 불법 접근·정보 유출 등을 방지하기 위한 기술적·관리적·물리적 안전조치 의무.
  • 「개인정보의 안전성 확보조치 기준」 제6조 — 개인정보처리시스템의 접속 권한을 제한하고 접속 주소 등을 분석하여 개인정보 유출 시도를 탐지·대응할 의무.

Control Owner

인프라·네트워크 보안 책임자

Stakeholders

정보보호 담당부서, IT 운영부서, 클라우드·시스템 관리 책임자, 개발부서, 공급업체, 각 업무부서

Implementation Guide

용어 안내: DMZ는 외부 공개 서버를 내부 업무망과 분리해 배치하는 네트워크 구간입니다. VPN은 외부에서 내부 자원에 접속할 때 사용하는 암호화된 가상사설망이며, SSH·SFTP는 원격 관리·파일 전송을 보호하는 접속 방식입니다. 보안그룹은 클라우드 자원의 허용·차단 통신 규칙을 정하는 기능이고, 포트는 서비스가 통신에 사용하는 번호입니다.

1. 네트워크와 논리적 접근 경로 식별 및 최신 상태로 관리

관리체계 범위 내의 온프레미스 네트워크, 클라우드 가상 네트워크, 무선 네트워크, 원격접근 경로, 외부 공개 구간과 시스템 간 연결 관계를 식별합니다. 인터넷, 지사·데이터센터(IDC)·협력업체 연결, VPN, 무선 접속장치(AP), 클라우드 관리 화면 등 내부 시스템으로 접근할 수 있는 경로가 누락되지 않도록 네트워크 구성도와 자산·IP 현황을 함께 관리합니다.

신규 시스템이나 서비스 도입, 네트워크 구성 변경, 클라우드 전환, 원격업무 확대 등으로 접속 경로가 변경된 경우 관련 문서를 현행화하고, 기존에 승인되지 않은 우회 경로나 불필요한 연결이 생기지 않았는지 확인합니다.

2. 업무 목적과 자산 중요도에 따른 네트워크 영역 분리 및 영역 간 접근 통제

서비스와 정보자산의 중요도, 사용자 그룹, 업무 목적 및 관련 요구사항을 고려하여 DMZ, 서버 영역, 데이터베이스 영역, 운영자 영역, 개발·시험 영역, 외부자 영역 등을 필요한 수준으로 물리적 또는 논리적으로 분리합니다.

분리된 영역 간 통신은 방화벽, 네트워크 장비의 접근 허용·차단 목록(ACL), 클라우드 보안그룹 등 조직이 사용하는 접근통제 수단을 통해 업무상 필요한 출발지·목적지·서비스만 허용합니다. 외부에 공개되는 서버는 내부 네트워크와 분리하고, 공개 서버가 침해되더라도 내부 시스템으로 직접 이동할 수 없도록 연결 경로를 제한합니다.

네트워크 접근정책은 필요하지 않은 통신을 기본적으로 차단하고 업무상 필요한 연결만 허용하는 방향으로 관리하며, 과도하게 허용된 규칙과 장기 미사용 규칙, 승인되지 않은 예외가 남아 있지 않도록 검토합니다.

3. 정보시스템과 관리 경로에 안전한 접근수단 적용

서버, 네트워크 장비, 보안시스템 등 정보시스템별로 접근이 허용되는 사용자, 접속 위치, 접근수단과 관리 경로를 정의합니다. 관리자는 개별 계정을 사용하고, 접속 위치 또는 관리용 단말을 필요한 범위로 제한하며, SSH·SFTP·VPN 등 보호된 접근수단을 사용합니다.

업무 목적과 무관하거나 침해에 악용될 수 있는 서비스·포트·프로토콜은 제거하거나 차단하고, 시스템 특성과 위험을 고려하여 일정 시간 활동이 없는 관리 세션이 계속 유지되지 않도록 통제합니다. 서버 간 접속이나 관리시스템 우회 등 정상 접근통제 체계를 거치지 않는 경로도 함께 확인하여 차단합니다.

4. 무선 및 원격접근 경로 보호

업무용 무선 네트워크는 인가된 사용자와 단말만 접속하도록 인증·암호화·접근통제를 적용하고, 무선 AP의 목록과 관리자 접근을 관리합니다. 외부인용 무선 네트워크가 필요한 경우 내부 업무 네트워크와 분리하며, 비인가 AP나 임의의 무선 연결이 내부 네트워크 접근 경로로 사용되지 않는지 점검합니다.

재택근무, 장애대응, 원격협업 등으로 원격접근이 필요한 경우에는 승인된 사용자·단말·기간·접근범위를 정하고, VPN 등 암호화된 접속수단과 강화된 인증을 적용합니다. 원격접속 단말에는 조직이 정한 보안 요구사항을 적용하고, 원격접속 계정과 접속기록을 관리하여 불필요하거나 장기간 사용되지 않는 접근권한을 정리합니다.

5. 인터넷 접속, 클라우드 및 공개 서버 노출 Control

데이터베이스 서버 등 외부 인터넷 연결이 필요하지 않은 주요 정보시스템은 불필요한 인터넷 접속을 제한합니다. 업무상 예외가 필요한 경우에는 사유와 위험을 검토하고 승인된 범위 안에서만 허용하며, 우회 경로를 통해 Control이 무력화되지 않는지 확인합니다.

클라우드 환경에서는 서비스 유형과 책임분담 구조를 고려하여 가상 네트워크, 관리자 계정, 관리 콘솔, 보안그룹, 공개 설정, 원격접속 경로 등에 대한 보안기준을 정합니다. 관리자 권한은 업무 역할에 맞게 최소화하고 강화된 인증과 접속기록을 적용하며, 승인받지 않은 보안설정 변경이나 외부 공개가 발생하지 않는지 모니터링합니다.

외부에 공개되는 서버는 DMZ 등 분리된 영역에서 운영하고, 운영체제와 서비스의 불필요한 기능·포트를 제거하며 보안패치와 취약점 점검을 수행합니다. 공개 서버가 내부 데이터베이스나 애플리케이션 서버와 통신해야 하는 경우 필요한 통신만 허용하도록 엄격하게 접근을 제한합니다.

6. 보안시스템 정책과 예외의 통제된 절차 운영

방화벽, 침입 탐지·차단 시스템(IDS/IPS), VPN, 네트워크 접근제어 등 조직이 사용하는 보안시스템의 관리자와 운영절차를 정하고, 승인된 절차에 따라 정책을 등록·변경·삭제하도록 합니다.

예외 정책은 업무상 필요성과 보안 영향을 검토한 후 필요한 최소 범위로 적용하며, 사용 목적이나 기간이 끝난 예외가 계속 유지되지 않도록 관리합니다. 정책 변경 내역과 승인 기록을 남기고, 실제 운영 중인 정책이 승인된 내용과 일치하는지 확인합니다.

7. 접근통제 정책과 운영기록 검토 및 미흡 사항 개선

네트워크 접근기록, 원격·무선 접속기록, 보안시스템 이벤트와 정책 변경 이력을 활용하여 비인가 접근 시도, 우회 경로, 과도한 허용 규칙, 장기 미사용 정책, 설정 오류 등을 확인합니다.

시스템·서비스·조직 구조 또는 위협환경이 변경되면 관련 네트워크 구성과 접근통제 정책의 적절성을 다시 검토합니다. 발견된 미흡 사항은 원인과 영향을 확인하고 개선조치의 담당자와 처리 상태를 관리하여, 동일한 접근통제 문제가 반복되지 않도록 합니다.

Evidence

  • 네트워크 구성도 및 접속 경로 현황: 온프레미스·클라우드·무선·원격 환경의 네트워크 영역, 시스템 간 연결, 외부 접점과 관리 경로가 식별되어 있으며 실제 구성과 일치하는지 확인할 수 있는 자료입니다.
  • IP 및 정보자산 관리자료: 네트워크 대역별 IP주소 부여 기준, IP 할당 현황, 서버·네트워크 장비·보안시스템 등 접근통제 대상 자산의 식별 및 최신성을 확인할 수 있는 자료입니다.
  • 방화벽·ACL·보안그룹 정책 및 변경 기록: 영역 간 허용 통신의 출발지·목적지·서비스가 업무상 필요 범위로 제한되어 있는지, 정책의 신청·승인·변경·삭제와 예외 관리가 이루어지는지 확인할 수 있는 자료입니다.
  • 정보시스템 관리접근 설정 및 계정 현황: 서버·네트워크 장비·보안시스템의 관리자 계정, 접속 가능 위치, 안전한 접속수단, 세션 Control과 불필요 서비스·포트 차단 상태를 확인할 수 있는 자료입니다.
