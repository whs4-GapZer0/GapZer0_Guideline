Asset Management - Enhancement Controls

Asset Management - Enhancement Controls

AST-E-01

Control Name

승인된 네트워크 구성도·데이터 흐름도 유지

Security Domain

Asset Management

Control Class

Enhancement

Control Objective

승인된 네트워크 통신경로와 내·외부 데이터 흐름을 최신 상태로 표현하여, 허용된 연결과 정보 이동을 이해하고 비인가 연결·변경을 식별할 수 있도록 합니다.

Control Statement

네트워크 구성과 데이터 흐름이 실제 운영과 다르면 접근통제, 변경 영향분석, 사고조사와 데이터 보호의 기준선이 불명확해집니다. 조직은 자산·서비스·인터페이스·통신 주체·프로토콜·포트·데이터 유형과 경계 통과 지점을 연결한 구성도·흐름도를 승인하고, 변경과 실제 관측 결과를 반영해 유지해야 합니다.

적용 조건

적용 시점

네트워크·클라우드·외부 연결을 신설하거나 통신정책·인터페이스·데이터 흐름을 변경할 때 적용합니다. 정기적인 실제 구성 점검 및 서비스 종료 시 구성도·흐름도를 대조합니다.

적용 대상

관리체계 범위의 내부망·외부망·클라우드·원격접속·공급자 연결과, 시스템·서비스 간 및 조직 경계를 통과하는 데이터 흐름에 적용합니다. 개인정보 관련 법적 의무는 해당 법령의 적용 요건에 따라 개인정보 처리업무와 관련 시스템·인력에 적용합니다.

관련 법령

  • 「개인정보 보호법」 제29조 — 개인정보의 분실·도난·유출·위조·변조·훼손을 방지하기 위한 기술적·관리적·물리적 안전조치 의무.
  • 「개인정보의 안전성 확보조치 기준」 제6조 — 개인정보처리시스템의 불법 접근을 제한하고 개인정보 유출 시도를 탐지·대응하는 등 접근통제 의무.

Control Owner

네트워크 아키텍처·운영 책임자

Stakeholders

시스템·서비스 소유자, 정보보호 담당자, 개인정보보호 담당자, 개발·클라우드 운영 담당자, 데이터 소유자, 공급자 담당자

매핑된 ISMS-P 항목

  • 1.2.2 현황 및 흐름분석
  • 2.6.1 네트워크 접근

매핑된 CSF 항목

  • ID.AM-03 — Representations of the organization’s authorized network communication and internal and external network data flows are maintained.

Implementation Guide

1. 구성도·흐름도의 범위와 표기 기준을 정하기

관리체계 경계, 네트워크 구역, 자산·서비스, 인터페이스, 출발지·목적지, 프로토콜·포트, 데이터 유형·보안등급, 외부 연결과 승인자를 기록할 기준을 정의합니다.

2. 승인된 통신·데이터 흐름을 문서화하기

네트워크 구성도, 연결·방화벽 정책, 시스템 간 연동 인터페이스(API)·인터페이스, 개인정보·중요정보 흐름을 대조하여 허용된 경로와 경계 통과 지점을 표현하고 소유자와 보안 검토자가 승인합니다.

3. 변경관리와 연결하기

신규 연결, 경로·정책·인터페이스·데이터 유형 변경 전에 영향과 권한을 검토하고, 승인된 변경이 구성도·흐름도와 관련 Control에 반영되도록 합니다.

4. 실제 상태와 정합성을 확인하기

구성정보와 네트워크 관측 결과를 승인된 구성도·흐름도과 대조하여 미등록 연결, 과도한 허용, 폐기되지 않은 경로와 문서 불일치를 조치합니다.

Evidence

  • 승인된 네트워크 구성도·데이터 흐름도: 허용된 연결, 경계와 정보 이동을 확인할 수 있는 자료입니다.
  • 방화벽·라우팅·클라우드·API 구성 및 승인 기록: 표현된 경로가 실제 허용 정책과 일치하는지 확인할 수 있는 자료입니다.
  • 변경 요청·영향분석·검증 기록: 연결과 흐름 변경이 승인되고 문서에 반영되었는지 확인할 수 있는 자료입니다.
  • 구성·흐름 정합성 점검 결과: 미등록·과도·잔존 경로의 발견과 조치 내역을 확인할 수 있는 자료입니다.

ISMS-P Limitation

ISMS-P 1.2.2는 정보서비스 및 개인정보 처리의 업무 절차와 흐름을 문서화하고 최신성을 유지하도록 하며, 2.6.1은 네트워크 경로의 식별, 영역 분리 및 접근통제를 요구합니다. 다만 조직이 승인한 네트워크 통신과 내부·외부 네트워크 데이터 흐름을 자산·서비스·인터페이스 단위의 통합된 구성도·흐름도으로 유지하도록 명시하는 요구는 제한적이다.

CSF Coverage

이 Control은 네트워크 구역, 자산·서비스, 인터페이스, 출발지·목적지, 프로토콜·포트 및 데이터 유형을 연결하여 승인된 통신과 내부·외부 네트워크 데이터 흐름을 문서화하도록 합니다. 변경관리와 실제 구성 대조로 구성도·흐름도의 최신성과 정확성을 유지하여 CSF ID.AM-03의 요구사항을 보완합니다.

AST-E-02

Control Name

통합 자산·데이터 수명주기

Security Domain

Asset Management

Control Class

Enhancement

Control Objective

시스템·하드웨어·소프트웨어·서비스·데이터의 도입부터 변경·유지보수·재사용·종료·폐기까지를 하나의 수명주기 체계로 연결하여 단계별 책임과 Control 공백을 방지합니다.

Control Statement

자산 유형별 목록과 일부 폐기 절차만으로는 서로 의존하는 시스템·서비스·데이터의 상태와 책임을 전 수명주기에 걸쳐 일관되게 관리하기 어렵습니다. 조직은 모든 자산 유형에 공통 수명주기 상태와 전환 기준을 적용하고, 승인·소유자·보호조치·검증 기록을 연결하여 누락과 잔존 위험을 통제해야 합니다.

적용 조건

적용 시점

자산·데이터의 도입·생성부터 운영·변경·이전·재사용·종료·폐기까지 각 단계 전환 시 적용합니다. 조직·공급자·연계 시스템 변경 시 전체 수명주기와 책임 공백을 재검토합니다.

적용 대상

관리체계 범위의 시스템, 하드웨어, 소프트웨어, 서비스와 데이터에 적용합니다. 개인정보뿐 아니라 조직이 보호 대상으로 지정한 비개인정보 데이터도 포함하며, 자산 유형별 세부 절차는 공통 수명주기 체계와 연결합니다. 개인정보 관련 법적 의무는 해당 법령의 적용 요건에 따라 개인정보 처리업무와 관련 시스템·인력에 적용합니다.

관련 법령

  • 「개인정보 보호법」 제29조 — 개인정보의 분실·도난·유출·위조·변조·훼손을 방지하기 위한 기술적·관리적·물리적 안전조치 의무.
  • 「개인정보 보호법」 제21조 — 불필요해진 개인정보의 지체 없는 파기와 복구·재생 방지 및 법정 보존 시 분리 저장·관리 의무.
  • 「개인정보 보호법」 제26조 — 개인정보 처리위탁 시 보호조치 등의 문서화, 위탁사항 공개 및 수탁자 교육·감독 의무.

Control Owner

정보자산 거버넌스 책임자 / 정보보호 최고책임자

Stakeholders

자산·데이터·서비스 소유자, IT 운영 담당자, 개발 담당자, 구매·계약 담당자, 개인정보보호 담당자, 법무 담당자, 재무 담당자, 공급자 관리 담당자

매핑된 ISMS-P 항목

  • 2.1.3 정보자산 관리
  • 2.9.7 정보자산의 재사용 및 폐기
  • 3.4.1 개인정보 파기

매핑된 CSF 항목

  • ID.AM-08 — Systems, hardware, software, services, and data are managed throughout their life cycles.

Implementation Guide

1. 공통 수명주기 모델을 정의하기

도입·생성, 승인, 운영·이용, 변경, 유지보수, 이전·재사용, 종료·폐기 상태와 전환 조건을 정의하고 자산 유형별 절차·책임·필수 기록을 연결합니다.

2. 자산 간 관계와 책임을 연결하기

시스템, 하드웨어, 소프트웨어, 서비스와 데이터 목록에 소유자·관리자, 의존관계, 처리 데이터, 공급자와 수명주기 상태를 연결하여 단계별 책임 공백을 확인합니다.

3. 단계 전환을 통제하기

각 전환 시 위험·보안·법적 요구를 검토하고 승인, 시험·검증, 데이터 이전·삭제, 접근권한·계약·라이선스 정리와 문서 갱신을 완료조건으로 관리합니다.

4. 전체 수명주기의 누락과 잔존 위험을 검증하기

실제 운영·계약·배포·데이터 처리·폐기 기록을 통합 목록과 대조하여 상태 불일치, 소유자 공백, 종료 후 접근·데이터·서비스 잔존을 조치합니다.

Evidence

  • 통합 자산 수명주기 정책·절차: 공통 상태, 전환 조건, 자산 유형별 책임과 완료기준을 확인할 수 있는 자료입니다.
  • 통합 자산·데이터 목록 또는 연계도: 소유자, 의존관계, 공급자, 데이터와 수명주기 상태의 연결을 확인할 수 있는 자료입니다.
  • 단계 전환 승인·검증 기록: 도입·변경·이전·재사용·종료 시 위험검토와 완료조건 이행을 확인할 수 있는 자료입니다.
  • 종료·폐기 정합성 점검 결과: 접근권한·계약·라이선스·데이터·자산 상태의 잔존과 조치 결과를 확인할 수 있는 자료입니다.

ISMS-P Limitation

ISMS-P 2.1.3은 정보자산의 중요도별 취급과 책임자 지정을, 2.9.7과 3.4.1은 정보자산 재사용·폐기 및 개인정보 파기를 다룬다. 비개인정보 데이터까지 포함하여 시스템·하드웨어·소프트웨어·서비스·데이터의 도입·운영·변경·유지보수·재사용·폐기 단계와 책임을 하나의 체계로 연결하는 요구는 명시적으로 통합되어 있지 않다.

CSF Coverage

이 Control은 모든 자산 유형에 공통 수명주기 상태·전환 기준·소유자·승인·검증 기록을 적용하고, 자산 간 의존관계와 종료 후 잔존 위험을 대조하도록 하여 Gap을 보완합니다. 이는 시스템·하드웨어·소프트웨어·서비스·데이터를 수명주기 전반에서 관리하도록 하는 CSF ID.AM-08의 결과와 연결됩니다.
