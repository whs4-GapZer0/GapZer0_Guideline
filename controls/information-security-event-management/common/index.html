Information Security Event Management - Common Controls

IEM-C-01

Control Name

다중 출처 정보의 상관 분석을 통한 탐지 정확도와 사건 가시성 향상

Security Domain

Information Security Event Management

Control Class

Common

Control Objective

여러 출처의 보안정보를 연결하여 실제 조사할 사건을 정확히 식별하고 관련 활동의 흐름을 파악합니다. 시스템·계정·네트워크의 개별 기록을 같은 시간과 자산 기준으로 연결하여 공격의 시작점, 이동 경로와 관련 활동을 함께 확인할 수 있도록 합니다. 단일 장비의 경보만으로는 놓치는 사건과 반복되는 오탐을 줄이고, 조사 담당자가 우선 확인할 근거를 확보합니다.

Control Statement

하나의 장비에서 발생한 경보만으로는 여러 시스템에 걸친 공격의 흐름을 파악하기 어렵습니다. 조직은 서로 다른 출처의 보안정보를 연결하여 개별 이벤트의 관계를 확인하고, 실제 조사할 사건을 더 정확하게 식별해야 합니다.

예를 들어 계정 로그인, 원격 명령 실행과 외부 전송이 서로 다른 장비에 기록되면 각 기록만으로는 침해 여부를 판단하기 어렵습니다. 이 Control은 출처 간 식별자와 시각의 차이를 해소하고 수집 품질을 유지하여, 연관 분석 결과를 실제 조사와 대응에 활용할 수 있는 상태를 유지하도록 합니다.

적용 조건

적용 시점

로그 수집 체계와 탐지 규칙을 설계할 때, 새로운 시스템을 연계할 때, 오탐이나 탐지 누락이 확인되었을 때 적용합니다.

적용 대상

조직의 관리 범위에 포함된 시스템·애플리케이션·네트워크·보안장비의 로그, 자산·계정 정보 및 외부 위협정보에 적용합니다. 개인정보 관련 법령·고시의 의무는 해당 개인정보 처리와 법정 적용 요건에 따라 적용합니다.

관련 법령

  • 「개인정보 보호법」 제29조 — 개인정보의 유출등을 방지하기 위한 기술적·관리적·물리적 안전조치 의무.
  • 「개인정보의 안전성 확보조치 기준」 제8조 — 개인정보처리시스템 접속기록의 보관·점검과 안전한 보관을 위한 조치 의무.

Control Owner

보안관제 책임자

Stakeholders

정보보호 최고책임자(CISO), IT 운영·개발부서, 자산·계정 관리 담당자, 개인정보보호 담당자, 보안관제 서비스 제공자

  • 2.9.6 시간 동기화

매핑된 CSF 항목

Implementation Guide

1. 공격 시나리오에 필요한 로그와 정보 출처 식별

주요 공격 시나리오별로 확인해야 할 로그와 자산·계정 정보를 목록화합니다. 외부 위협정보는 출처, 갱신 주기와 신뢰도를 확인하고 수집이 불가능한 구간은 대체 확인 방법을 정합니다.

계정 탈취 시나리오라면 인증 기록, 단말기 실행 기록과 외부 접속 기록을 함께 선정합니다. 각 출처의 보유 부서, 제공 주기, 필수 필드와 조회 권한을 기록하여 분석 담당자가 필요한 자료를 반복 요청하지 않도록 합니다.

2. 공통 시각과 자산·사용자 식별자를 기준으로 기록 정규화

서로 다른 로그의 시간대, 자산명, 계정명과 IP 주소를 비교 가능한 형식으로 맞춥니다. 시스템 시각을 표준시각과 동기화하고, 시각 오차나 주소 변경으로 서로 다른 활동이 잘못 연결되지 않는지 확인합니다.

표준시각과 원본 시각을 구분하고, 계정 이름이 같아도 조직·시스템이 다르면 별개의 사용자로 처리합니다. 주소를 공유하는 장비나 수시로 주소가 바뀌는 클라우드 자원은 자산 식별자와 사용 시점 정보를 추가하여 잘못된 연결을 줄입니다.

3. 연관 활동을 식별할 수 있는 상관 분석 규칙 설계와 적용

상관 분석은 여러 기록을 연결하여 하나의 사건 흐름을 찾는 활동입니다. 예를 들어 반복된 로그인 실패 뒤의 성공과 대량 다운로드를 연결하고, 규칙의 조건·관찰 시간·예외와 담당자를 기록합니다.

규칙에는 필요한 출처, 필드, 일치 조건과 경보에 표시할 근거를 함께 정의합니다. 실제 운영 반영 전 정상 업무와 의심 활동의 표본을 사용하여 조건이 지나치게 넓거나 중요한 단계를 빠뜨리지 않았는지 검증합니다.

4. 상관 분석 경보의 사실 확인과 후속 조사 연결

규칙에 일치한 기록의 원본을 확인하고 정상 업무인지 관련 부서와 검증합니다. 의심 사건은 근거 로그와 관련 자산을 함께 전달하여 초기 분류·분석으로 연결하고, 개인정보나 인증정보가 불필요하게 전달되지 않도록 합니다.

경보를 하나의 사건으로 묶더라도 각 원본 기록의 위치와 수집 시각을 추적할 수 있게 합니다. 정상으로 판단한 경우에는 작업 승인이나 업무 담당자 확인 등 근거를 남겨 이후 같은 경보를 일관되게 처리합니다.

5. 로그 수집 품질과 규칙의 탐지 효과 점검 및 개선

로그 누락, 수집 지연과 시각 오차를 점검하고 대표 공격 사례가 탐지되는지 시험합니다. 오탐 원인과 놓친 사건을 검토하여 규칙을 수정하고 승인·적용·재시험 결과를 남깁니다.

탐지 규칙이 의존하는 출처가 끊기면 단순한 경보 감소와 구분하여 수집 장애로 알립니다. 개선 전후의 오탐·미탐 사례와 처리 시간을 비교하고, 수정한 규칙의 적용일·버전과 재검토 담당자를 관리합니다.

Evidence

  • 로그 출처·연계 목록: 시스템별 수집 항목, 식별자, 수집 담당자와 미수집 구간을 확인할 수 있는 자료입니다.
  • 시각 동기화·수집 상태 기록: 로그를 시간순으로 연결할 수 있고 수집 장애를 관리하고 있음을 보여줍니다.
  • 상관 분석 규칙과 시험 결과: 규칙의 판단 조건과 실제 탐지 가능성을 확인할 수 있는 설정·검증 자료입니다.
  • 경보 조사·개선 이력: 오탐 판단 근거, 후속 조사 및 규칙 개선 결과를 추적할 수 있는 기록입니다.

IEM-C-02

Control Name

이벤트의 영향도와 범위 평가를 통한 대응 수준 및 우선순위 결정 지원

Security Domain

Information Security Event Management

Control Class

Common

Control Objective

이벤트의 예상 피해와 확산 가능 범위를 파악하여 대응 수준과 우선순위 결정에 활용합니다. 이벤트와 연결된 서비스의 중요도, 정보의 민감도와 의존관계를 함께 확인하여 제한된 대응 자원을 중요한 위험에 우선 배분할 수 있도록 합니다. 초기 정보가 불완전한 경우에도 확인 사실과 예상 범위를 구분하여, 피해가 작다는 근거 없는 판단으로 조치가 지연되는 것을 방지합니다.

Control Statement

같은 경보라도 연결된 업무와 정보의 중요도에 따라 예상 피해가 다릅니다. 조직은 사고 여부가 확정되기 전에도 이벤트가 미칠 영향과 확산 가능성을 파악하여 필요한 대응 수준과 우선순위를 판단해야 합니다.

탐지 시점에는 실제 침해 여부나 전체 피해 범위가 확정되지 않는 경우가 많습니다. 이 Control은 초기 단계에서 가능한 피해와 전파 경로를 근거에 따라 추정하고, 새로운 정보가 들어오면 대응 수준을 조정할 수 있도록 하여 대응 기회를 놓치는 위험을 줄입니다.

적용 조건

적용 시점

이상 이벤트를 발견하거나 새로운 분석 정보가 들어왔을 때, 영향받는 자산이나 서비스가 추가로 확인되었을 때 적용합니다.

적용 대상

초기 조사 중인 보안 이벤트와 연결된 자산·계정·정보·서비스 및 외부 의존관계에 적용합니다. 개인정보 관련 법령·고시의 의무는 해당 개인정보 처리와 법정 적용 요건에 따라 적용합니다.

관련 법령

  • 「개인정보 보호법」 제29조 — 개인정보의 유출등을 방지하기 위한 기술적·관리적·물리적 안전조치 의무.

Control Owner

보안관제 및 사고대응 책임자

Stakeholders

서비스·업무 책임자, IT 운영·개발부서, 자산관리 담당자, 개인정보보호 담당자, 법무·컴플라이언스 담당자

매핑된 ISMS-P 항목

  • 2.11.5 사고 대응 및 복구
  • 2.11.1 사고 예방 및 대응체계 구축

매핑된 CSF 항목

  • DE.AE-04 — The estimated impact and scope of adverse events are understood

Implementation Guide

1. 이벤트 발생 자산과 연결된 업무·정보의 중요도 확인

발생 시각, 탐지 근거, 관련 계정과 자산을 확인합니다. 자산 목록과 업무 담당자를 통해 처리 정보, 서비스 중요도와 연결된 시스템을 파악합니다.

같은 서버 경보라도 대외 서비스, 인증 기반시설 또는 개인정보 저장소인지에 따라 영향을 다르게 평가합니다. 자산 목록이 최신이 아니면 운영 담당자의 확인으로 보완하고 자료의 확인 시점과 출처를 표시합니다.

2. 기밀성·무결성·가용성 관점에서 예상 피해 구분

정보 유출, 데이터 변경·삭제, 서비스 중단이 발생할 가능성을 구분합니다. 영향받을 수 있는 이용자·업무·거래처와 개인정보 포함 여부를 확인하고 피해 추정의 근거를 기록합니다.

데이터가 외부로 전달될 가능성, 거래 내용이 바뀔 가능성과 서비스가 멈출 가능성을 따로 검토합니다. 금액이나 이용자 수를 즉시 산정할 수 없으면 영향을 받는 업무와 최대 예상 범위를 설명하고 추가 확인할 정보를 명시합니다.

3. 연결 관계와 공격 경로를 고려한 확산 가능 범위 추정

연결된 네트워크, 공통 계정과 외부 서비스로 이벤트가 확대될 수 있는 경로를 조사합니다. 실제 확인된 범위와 추가 확인이 필요한 범위를 구분하고, 자료 부족으로 영향이 작게 평가되지 않도록 합니다.

동일 계정을 쓰는 서버, 공통 인증 시스템과 공유 저장소처럼 피해가 함께 확대될 수 있는 지점을 확인합니다. 직접 조사할 수 없는 외부 서비스는 제공자에게 확인을 요청하고 응답 전까지의 불확실성을 평가에 남깁니다.

4. 예상 영향에 따른 긴급 조치와 대응 자원 결정

예상 피해와 진행 속도를 기준으로 조사 순서, 긴급 보호조치와 필요한 인력을 제안합니다. 업무 책임자와 사고대응 책임자가 판단 근거를 공유하고, 중대한 가능성이 있으면 확정 전이라도 상위 책임자에게 보고합니다.

단기간에 확대될 수 있는 대량 반출과 핵심 서비스 장애는 즉시 확인할 대상으로 분류합니다. 긴급 차단의 업무 영향도 함께 제시하여 책임자가 조사 지속, 제한적 차단과 전체 격리 중 필요한 조치를 판단하게 합니다.

5. 추가 분석 결과에 따른 영향 추정과 대응 수준 갱신

추가 로그나 담당자 확인 결과가 들어오면 영향과 범위를 갱신합니다. 이전 판단과 달라진 이유를 기록하고, 사고로 확인된 이후에는 사고 규모 평가에 이어서 활용합니다.

평가서에 갱신 시각, 새로 확보한 근거와 변경된 판단을 남깁니다. 이미 전달한 평가가 달라지면 담당자와 지휘 책임자에게 변경 사항을 알려 이전의 낮은 우선순위가 그대로 유지되지 않도록 합니다.

Evidence

  • 초기 영향 평가서: 예상 피해, 판단 근거 및 확인되지 않은 사항을 구분한 자료입니다.
  • 자산·서비스 연관도: 이벤트가 연결된 업무와 확산 가능 경로를 확인할 수 있는 자료입니다.
  • 대응 수준 결정 기록: 위험에 따라 조사 순서와 투입 자원을 정한 근거입니다.
  • 재평가 이력: 추가 정보가 영향도와 대응 판단에 반영되었음을 보여줍니다.

IEM-C-03

Control Name

이벤트 정보의 적시 전달 및 대응 연계

Security Domain

Information Security Event Management

Control Class

Common

Control Objective

이벤트 정보를 대응 권한이 있는 담당자와 보안도구에 적시에 전달하여 후속 대응을 시작할 수 있게 합니다. 신고·경보가 접수된 시점부터 담당자가 인수하는 시점까지 전달 상태를 추적할 수 있도록 합니다. 근무시간 밖이나 담당자 부재에도 대응이 이어지게 하여, 탐지 후에도 아무도 처리하지 않는 상황을 줄입니다.

Control Statement

보안 이벤트가 탐지되어도 담당자에게 도달하지 않으면 대응이 지연됩니다. 조직은 이벤트 정보를 대응 권한이 있는 인력과 도구에 적시에 전달하고, 수신 실패나 담당자 부재에도 후속 대응이 이어지는 연락 체계를 갖추어야 합니다.

이메일 발송 성공이나 경보 화면 표시는 담당자가 사건을 확인했다는 의미가 아닙니다. 이 Control은 접수 창구, 수신 권한, 인수 확인과 미응답 시 보고 경로를 연결하여 사고 초기 분류와 조사 업무로 정보가 빠짐없이 넘어가도록 합니다.

적용 조건

적용 시점

적용 대상

임직원·외부 이용자의 신고 창구, 보안관제 경보, 대응 업무 관리시스템과 비상연락망에 적용합니다. 개인정보 관련 법령·고시의 의무는 해당 개인정보 처리와 법정 적용 요건에 따라 적용합니다.

Implementation Guide

1. 조직의 운영시간과 신고자 특성을 반영한 접수 창구 마련

전화, 이메일, 포털과 자동 경보 등 조직 환경에 맞는 복수의 창구를 마련합니다. 24시간 접수 가능한 방법과 근무시간 밖의 확인 담당자를 정하고 사용 방법을 안내합니다.

내부 직원과 외부 고객이 이용할 수 있는 연락 방법을 구분하여 안내합니다. 접수 시스템 장애 시 사용할 대체 연락처를 별도로 제공하고, 신고자가 민감한 자료를 공개 게시판에 올리지 않도록 안전한 제출 방법을 안내합니다.

2. 이벤트 유형별 수신자·대체 담당자·도구 연계 경로 지정

이벤트 유형과 중요도별 수신자, 대체 담당자와 연계 도구를 지정합니다. 외부 업체나 자동화 도구에는 업무에 필요한 정보만 전달하고 접근권한과 전송 구간을 보호합니다.

계정 이상, 개인정보 유출 의심과 서비스 장애처럼 처리 부서가 다른 유형의 전달 규칙을 정합니다. 조직 변경이나 위탁계약 변경 시 연락망과 도구의 수신 계정이 함께 수정되었는지 확인합니다.

3. 후속 판단에 필요한 이벤트 정보의 표준 양식 적용

발생·접수 시각, 관련 자산, 현상, 근거 자료와 이미 수행한 조치를 같은 양식으로 전달합니다. 원문에 개인정보나 비밀번호가 포함되어 있으면 필요한 범위로 제한하고 원본은 별도로 보호합니다.

신고자가 모든 항목을 알지 못하더라도 우선 접수하고 담당자가 누락 정보를 보완합니다. 자동 경보에는 탐지 규칙과 원본 조회 위치를 포함하여 조사 담당자가 같은 내용을 다시 찾는 시간을 줄입니다.

4. 수신·인수 상태 확인과 미응답 시 대체 경로 가동

중요도별 확인 시간을 정하고 수신 여부와 담당자의 인수를 기록합니다. 미응답이나 전송 실패가 발생하면 대체 채널과 상위 책임자에게 전달하며, 접수 건은 초기 분류·검증 절차로 연결합니다.

발송, 수신 확인과 실제 처리 담당자 배정을 구분하여 기록합니다. 알림이 여러 명에게 전달된 경우에도 최종 인수자를 명시하여 서로 다른 사람이 처리할 것이라고 생각하는 상황을 방지합니다.

5. 야간·휴일과 전송 장애를 포함한 연락 체계 시험

주간·야간 및 담당자 부재 상황을 가정하여 신고부터 인수까지 시험합니다. 지연된 구간과 잘못된 연락처를 수정하고, 법정 통지·신고가 필요한 사안은 별도의 통지 담당자에게 즉시 연결합니다.

시험 신고를 전달하고 실제로 누가 언제 인수했는지 확인합니다. 자동 전달은 성공했지만 담당자가 확인하지 못한 경우 알림 방식과 근무 편성을 함께 검토하고 개선 후 같은 조건에서 재시험합니다.

Evidence

  • 신고 창구·비상연락망: 접수 방법, 수신자와 대체 담당자가 정의되어 있음을 보여줍니다.
  • 이벤트 전달 양식·연계 설정: 필요한 정보가 권한 있는 대상에게 전달되도록 구성한 자료입니다.
  • 수신·인수·재전달 기록: 경보가 담당자에게 도달하고 미응답 시 후속 보고되었음을 입증합니다.
  • 연락망 시험·개선 결과: 근무시간 밖이나 전송 장애 상황에서도 전달 체계가 작동하는지 확인한 자료입니다.

Control Name

네트워크·네트워크 서비스의 이상 및 침해 징후에 대한 적시 탐지

Control Objective

유·무선 네트워크와 네트워크 서비스의 이상 및 침해 징후를 적시에 발견합니다. 인터넷·무선·원격접속과 내부 시스템 간 통신에서 정상 업무와 다른 연결을 식별하고 조사할 수 있도록 합니다. 비인가 접속과 정보 반출의 징후를 조기에 파악하여 침해의 확산과 탐지 공백을 줄입니다.

Control Statement

비인가 접속이나 비정상 통신은 침해사고의 초기 징후일 수 있습니다. 조직은 네트워크와 네트워크 서비스의 정상 사용 특성을 파악하고 이상 통신을 탐지하여, 조사와 필요한 접속 Control이 적시에 이루어지도록 해야 합니다.

네트워크 구성이 바뀌거나 암호화된 통신이 늘어나면 기존 관찰 지점만으로 실제 활동을 확인하기 어려워질 수 있습니다. 이 Control은 통신 경로와 정상 사용 기준을 최신 상태로 유지하고, 경보의 분석·조치까지 연결하여 감시 장비가 설치된 것만으로 점검이 끝나지 않도록 합니다.

적용 조건

적용 시점

네트워크를 구축·변경할 때, 외부 연결이나 원격접속 서비스를 개설할 때 및 상시 운영·정기 점검 시 적용합니다.

적용 대상

Implementation Guide

1. 네트워크 구성과 외부 연결별 관찰 지점 식별

외부 연결, 주요 서버 구간과 무선망을 네트워크 구성도에 표시합니다. 구간별 트래픽·접속 로그의 확보 방법과 암호화 등으로 직접 확인하기 어려운 부분의 대체 자료를 정합니다.

인터넷 경계뿐 아니라 중요 서버 간 연결, 지사 회선과 클라우드 내부 통신을 포함합니다. 장비 로그로 확인하기 어려운 구간은 흐름 기록이나 서비스 로그를 활용하고 확인 가능한 범위와 한계를 구성도에 표시합니다.

2. 서비스별 정상 통신 특성에 따른 이상 탐지 기준 수립

허용된 목적지·포트·사용 시간과 통신량을 기준으로 반복 접속 실패, 비정상 외부 전송과 알려진 공격 목적지 접속을 탐지합니다. 임계치는 서비스 특성을 반영하고 예외에는 사유와 만료일을 둡니다.

대량 전송, 주기적인 의심 목적지 연결과 허용되지 않은 포트 사용을 탐지 사례로 정합니다. 백업이나 배포 작업의 정상 통신을 고려하되 예외 범위를 목적지·시간·담당 업무로 제한하여 광범위한 탐지 제외를 피합니다.

3. 접속 정책과 보안장비 관리 권한의 통제된 운영

인터넷 접속정책에 따라 불필요한 연결을 제한하고, 법정 망 분리·접속 차단 요건의 적용 여부를 별도로 확인합니다. 보안장비의 관리 권한과 정책 변경을 승인·기록하고 변경 후 서비스 영향과 탐지 상태를 확인합니다.

정책 변경 요청에는 출발지·목적지·서비스·사용 기간과 업무 사유를 포함합니다. 긴급 변경도 적용 내용과 승인·사후 검토를 남기고 실제 장비 설정이 승인된 정책과 일치하는지 확인합니다.

4. 이상 통신 경보의 조사와 승인된 후속 조치 수행

경보의 출발지·목적지와 관련 계정을 확인하고 정상 업무인지 조사합니다. 침해가 의심되면 근거를 보존한 뒤 승인된 절차에 따라 접속 제한이나 사고대응으로 연결합니다.

탐지된 주소를 실제 자산·계정과 연결하고 같은 시간대의 접속·프로그램 실행 기록을 함께 확인합니다. 차단이 필요한 경우 업무 담당자에게 예상 영향을 알리고 조치 후 우회 경로로 통신이 계속되는지도 확인합니다.

5. 구성 변경과 수집 장애에 따른 탐지 사각지대 해소

신규 회선·장비와 수집 중단 구간을 정기적으로 확인합니다. 대표 통신 사례로 탐지·알림을 시험하고 미탐·오탐 및 장비 장애를 개선합니다.

새로운 회선이나 서비스가 운영을 시작하기 전에 로그와 알림이 들어오는지 확인합니다. 장애 복구 후에는 중단 기간의 누락 자료를 확보할 수 있는지 검토하고 확보할 수 없는 기간과 위험을 기록합니다.

Evidence

  • 네트워크 구성도와 수집 목록: 주요 연결과 관찰 구간의 누락 여부를 확인하는 자료입니다.
  • 탐지·접속 정책과 변경 승인: 이상 기준, 예외, 관리 권한 및 정책 변경의 적정성을 보여줍니다.
  • 이상 통신 조사·차단 기록: 경보의 확인 결과와 실제 후속 조치를 추적할 수 있는 자료입니다.
  • 탐지 시험·장애 개선 기록: 구성 변경 이후에도 탐지가 유지되는지 확인한 결과입니다.

Common

인력의 업무 활동과 기술 사용에서 권한 오·남용이나 정보 유출 등 보안 위협의 징후를 발견합니다. 업무 계정의 조회·다운로드·출력·원격접속을 업무 역할과 비교하여 정상 권한의 오·남용을 식별합니다. 점검 목적과 수집 범위를 제한하면서도 이상행위의 근거를 확인할 수 있게 하여 중요정보 반출과 불필요한 개인 활동 감시를 함께 줄입니다.

Control Statement

정상 계정과 업무 도구도 권한 오·남용이나 정보 유출에 이용될 수 있습니다. 조직은 업무 목적에 맞는 범위에서 인력의 시스템 사용을 점검하여 이상행위를 발견하고, 과도한 감시나 불필요한 개인정보 수집을 방지해야 합니다.

정상 계정으로 수행된 행위라도 담당 업무와 무관한 대량 조회나 비정상 시간의 반출은 추가 확인이 필요합니다. 이 Control은 행위의 업무 맥락을 확인하고 접근·단말기 보호와 연계하여, 자동 경보만으로 부정행위를 단정하거나 과도한 감시 자료를 축적하지 않도록 합니다.

적용 시점

적용 대상

Implementation Guide

1. 업무 목적에 맞는 사용행위 점검 범위와 개인정보 보호 기준 수립

비인가 조회, 대량 반출 등 확인하려는 위험과 필요한 기록을 정합니다. 인사·법무·개인정보보호 담당자와 수집 근거, 안내 사항, 열람 권한과 보관 범위를 확인하고 목적에 불필요한 개인 활동 정보는 수집하지 않습니다.

수집하려는 기록마다 위험 확인에 필요한 이유와 열람할 역할을 정합니다. 조사 자료를 인사 평가 등 다른 목적으로 사용하려면 별도의 근거와 절차를 검토하고, 일상 점검자가 상세 개인정보를 불필요하게 보지 않도록 제한합니다.

2. 담당 업무와 권한을 반영한 이상 조회·반출 판단 기준 마련

담당 업무와 권한을 기준으로 과다 조회, 비정상 시간 접속, 대량 출력·다운로드와 반복된 권한 거부를 구분합니다. 업무량이 일시적으로 증가하는 정상 사례와 승인된 예외도 함께 관리합니다.

정상 업무량과 담당 정보의 범위를 확인하여 과다 조회나 대량 반출 기준을 정합니다. 승인된 일괄 처리라도 요청자·기간·목적을 기록하고 승인 범위를 넘어선 사용은 별도 경보로 확인합니다.

3. 원격접속·업무용 단말기와 정보 취급 환경의 보호 연계

원격 관리자 접속과 개인정보 취급자의 원격접속은 적용 법령·승인 요건을 확인하여 제한합니다. 단말기 보안 설정, 화면 잠금과 출력물 관리 상태를 함께 점검하여 사용 기록에서 확인된 위험의 원인을 찾습니다.

이상 활동이 발생한 단말기의 보안 상태와 접속 위치가 승인된 환경인지 확인합니다. 출력물 방치나 화면 노출처럼 로그만으로 확인할 수 없는 위험은 업무환경 점검과 연결하고 확인 담당자를 정합니다.

4. 이상행위의 업무 사유 확인과 필요한 대응 조치 결정

경보와 관련된 조회 대상·시간·업무 사유를 권한 있는 담당자가 확인합니다. 경보만으로 부정행위를 단정하지 않고 사실 확인 결과에 따라 추가 조사, 권한 제한 또는 사고대응으로 연결합니다.

담당자에게 확인할 때는 조사 목적과 필요한 사실을 명확히 하고 자료 열람자를 제한합니다. 계정 탈취 가능성이 있으면 실제 사용자 행위와 구분하여 접근 제한·인증정보 교체 등 보호조치를 검토합니다.

5. 점검 결과와 반복 사례를 반영한 사용행위 Control 개선

점검 결과와 개인정보 다운로드 등 주요 행위의 확인 내용을 기록합니다. 반복되는 오탐과 우회 행위를 반영하여 기준을 개선하고 기록 열람권한·보관기간의 적정성도 재검토합니다.

같은 부서에서 반복되는 과다 권한이나 승인 없는 반출은 개별 경보 종결에 그치지 않고 권한·업무 절차를 개선합니다. 기준 변경 후 정상 업무가 과도하게 차단되지 않는지 확인하고 예외의 필요성을 다시 검토합니다.

Evidence

  • 사용행위 점검 정책: 점검 목적, 대상, 법적 근거 검토와 개인정보 보호 범위를 확인할 수 있는 자료입니다.
  • 업무별 이상 기준·예외 승인: 권한과 정상 업무를 고려하여 판단하도록 설정한 근거입니다.
  • 접속기록 점검·사유 확인 기록: 조회·다운로드 등 이상행위에 대한 사실 확인과 후속 조치의 증적입니다.
  • 권한·원격접속·단말기 개선 이력: 발견된 위험이 실제 운영 Control 개선으로 이어졌음을 보여줍니다.

Implementation Guide

1. 컴퓨팅 자산과 실행 환경별 탐지 대상·항목 정의

운영체제·애플리케이션·컨테이너별로 실행 기록, 계정 변경, 파일 변조와 데이터 접근 등 필요한 항목을 정합니다. 단기간 생성·삭제되는 자원도 수집 대상에 포함하고 담당자를 지정합니다.

서버·PC 목록과 클라우드 자원 목록을 비교하고 신규 자원이 수집 체계에 자동으로 포함되는지 확인합니다. 컨테이너처럼 종료가 빠른 자원은 종료 전 기록이 중앙 저장소에 전달되도록 수집 시점과 경로를 정합니다.

2. 운영 환경에 적합한 악성 행위 탐지 수단 적용

악성코드 방지 프로그램, 단말기 행위 탐지 도구와 클라우드 감사 로그 등을 조합합니다. 설치가 어려운 자산은 네트워크 기록이나 플랫폼 로그 등 대체 수단과 한계를 기록합니다.

보안 에이전트 설치가 서비스 성능에 미치는 영향을 확인하고 허용된 시험 환경에서 먼저 검증합니다. 대체 로그만 확보하는 자산은 탐지할 수 없는 행위를 명시하고 추가 관찰이나 접근 제한으로 보완합니다.

3. 탐지 정책·보안 프로그램과 예외 설정의 최신성 관리

탐지 정책, 보안 프로그램과 악성코드 정보의 최신 상태를 확인합니다. 탐지 제외 경로는 필요한 범위만 승인하고 유효기간을 두며, 업데이트 실패나 탐지 기능 중단을 알림으로 확인합니다.

각 장비가 마지막으로 정상 통신한 시각과 업데이트 결과를 확인합니다. 탐지 제외는 특정 프로그램·경로 등 필요한 범위로 제한하고 사용 목적이 끝나면 제거하여 공격자가 제외 범위를 악용하지 못하게 합니다.

4. 실행·변경·데이터 접근 경보의 분석과 대응 연계

의심 실행 파일, 부모·자식 프로세스 관계, 연결 목적지와 관련 데이터 접근을 확인합니다. 정상 작업과 구분한 뒤 사고대응 담당자에게 전달하고 업무 영향과 증거 보존을 고려하여 격리·조치를 수행합니다.

의심 프로그램의 실행 계정, 이전 실행 과정과 외부 연결을 함께 확인합니다. 자동 격리를 사용하는 경우 중요 서비스가 중단될 수 있는 조건을 사전에 승인하고 오탐 시 복구·해제 책임자를 정합니다.

5. 자산별 적용 누락과 탐지 기능의 정기 검증

자산 목록과 실제 탐지 수단의 적용 현황을 비교하여 누락을 확인합니다. 승인된 안전한 시험 사례로 탐지·알림을 확인하고 수집 지연, 우회 가능성과 반복 오탐을 개선합니다.

목록에 있으나 기록이 들어오지 않는 자산과 목록에 없는 신규 자원을 구분하여 확인합니다. 점검 결과에는 미적용 사유, 보완조치와 적용 기한을 남기고 종료된 자원의 불필요한 계정·수집 설정도 정리합니다.

Evidence

  • 자산별 탐지 적용 현황: 관리 대상 대비 탐지 수단의 적용·예외·누락을 확인하는 자료입니다.
  • 보안 프로그램·정책 관리 이력: 업데이트, 탐지 제외 승인과 기능 중단에 대한 관리 증적입니다.
  • 단말기·실행 환경 경보 조사: 실행·변경·접근 기록을 근거로 이상행위를 검증한 자료입니다.
  • 탐지 시험·누락 개선 기록: 환경별 탐지 수단이 작동하고 미적용 자산이 관리되는지 보여줍니다.

Control Statement

로그가 생성되지 않거나 필요할 때 조회할 수 없으면 이상행위 탐지와 사고 원인 확인이 어려워집니다. 조직은 업무와 법적 요구에 맞는 기록을 생성하고, 정확성과 무결성을 유지하면서 권한 있는 담당자가 분석에 활용할 수 있도록 보관해야 합니다.

기록이 존재하더라도 시간대가 다르거나 저장 위치와 조회 권한을 알 수 없으면 사고 대응에 활용하기 어렵습니다. 이 Control은 생성부터 보관·검색·삭제까지의 책임과 기준을 정하여, 일반 운영 로그와 개인정보 접속기록의 서로 다른 요구사항이 실제 시스템 설정에 반영되도록 합니다.

적용 조건

적용 시점

Implementation Guide

1. 시스템별 로그 항목·보관기간·조회 책임의 명확한 정의

자산별 기록 목적, 필수 항목, 수집 주기, 보관기간과 조회 책임자를 정합니다. 개인정보 접속기록은 해당 시점에 시행 중인 법령의 적용 대상·규모에 따른 요건을 확인하고, 일반 로그에도 같은 기간을 일괄 적용하지 않습니다.

보관기간은 법정 최소기간뿐 아니라 탐지·조사에 필요한 기간과 개인정보 최소 보유 원칙을 함께 검토합니다. 적용 근거와 결정자를 남기고 클라우드 서비스의 기본 보관기간이 조직 기준보다 짧은 경우 별도 저장 수단을 마련합니다.

2. 필요한 활동 기록과 표준시각 동기화의 설정·확인

이용자 식별정보, 행위, 대상, 결과와 시각 등 분석에 필요한 항목이 생성되는지 표본으로 확인합니다. 각 시스템의 시각을 표준시각에 맞추고 비밀번호·인증 토큰과 불필요한 개인정보가 기록되지 않도록 설정합니다.

로그인 성공·실패, 권한 변경과 주요 데이터 접근이 실제 기록되는지 표본 작업으로 확인합니다. 시스템 업데이트 후 기록 형식이나 시간 설정이 달라졌는지 검토하고 변경된 필드는 수집·검색 규칙에 반영합니다.

3. 로그 전송·저장 경로와 변경·삭제 권한 보호

로그 전송과 보관 경로에 접근통제와 필요한 암호화를 적용합니다. 기록 생성·운영 담당자가 조사에 필요한 로그를 임의 삭제·변경하지 못하도록 권한을 분리하고 변경·삭제 이력을 관리합니다.

중앙 저장소 접근권한을 분석·운영·관리 역할로 구분하고 관리자 작업도 별도로 기록합니다. 전송 장애 시 임시 저장과 재전송이 가능한지 확인하여 잠깐의 통신 장애가 영구적인 자료 누락으로 이어지지 않도록 합니다.

4. 수집 상태와 보관 로그의 검색·복구 가능성 점검

수집 중단, 지연과 저장공간 부족을 감시하고 장애 발생 시 복구 담당자에게 알립니다. 실제 시간·계정·사건 조건으로 검색해 보고 보관된 기록을 복구할 수 있는지 확인합니다.

저장량 증가 추세와 남은 용량을 확인하여 보관기간 전에 기록이 순환 삭제되지 않도록 합니다. 현재 화면에 보이는 최근 로그뿐 아니라 오래된 기간의 표본 로그도 실제로 검색·복원하여 점검합니다.

5. 보관기간 만료 기록의 삭제와 조사 목적 보존 관리

보관기간 만료 시 불필요한 기록을 안전하게 삭제합니다. 진행 중인 조사나 법적 보존 의무가 있는 기록은 근거·대상·승인자·재검토일을 정하여 별도 보호하고 목적 종료 후 정리합니다.

보존 예외에는 대상 사건·기록 범위와 보존 종료 판단자를 명시합니다. 삭제는 운영본과 복제·백업본의 정책을 함께 검토하고, 즉시 삭제할 수 없는 매체는 접근 제한과 최종 삭제 시점을 관리합니다.

Evidence

  • 로그 관리 기준·목록: 기록 항목, 보관기간, 법적 요건과 담당자의 구분을 보여줍니다.
  • 로그 표본·시각 동기화 설정: 필요한 활동이 정확한 시각으로 기록되는지 확인하는 자료입니다.
  • 접근권한·수집 상태 기록: 기록의 임의 변경을 제한하고 수집 장애를 관리한 증적입니다.
  • 검색·복구 시험 및 삭제 기록: 필요 시 기록을 활용하고 보관 목적 종료 후 정리했음을 입증합니다.

악성 파일을 발견한 위치가 최초 침입 지점과 같다고 볼 수 없으며, 한 가지 취약점을 고쳐도 계정이나 관리 절차의 문제가 남을 수 있습니다. 이 Control은 증거의 한계와 대안 가설을 함께 검토하여 설명 가능한 사고 경위를 만들고 원인별 개선조치를 검증할 수 있도록 합니다.

Implementation Guide

1. 사고 경위 규명을 위한 조사 질문과 증거 보존 범위 설정

최초 침입 시점, 이용된 계정, 변경·반출된 정보 등 확인할 질문을 정합니다. 사건 번호를 부여하고 원본 로그와 관련 자료의 보존을 요청하여 자동 삭제나 정상 운영 작업으로 근거가 사라지지 않게 합니다.

조사 질문별로 필요한 로그·시스템 상태와 자료 보유자를 연결합니다. 보존 요청에는 기간과 대상 식별자를 명시하고 외부 제공자에게 요청한 자료의 제공 가능 범위와 예상 시점을 확인합니다.

2. 주요 행위를 시간순으로 연결한 사고 경위 재구성

인증, 시스템 실행, 통신과 데이터 접근 기록을 표준시각 기준으로 연결합니다. 시각 오차와 기록 공백을 표시하고 최초 침입부터 탐지·대응까지의 경위를 작성합니다.

발견된 흔적을 최초 침입, 권한 획득, 내부 이동과 반출·변경 단계로 나누어 검토합니다. 기록 공백이 있는 구간은 추정한 내용과 추정 근거를 표시하여 확인된 활동과 혼동되지 않게 합니다.

3. 기술적 원인 가설의 증거 대조와 검증

취약점 악용, 계정 탈취와 잘못된 설정 등 가능한 원인을 증거와 대조합니다. 확인된 사실과 추정을 구분하고 반대 증거도 검토하여 단일 경보만으로 원인을 확정하지 않습니다.

취약점 악용으로 판단한다면 해당 버전·설정과 실제 공격 흔적이 일치하는지 확인합니다. 조사 환경에서 재현이 필요한 경우 운영 시스템에 영향을 주지 않는 환경과 승인된 방법을 사용하고 재현의 한계도 남깁니다.

4. 기술적 원인과 연결된 관리상 미흡 사항·피해 확인

기술적 원인을 가능하게 한 권한 관리, 변경 승인과 점검 누락을 함께 분석합니다. 영향받은 업무와 데이터 범위를 사고 규모 평가 결과와 대조하고 불일치 사항은 재조사합니다.

패치 지연, 과도한 권한과 경보 미처리 등 원인별로 관련 절차가 있었는지와 실제 이행 여부를 구분합니다. 개인의 실수로만 원인을 종결하지 않고 승인·검토·자원 부족처럼 반복을 유발하는 요인도 확인합니다.

5. 근본 원인별 재발방지 과제 수립과 효과 확인

원인별 개선 과제, 담당자와 기한을 지정하여 책임자에게 보고합니다. 조치 후 같은 공격 경로가 차단되는지 시험하고 결과를 탐지 규칙·운영 절차·교육에 반영합니다.

각 개선 과제에 어떤 원인을 해소하는지와 완료를 판단할 증거를 연결합니다. 설정 변경이나 패치 적용 사실뿐 아니라 같은 침입·확산 경로가 다시 이용되지 않는지 확인한 뒤 과제를 종결합니다.

Evidence

  • 원인 가설·검증 기록: 확정 사실과 미확인 사항을 구분하고 원인 판단을 검증한 자료입니다.
  • 사고 원인 분석 보고서: 기술적 원인과 관리상 미흡 사항을 함께 정리한 결과입니다.
  • 개선 과제·재시험 결과: 원인 분석이 재발방지 조치와 효과 확인으로 이어졌음을 보여줍니다.

Control Objective

사고 조사 활동과 판단을 추적할 수 있게 기록하고 기록의 변경 여부와 작성·취급 이력을 확인할 수 있게 합니다. 누가 언제 어떤 대상에 어떤 작업을 수행했는지와 그 판단 근거를 확인할 수 있도록 조사 일지를 관리합니다. 인계나 사후 검토 과정에서 조사자가 바뀌어도 결과를 재확인할 수 있게 하여 설명되지 않는 기록 변경과 조사 공백을 방지합니다.

Control Statement

사고 조사 중 수행한 작업 자체가 시스템이나 증거의 상태를 바꿀 수 있습니다. 조직은 조사자의 활동과 판단을 추적할 수 있도록 기록하고, 해당 기록의 작성 경위와 변경 이력을 보호하여 조사 결과의 신뢰성을 확보해야 합니다.

조사자가 수행한 조회·복사·격리도 시스템 상태에 영향을 줄 수 있으므로 사고 당시 활동과 조사 활동을 구분할 수 있어야 합니다. 이 Control은 원시 증거 수집과 별도로 조사 과정의 연속성을 관리하여, 결론을 도출한 절차와 책임을 추적할 수 있게 합니다.

적용 조건

적용 시점

사고 조사 착수부터 분석·인계·종료 및 조사 기록 보관·정정 시 적용합니다.

적용 대상

조사자가 수행한 명령·조회·자료 처리, 승인·판단, 담당자 간 인계와 조사 일지에 적용합니다. 개인정보 관련 법령·고시의 의무는 해당 개인정보 처리와 법정 적용 요건에 따라 적용합니다.

Implementation Guide

1. 조사 활동과 변경 작업을 기록할 공통 기준 마련

사건 번호, 작성자, 수행 시각, 작업 대상, 목적과 결과를 기록하도록 양식을 정합니다. 시스템 상태를 변경하는 작업은 승인자와 예상 영향을 함께 남기도록 합니다.

같은 사건을 여러 조직이 조사할 경우 사건 번호와 기록 시각의 기준을 통일합니다. 도구의 자동 기록을 활용하더라도 사람이 내린 판단과 승인·예외 사유는 추가로 남기도록 합니다.

2. 조사 작업의 수행 시각·방법·결과를 연속적으로 기록

조회·수집·분석에 사용한 도구와 명령, 주요 설정 및 발견 사항을 작업 시점에 기록합니다. 긴급 조치로 즉시 작성하지 못한 경우 실제 수행 시각과 나중에 작성한 시각을 구분하여 보완합니다.

시스템 상태에 영향을 준 작업은 실행 전후 상태와 예상하지 못한 변화를 남깁니다. 교대근무 중에도 기록이 이어지도록 작업 종료 시 미작성 항목과 진행 중인 명령·분석의 상태를 확인합니다.

3. 분석 결론과 사용 증거·판단 근거의 연결 관리

분석 결론에는 사용한 증거 식별자와 확인 방법을 연결합니다. 조사자의 추정과 관찰 사실을 구분하고 다른 담당자가 판단 과정을 따라갈 수 있도록 기록합니다.

보고서의 주요 결론에서 증거 목록과 조사 일지로 이동할 수 있도록 식별자를 사용합니다. 의견이 달라진 경우 이전 판단을 삭제하지 않고 추가 증거와 변경 이유를 기록합니다.

4. 조사 기록의 작성 경위와 무결성을 확인할 보호조치 적용

기록의 작성·수정 권한을 제한하고 버전 이력과 변경 사유를 보존합니다. 필요에 따라 변경 탐지값인 해시값이나 변경 방지 저장소를 사용하고 작성자·수정자·인계자를 추적할 수 있게 합니다.

수정·삭제 권한은 필요한 역할로 제한하고 기록 저장소의 관리자 활동도 점검합니다. 기록을 외부에 전달할 때는 전달한 버전과 포함 범위를 보존하여 내부 최종본과의 차이를 설명할 수 있게 합니다.

5. 인계·종료 시 조사 기록의 완전성 확인과 보관

조사 인계 시 완료 작업, 미확인 사항과 기록 위치를 확인합니다. 종료 시 누락을 검토하고 승인된 보관기간·접근권한을 적용하며 정정이 필요하면 원래 기록을 남기고 정정 사유를 추가합니다.

조사 종료 전 주요 대응 작업이 일지에 빠짐없이 남아 있는지 작업 목록과 대조합니다. 미확인 사항과 후속 조사 책임을 인계 문서에 명시하고 보관 중 열람 요청도 승인·기록합니다.

Evidence

  • 조사 일지·작업 기록: 조사자가 언제 무엇을 수행하고 어떤 결과를 얻었는지 보여줍니다.
  • 판단·증거 연결 기록: 조사 결론의 근거 자료와 검증 방법을 확인할 수 있습니다.
  • 버전·접근·변경 이력: 조사 기록의 출처와 무단 변경 방지 상태를 확인하는 자료입니다.
  • 조사 인계·종료 확인서: 기록의 연속성과 미완료 사항의 전달 여부를 입증합니다.

IEM-C-10

Control Name

사고 데이터·메타데이터 수집 및 증거 신뢰성 확보

Security Domain

Information Security Event Management

Control Class

Common

Control Objective

사고 데이터와 수집 맥락을 확보하고 자료의 무결성·출처·취급 이력을 보존합니다. 로그·메모리·저장장치 자료와 수집 시각·도구·원래 위치를 함께 관리하여 조사 결과를 뒷받침하는 근거를 확보합니다. 자료의 변경 여부와 보관 책임을 추적할 수 있게 하여 분석 과정에서 원본과 사본이 혼동되거나 출처가 불분명해지는 것을 방지합니다.

Control Statement

사고 당시의 데이터는 삭제되거나 변경될 수 있으며, 수집 경위를 알 수 없으면 해석이 어려워집니다. 조직은 분석에 필요한 데이터와 그 맥락을 설명하는 메타데이터를 함께 수집하고 원본성·무결성·인계 과정을 관리해야 합니다.

재부팅·자동 삭제·자원 폐기 등 정상 운영 작업도 사고 당시 자료를 없앨 수 있으며, 수집 과정에서 원본 상태가 달라질 수 있습니다. 이 Control은 수집 권한과 우선순위, 원본 보호와 인계 이력을 함께 관리하여 자료를 안전하고 설명 가능한 방식으로 조사에 활용하도록 합니다.

적용 조건

적용 시점

사고 증거를 확보·분석·전달하거나 보관할 때 적용하며, 휘발성 자료는 사라지기 전에 수집 필요성을 판단합니다.

적용 대상

로그, 메모리·저장장치 자료, 통신 기록과 클라우드 자료 및 수집 시각·도구·출처 등의 메타데이터에 적용합니다. 개인정보 관련 법령·고시의 의무는 해당 개인정보 처리와 법정 적용 요건에 따라 적용합니다.

관련 법령

  • 「개인정보 보호법」 제29조 — 개인정보의 유출등을 방지하기 위한 기술적·관리적·물리적 안전조치 의무.
  • 「개인정보의 안전성 확보조치 기준」 제8조 — 개인정보처리시스템 접속기록의 보관·점검과 안전한 보관을 위한 조치 의무.

Implementation Guide

1. 자료 소실 위험과 수집 권한을 고려한 증거 확보 계획 수립

조사 목적에 필요한 자료, 확보 권한과 개인정보 포함 여부를 확인합니다. 시스템 운영 중단과 자료 소실 위험을 비교하여 메모리 등 휘발성 자료의 수집 순서를 정하고 외부 서비스의 자료 보존도 요청합니다.

메모리·실행 중 연결과 같이 소실이 빠른 자료의 필요성을 먼저 검토합니다. 운영 중단을 수반하는 수집은 업무 책임자와 영향·시점을 협의하고, 급한 조치로 자료를 확보하지 못한 경우 사유와 대체 자료를 기록합니다.

2. 원시 데이터와 수집 시점의 메타데이터 동시 확보

자료마다 식별자를 부여하고 원래 위치, 수집자·시각·시간대, 도구와 버전·설정 및 수집 방법을 기록합니다. 수집 때문에 원본 상태가 변한 경우 변경 내용과 제한 사항을 함께 남깁니다.

클라우드에서 내려받는 자료는 계정·자원 식별자, 조회 기간과 제공 방식도 기록합니다. 자동 변환이나 필터링이 적용된 자료는 원본 그대로의 자료와 구분하여 분석 시 누락·변형 가능성을 확인할 수 있게 합니다.

3. 원본 증거의 보호와 분석용 사본의 무결성 검증

가능한 범위에서 원본을 보호하고 분석은 복제본으로 수행합니다. 수집·복사 시 해시값을 계산하여 이후 변경 여부를 비교하되, 해시값만으로 수집의 적법성이나 증거능력이 보장되는 것으로 보지 않습니다.

원본은 가능한 범위에서 쓰기 제한 상태로 보관하고 작업별 분석 사본을 구분합니다. 복사나 전송 후에는 해시값 등으로 동일성을 확인하고 불일치가 있으면 사용을 중단하여 원인과 자료 상태를 검토합니다.

4. 증거 보관·전송·인계 과정의 접근통제와 추적성 확보

자료에 접근할 수 있는 사람을 제한하고 전송·보관 중 노출을 방지합니다. 인계할 때마다 전달자·수령자·시각·목적과 자료 상태를 기록하여 누가 보관했는지 연속적으로 확인할 수 있게 합니다.

전달자와 수령자가 자료 식별자·수량·상태를 함께 확인하고 인수 시각을 기록합니다. 외부 전문가가 분석하는 경우 이용 목적, 재전달 제한과 반환·삭제 조건을 확인하여 증거의 관리 책임이 끊기지 않도록 합니다.

5. 분석에 사용한 증거의 연결과 보관 종료 조건 관리

분석 결과에 사용한 자료 식별자를 연결하고 손상·누락 자료의 영향도 기록합니다. 조사·분쟁 등 보존 사유를 검토하여 보관기간을 정하고 종료 후 승인된 절차로 삭제합니다.

자료가 손상되었거나 일부만 확보된 경우 분석 결론에 미치는 영향을 설명합니다. 조사 종료 후에도 법적 보존 사유가 남아 있으면 대상과 재검토 시점을 관리하고, 보존 사유가 끝나면 승인된 절차로 정리합니다.

Evidence

  • 증거 수집 계획·권한 확인: 필요한 범위와 수집 방법의 적정성을 확인한 근거입니다.
  • 증거 목록·수집 메타데이터: 자료의 출처와 수집 당시 상황을 재확인할 수 있는 자료입니다.
  • 해시 검증·인계 기록: 수집 이후 변경 여부와 보관 책임의 연속성을 보여줍니다.
  • 증거 접근·보관·삭제 이력: 민감한 조사 자료가 승인된 범위에서 관리되었음을 입증합니다.

Security Domain

Information Security Event Management

Common

Control Objective

확인된 사고의 규모와 심각도를 추정·검증하여 대응 범위와 자원 배분에 활용합니다. 침해된 자산·계정, 영향을 받은 정보·이용자와 서비스 중단 범위를 실제 기록과 업무 확인으로 검증합니다. 초기 추정과 확인된 피해를 구분하고 조사 범위를 반복 확대·조정하여 대응 인력, 격리 대상과 복구 순서가 실제 사고 규모에 맞게 결정되도록 합니다.

Control Statement

사고가 확인된 뒤에는 실제 영향을 받은 범위를 검증해야 대응 자원을 적절히 배분할 수 있습니다. 조직은 피해 자산·정보·이용자와 업무 영향을 반복 확인하여 사고 규모를 평가하고 대응 범위 결정에 반영해야 합니다.

공격 흔적이 발견된 시스템만 조사하면 공통 계정이나 연결 서비스로 확산된 피해를 놓칠 수 있습니다. 이 Control은 이미 확인된 사고의 전체 범위를 검증하는 데 초점을 두며, 자료가 부족한 구간을 피해가 없는 구간으로 간주하지 않도록 합니다.

적용 조건

적용 시점

사고 선언 후, 추가 침해 흔적이나 피해가 확인될 때 및 대응 범위·자원 규모를 조정할 때 적용합니다.

적용 대상

사고 관련 자산·계정·정보·업무와 연결된 내부 시스템 및 외부 서비스에 적용합니다. 개인정보 관련 법령·고시의 의무는 해당 개인정보 처리와 법정 적용 요건에 따라 적용합니다.

Implementation Guide

1. 사고 규모를 판단할 자산·정보·업무별 평가 단위 정의

침해된 자산 수, 계정, 정보 항목·건수, 이용자와 중단 시간 등 필요한 평가 단위를 정합니다. 초기 예상 영향 평가를 출발점으로 삼되 실제 확인된 피해와 잠재 영향을 구분합니다.

개인정보 건수와 정보주체 수, 시스템 수와 서비스 수처럼 서로 다른 단위를 구분합니다. 중복 집계 기준과 산정 담당자를 정하여 부서별 보고 수치가 서로 다른 기준으로 합산되지 않게 합니다.

2. 관련 자산·기간 전체에 대한 침해 흔적 검색과 범위 확인

확인된 공격 주소, 파일과 계정 사용 흔적을 관련 시스템과 기간 전체에서 검색합니다. 공통 계정·연결 서비스와 외부 제공자까지 조사 범위를 검토하고 로그가 없다는 이유만으로 영향이 없다고 판단하지 않습니다.

공격에 이용된 계정의 다른 접속 대상과 공유 인증정보 사용 여부를 확인합니다. 검색 조건, 대상 목록과 검색하지 못한 구간을 남겨 나중에 새로운 흔적이 확인되면 같은 범위에 재검색할 수 있도록 합니다.

3. 업무 중단과 데이터 유출·변경 범위의 사실 검증

업무 담당자와 서비스 장애·데이터 변경·반출 여부를 확인합니다. 개인정보의 종류·대상과 중복을 확인하여 과대·과소 집계를 줄이고 확인 불가능한 범위와 이유를 명시합니다.

다운로드나 외부 전송 기록이 있다는 사실과 실제 반출된 데이터의 내용을 구분하여 확인합니다. 서비스 담당자의 장애 보고와 시스템 기록을 대조하고 자료가 일치하지 않으면 수치를 확정하기 전에 원인을 확인합니다.

4. 검증된 사고 규모에 따른 대응 범위와 자원 배분 조정

검증된 규모에 따라 분석 인력, 외부 지원, 격리 대상과 복구 순서를 제안합니다. 책임자는 업무 영향과 잔여 위험을 검토하여 자원 배분을 결정하고 통지·신고 담당자에게 최신 규모를 전달합니다.

피해가 새로 확인된 업무의 책임자를 대응 조직에 포함하고 추가 분석·지원 필요성을 판단합니다. 통지 대상이나 복구 우선순위가 바뀌는 경우 관련 담당자에게 변경된 수치와 근거를 함께 전달합니다.

5. 규모 평가의 변경 이력과 미확인 범위 추적

추가 피해와 조치 결과를 반영하여 범위를 갱신하고 이전 수치가 변경된 근거를 남깁니다. 조사 종료 시 미확인 범위와 후속 확인 책임자를 명확히 하여 사고 보고서에 반영합니다.

각 평가본에 기준 시각과 확인 완료·진행 중 범위를 표시합니다. 사고 종결 시에도 미확인 범위가 남아 있다면 이를 숨기지 않고 잔여 위험, 추가 확인 방법과 책임자를 보고합니다.

Evidence

  • 사고 규모 평가표: 확인된 피해, 잠재 영향과 미확인 범위를 구분한 자료입니다.
  • 침해 흔적 검색·검증 결과: 관련 자산과 기간을 대상으로 범위를 확인한 증적입니다.
  • 업무·개인정보 영향 확인 자료: 서비스와 정보 피해의 집계 근거를 보여줍니다.
  • 자원 조정·범위 갱신 기록: 규모 평가가 대응 의사결정에 반영되었음을 확인할 수 있습니다.

Control Name

사고 관계자의 적시 인지와 의무 이행을 위한 사고 통지

Security Domain

Information Security Event Management

Control Class

Common

Control Objective

사고 관계자에게 법령·계약·내부 규정에 따라 적시에 통지하여 필요한 보호조치와 의무 이행을 지원합니다. 사고 유형별 통지·신고 대상과 기한을 확인하고 인지 시각, 판단 근거와 발송 이력을 관리합니다. 정보주체·고객·관계기관이 필요한 보호조치를 취할 수 있게 하며, 조사 완료나 내부 승인 대기로 법적·계약상 의무가 지연되는 것을 방지합니다.

Control Statement

사고 관계자는 적시에 상황을 알아야 피해를 줄이고 필요한 조치를 할 수 있습니다. 조직은 사고 유형과 적용 법령·계약에 따른 통지·신고 의무를 식별하고, 기한 내에 정확한 정보를 전달하여야 합니다.

내부 경보 전달과 관계자에게 보내는 공식 통지·신고는 대상, 내용과 기한이 다릅니다. 이 Control은 법무·개인정보보호·대응 조직의 판단을 연결하고 확인된 사실의 보완·정정까지 관리하여 부정확한 안내와 통지 누락으로 인한 피해를 줄이도록 합니다.

적용 조건

적용 시점

사고 또는 법령상 통지·신고 요건에 해당할 수 있는 상황을 인지했을 때, 추가 사실이 확인되거나 통지 내용이 달라졌을 때 적용합니다.

적용 대상

사고의 내부 보고와 정보주체·고객·거래처·관계기관에 대한 통지·신고에 적용합니다. 개인정보 관련 의무는 개인정보처리자에게, 정보통신망법상 침해사고 신고 의무는 해당 정보통신서비스 제공자에게 적용합니다.

관련 법령

  • 「개인정보 보호법」 제34조 — 개인정보 유출등 및 법정 요건에 해당하는 유출등의 가능성에 대한 통지와 유출등의 신고·피해 최소화 조치 의무.
  • 「정보통신망 이용촉진 및 정보보호 등에 관한 법률」 제48조의3 — 정보통신서비스 제공자의 침해사고 발생 사실 및 대응 현황 등에 대한 신고 의무.

Implementation Guide

1. 사고 유형별 법정·계약상 통지와 신고 요건 정리

사고 유형별 수신자, 발생 요건, 기한, 필수 항목과 전달 방법을 정리합니다. 개인정보 유출등과 법령이 정한 유출 가능성의 통지 대상 여부를 구분하여 검토하고, 법정 의무와 계약·내부 보고 의무의 기산점과 기한을 별도로 관리합니다.

의무표에는 근거 조문, 인지의 판단 기준, 제출 채널과 기한 계산 방법을 포함합니다. 법령이 바뀌거나 계약을 새로 체결하면 담당자가 검토하고 기존 문안·연락처·제출 권한도 함께 갱신합니다.

2. 사고 인지 시각과 의무 적용 여부의 신속한 판단

최초 인지 시각, 확인 경위와 현재까지 알려진 영향을 기록하고 법무·개인정보보호 담당자가 적용 요건을 확인합니다. 내부 사고 선언이나 최종 원인 분석이 끝나지 않았다는 이유로 법정 기한의 판단을 늦추지 않습니다.

신고 접수, 담당자 확인과 추가 사실 확인의 시각을 각각 기록합니다. 의무 적용 판단에 필요한 정보가 부족하면 추가 확인 담당자와 기한을 지정하고, 진행 상황을 책임자가 추적하도록 합니다.

3. 수신 대상별 필수 내용과 피해 예방 정보를 반영한 문안 작성

확인된 사실, 피해를 줄이는 방법, 조직의 조치와 문의 창구 등 해당 의무에서 요구하는 항목을 작성합니다. 미확인 내용은 확정 사실처럼 표현하지 않으며, 공격에 악용될 상세정보와 다른 사람의 개인정보가 노출되지 않게 검토합니다.

정보주체에게는 본인이 취할 수 있는 보호 방법과 문의 창구를 이해하기 쉽게 안내합니다. 관계기관 제출본과 고객 안내본은 요구 항목이 다를 수 있으므로 각각 검토하고 확인되지 않은 피해 규모나 원인을 단정하지 않습니다.

4. 법정 기한 내 승인·통지·신고와 전달 결과 확인

긴급 승인권자와 대체 승인자를 통해 기한 내에 통지·신고합니다. 수신 대상, 발송 시각·방법, 제출 내역과 전달 실패를 기록하고, 승인 지연이 예상되면 즉시 상위 책임자에게 보고합니다.

담당자 부재나 전산 제출 장애가 생겼을 때 사용할 대체 승인·제출 방법을 준비합니다. 이메일 반송 등 전달 실패는 별도로 관리하고 법령이 허용하는 보완·대체 통지 방법의 적용 여부를 확인합니다.

5. 추가 사실의 보완 통지와 피해 구제 요청 처리

조사 결과가 달라지면 관련 법령과 수신기관 절차에 따라 보완·정정합니다. 문의·피해 구제 요청을 담당 부서에 연결하고 통지 누락·지연 여부와 재발방지 과제를 검토합니다.

새롭게 확인된 항목과 이전 안내에서 변경된 사항을 구분하여 전달합니다. 문의 대응 부서에는 최신 승인 문안을 제공하고 통지 누락·오류·지연 사례는 의무표와 승인 절차 개선에 반영합니다.

Evidence

  • 통지·신고 의무표: 사고별 적용 근거, 요건, 수신자와 기한을 확인하는 자료입니다.
  • 인지 시각·의무 판단 기록: 기한 산정과 통지·신고 대상 판단의 근거입니다.
  • 승인 문안·발송·제출 내역: 실제 전달 내용과 기한 준수 여부를 확인할 수 있습니다.
  • 보완 통지·문의 처리 기록: 새로운 사실과 정보주체·관계자의 요청이 후속 처리되었음을 보여줍니다.

IEM-C-13

Control Name

대응 협업과 의사결정을 위한 통제된 사고 정보 공유 보장

Security Domain

Information Security Event Management

Control Class

Common

Control Objective

사고 대응에 필요한 정보를 지정된 관계자에게 승인된 범위와 방법으로 공유합니다. 내부 대응자와 외부 협력자에게 역할에 필요한 최신 사고 정보를 제공하면서 자료의 민감도·수신 권한·재공유 범위를 관리합니다. 협업에 필요한 근거는 전달하되 개인정보, 미공개 취약점과 조사 자료가 불필요하게 확산되는 위험을 줄입니다.

Control Statement

사고 대응에는 여러 부서와 외부 기관의 협력이 필요하지만, 무분별한 정보 공유는 추가 유출이나 조사 방해를 일으킬 수 있습니다. 조직은 지정된 관계자에게 필요한 정보를 적절한 시점에 제공하고 공유 범위·권한·방법을 통제해야 합니다.

사고 대응 과정에서는 빠른 공유가 필요하지만 수신자가 많아질수록 오래된 정보의 재사용과 목적 외 제공 가능성도 커집니다. 이 Control은 정보의 승인·배포·갱신·접근 종료를 연결하여 관계자가 같은 사실을 바탕으로 대응하고 자료의 취급 책임을 추적할 수 있도록 합니다.

적용 조건

적용 시점

적용 대상

내부 지휘부, 기술 대응자와 외부 협력자별로 필요한 정보와 사용 목적을 정합니다. 개인정보를 포함한 자료는 공유 전에 법적 근거와 계약상 비밀유지·재공유 제한을 확인합니다.

기술 조사자는 상세 로그가 필요할 수 있지만 경영진이나 고객 대응자는 영향·진행 상황의 요약이 필요할 수 있습니다. 역할별 정보 범위를 정하고 외부 관계자가 바뀌면 기존 접근권한과 새 수신자의 계약·권한을 함께 확인합니다.

2. 정보의 민감도와 수신 권한에 따른 공유 범위 결정

사고 개요, 공격 지표, 취약점 상세와 개인정보를 구분합니다. 수신자의 역할에 따라 내용을 축약·가림 처리하고 원본 조사 자료는 꼭 필요한 담당자만 열람하도록 합니다.

자료마다 개인정보, 인증정보와 악용 가능한 공격 절차가 포함되었는지 확인합니다. 원본 전달이 꼭 필요하지 않으면 요약본이나 식별정보를 제거한 자료를 제공하고, 상세 자료의 별도 요청은 승인 절차로 처리합니다.

3. 확정 사실과 추정을 구분한 공유 문안 검토·승인

확정 사실, 추정 사항과 권고 조치를 구분하여 작성합니다. 승인권자는 최신성·정확성·공개 위험을 검토하고 긴급 공유가 필요한 경우의 대체 승인 절차도 마련합니다.

자료에 기준 시각과 버전을 표시하고 정보가 변경될 수 있는 부분을 명확히 합니다. 여러 부서가 별도 문서를 만드는 경우 승인된 상황 보고를 기준으로 내용이 서로 충돌하지 않는지 확인합니다.

4. 수신자 확인과 전송·열람 이력을 갖춘 안전한 공유

수신자를 확인할 수 있는 보안 채널로 전송하고 필요한 경우 다운로드·접근 유효기간을 제한합니다. 누가 어떤 버전의 자료를 언제 받았는지 기록하고 발송 실패나 잘못된 수신자 전송을 즉시 처리합니다.

공유 링크를 사용하는 경우 대상 계정과 유효기간을 제한하고 공개 접근이 허용되지 않는지 확인합니다. 잘못 전달된 자료는 접근 차단·회수와 추가 노출 확인을 수행하고 사고대응 책임자에게 즉시 알립니다.

5. 상황 변화에 따른 자료 갱신과 공유 종료 관리

사고 상황이 바뀌면 변경 사항을 기존 수신자에게 알려 오래된 정보로 대응하지 않도록 합니다. 협조 요청의 처리 결과를 확인하고 공유 목적 종료 시 접근권한과 제공 자료의 보관·삭제를 정리합니다.

중요한 정정이 있으면 기존 자료를 받은 대상에게 변경 사실을 직접 알리고 구버전 사용 중단을 요청합니다. 협업이 끝난 뒤에는 접근권한·보관 사유와 반환·삭제 이행 여부를 확인하여 장기간 자료가 남지 않도록 합니다.

1. 사고 유형에 맞는 대응 계획 가동과 지휘·실무 역할 배정

선언된 사고의 유형·등급에 맞는 대응 계획을 선택하고 지휘 책임자와 실무 담당자를 지정합니다. 유형별 실행 절차인 플레이북에 따라 초기 목표·연락 채널·상황 보고 주기를 공유합니다.

계획 가동 시 현재 상황, 즉시 해야 할 조치와 승인 없이 수행할 수 있는 범위를 공유합니다. 한 사람이 여러 역할을 맡으면 의사결정과 실행의 확인 방법을 정하고 교대 시 지휘 책임이 누구에게 있는지 명확히 합니다.

2. 계약된 외부 전문기관과 서비스 제공자의 대응 참여 조정

관제·클라우드·조사 전문기관 등 필요한 협력자를 계약과 권한에 따라 호출합니다. 지원 범위, 자료 접근, 보고 방법과 응답 시간을 확인하고 의무 통지·신고 담당자도 참여시킵니다.

지원 요청에는 사건 개요, 필요한 작업과 자료 접근 범위를 포함합니다. 공급자가 담당하는 기반시설과 조직이 직접 관리하는 설정의 경계를 확인하여 같은 조치를 중복 수행하거나 책임 공백이 생기지 않도록 합니다.

3. 대응 작업의 담당자·기한·승인 상태 통합 관리

조사, 격리, 증거 보존, 통지와 복구 준비를 담당자·기한별 작업 목록으로 관리합니다. 서비스 중단이나 데이터 변경을 수반하는 조치는 승인권자에게 영향과 대안을 제시하고 결정 내용을 남깁니다.

작업 목록에 선행 조건과 다른 조치에 미치는 영향을 표시합니다. 예를 들어 재부팅이 증거 수집을 방해할 수 있으면 조사 담당자와 작업 순서를 조정하고 긴급 변경의 결정 근거를 남깁니다.

4. 정기 상황 점검과 사고 변화에 따른 대응 계획 조정

정해진 시점과 중대한 변화 발생 시 진행 상황·피해 범위·미완료 작업을 확인합니다. 계획으로 처리하기 어려운 상황은 상위 책임자에게 보고하여 인력·예산·외부 지원과 대응 순서를 조정합니다.

회의나 상황 보고에는 완료 작업, 지연 사유, 새로 확인한 위험과 결정이 필요한 사항을 포함합니다. 사고가 확대되면 기존 대응 계획의 한계를 확인하고 지휘 책임자가 인력·우선순위·외부 지원을 재배정합니다.

5. 복구 단계 인계와 사고 대응 과정의 개선 사항 정리

복구 개시 기준을 충족했는지 확인한 뒤 미완료 조치와 잔여 위험을 복구 담당자에게 인계합니다. 대응 과정의 병목과 협력자 이행 결과를 검토하여 계획과 계약·훈련에 반영합니다.

복구 담당자에게 미완료 조사, 유지해야 할 제한과 확인해야 할 재침해 징후를 전달합니다. 대응 종료 후 계획과 실제 수행의 차이를 검토하여 연락망·권한·계약·훈련 내용의 개선 과제로 등록합니다.

Implementation Guide

1. 업무 영향과 긴급성을 반영한 사고 유형·등급 기준 수립

계정 탈취, 악성코드 감염, 정보 유출과 서비스 중단 등 조직에 필요한 유형을 정의합니다. 심각도는 중요 업무 영향, 정보 민감도, 피해 범위와 확산 속도를 기준으로 구분하고 대표 사례를 붙입니다.

심각도별 판단 조건에 핵심 서비스 중단, 정보 민감도와 확산 가능성 등 조직의 위험 기준을 반영합니다. 단일 기준으로 결정하기 어려운 복합 사고는 가장 중대한 영향과 판단 책임자를 확인할 수 있게 합니다.

2. 확인된 사실과 업무 맥락에 따른 사고 등급 판단

확인된 사실과 규모 평가 결과를 기준표에 대입합니다. 탐지 도구가 제시한 등급을 그대로 확정하지 않고 업무 담당자의 영향 판단과 확인되지 않은 위험을 함께 검토합니다.

초기 정보가 부족할 때 적용할 잠정 등급과 재평가 조건을 정합니다. 과소평가 위험이 큰 사안은 미확인 사실을 표시한 상태에서 우선 대응하도록 하되 등급 확정과 변경의 근거를 계속 보완합니다.

3. 심각도·긴급도에 따른 대응 순서와 목표 설정

심각도와 긴급성을 기준으로 착수 순서, 보고 수준과 담당 인력을 정합니다. 동시에 발생한 사고가 자원을 공유하면 결정권자가 우선순위를 조정하고 근거를 기록합니다.

등급별 착수·보고 목표와 필요 자원을 연결하여 분류가 단순한 표시에 그치지 않도록 합니다. 처리 순서를 낮추거나 예외를 적용한 경우에는 업무 사유와 잔여 위험을 책임자가 검토하도록 합니다.

4. 피해 범위 변화에 따른 등급 조정과 관계자 전달

추가 피해나 확산 여부가 확인되면 등급과 우선순위를 재검토합니다. 변경 전후 등급, 판단 사유·승인자와 시각을 남기고 관련 대응자·통지 담당자에게 알립니다.

등급을 올리거나 낮출 때는 변경을 유발한 증거와 승인자를 기록합니다. 이미 배정된 인력, 보고 주기와 통지 판단에도 변경이 필요한지 확인하여 화면의 등급만 수정되는 것을 방지합니다.

5. 사례 기반 분류 일관성 점검과 기준·교육 개선

종결 사고와 훈련 사례를 여러 담당자가 같은 기준으로 평가해 봅니다. 판단이 엇갈린 항목과 과소평가 사례를 기준·예시·교육에 반영합니다.

담당자별 평가 결과가 다르면 모호한 문구나 부족한 사례를 찾아 기준을 보완합니다. 실제 피해보다 낮게 평가된 사건은 어떤 정보가 누락되었는지 확인하여 초기 조사 질문과 재평가 조건에 반영합니다.

Evidence

  • 사고 유형·심각도 기준표: 유형과 등급을 판단하는 조건 및 사례가 정리된 자료입니다.
  • 사고 분류·우선순위 결정 기록: 업무 영향과 위험을 반영하여 처리 순서를 정한 근거입니다.
  • 등급 변경·전달 이력: 새로운 정보가 대응 수준에 반영되었음을 보여줍니다.
  • 분류 검토·교육 결과: 담당자 간 판단 차이를 확인하고 개선한 기록입니다.

Control Objective

사고 수준에 맞는 책임자와 의사결정 권한·자원을 적시에 확보합니다. 사고가 실무자의 처리 능력이나 권한을 넘으면 적절한 책임자와 전문 조직이 의사결정에 참여하도록 합니다. 업무 중단 승인, 추가 인력과 외부 지원 확보가 늦어지는 것을 방지하고 요청부터 실제 투입까지 책임을 추적할 수 있게 합니다.

Control Statement

실무 담당자의 권한이나 자원만으로 처리하기 어려운 사고는 의사결정이 지연되기 쉽습니다. 조직은 사고 수준과 대응 지연에 따라 상위 책임자에게 보고하거나 전문 대응 조직으로 이관하여 필요한 권한과 자원을 확보해야 합니다.

상황이 심각하더라도 보고 조건과 결정권자가 불명확하면 담당자는 조치를 미루거나 권한을 넘는 결정을 하게 될 수 있습니다. 이 Control은 경영진 보고와 기술 지원 이관을 구분하면서도 양쪽 결정이 실제 대응 작업으로 연결되게 하여 사고 수준에 맞는 조직적 지원을 확보하도록 합니다.

최고경영자(CEO)와 경영진은 사고 심각도와 사안별로 정한 승인 권한의 범위에 따라 중대 사고의 대응 방향과 추가 자원 투입을 승인합니다. 사고대응 책임자는 실무 수행·보고 및 승인사항의 이행 책임을 유지합니다.

적용 시점

적용 대상

사고대응 담당자, 부서 책임자, 경영진과 외부 전문기관 사이의 보고·이관·지원 요청에 적용합니다. 개인정보 관련 법령·고시의 의무는 해당 개인정보 처리와 법정 적용 요건에 따라 적용합니다.

Implementation Guide

1. 사고 수준과 대응 지연에 따른 상향 보고·이관 기준 정의

중요 업무 중단, 피해 확대, 법정 기한 임박과 담당자 권한 초과 등 보고 조건을 정합니다. 경영진 판단이 필요한 사안과 전문 기술 지원이 필요한 사안을 구분하고 처리 지연 기준도 포함합니다.

고위험 사고 외에도 담당자 미응답, 증거 분석 역량 부족과 자원 소진을 보고 조건에 포함합니다. 보고 조건별 필요한 결정과 보고 대상을 연결하여 같은 내용을 여러 조직에 전달한 뒤 아무도 결정하지 않는 상황을 줄입니다.

2. 긴급 조치의 승인권자와 부재 시 대체 의사결정 경로 마련

사고 심각도와 사안별 승인 권한에 따라, 중대 사고의 대응 방향과 추가 자원 투입 중 최고경영자(CEO)·경영진이 승인할 범위를 정합니다. 일상적인 대응 조치의 승인권한과 중대 사고의 의사결정 권한을 구분하고, 서비스 중단, 긴급 비용과 외부 지원 투입을 결정할 권한자를 정합니다. 담당자 부재 시 대체 승인자와 연락 방법을 마련하고 야간·휴일에도 의사결정이 가능하도록 합니다.

서비스 중단과 비용 집행처럼 성격이 다른 결정의 권한을 구분합니다. 비상 연락망에 결정 가능한 시간과 대체자를 포함하고 기존 승인권자와 연락이 닿지 않을 때의 전환 조건을 시험합니다.

3. 상위 책임자의 판단에 필요한 영향·대안·요청사항 보고

현재 피해, 수행한 조치, 남은 위험과 필요한 결정을 간결하게 제시합니다. 가능한 대안과 각각의 업무 영향·비용·시간을 함께 전달하여 책임자가 판단할 수 있도록 합니다.

보고 내용은 확인된 피해, 지연 시 위험, 선택 가능한 조치와 결정 시한으로 구성합니다. 불확실한 수치에는 추정 근거를 붙이고 책임자가 추가 자료만 기다리느라 긴급 판단을 놓치지 않도록 핵심 요청을 명확히 합니다.

4. 승인된 지원의 실제 투입과 대응 책임 인수 확인

사고대응 책임자는 사고 현황과 필요한 자원을 보고하고 최고경영자(CEO)·경영진의 검토·승인 내용과 해당 사안의 승인권자·승인 권한의 범위를 기록합니다. 승인된 지원과 조치를 담당자에게 배정하고 실제 투입 여부와 이행 결과를 확인·보고합니다. 사고를 다른 조직으로 이관하면 자료, 미완료 과제와 지휘 책임의 인수 시점을 명시합니다.

인력·전문기관 지원은 승인 여부뿐 아니라 연락 완료, 착수 시각과 담당 범위를 확인합니다. 지휘 권한을 넘기는 경우 기존 담당자와 새 책임자가 진행 상황과 미결정을 함께 확인한 뒤 인수 시점을 기록합니다.

5. 보고·결정·실행 지연의 원인 검토와 지원체계 개선

요청부터 응답·결정·실행까지 걸린 시간을 검토합니다. 불명확한 권한이나 부족한 외부 지원 계약 때문에 반복되는 지연은 경영진 검토와 대응 계획 개선에 반영합니다.

각 구간의 소요 시간을 구분하여 연락 지연인지 권한 부족인지 파악합니다. 예산·계약 때문에 반복 지연되는 지원은 사전 계약이나 긴급 집행 절차로 개선하고 다음 훈련에서 효과를 확인합니다.

Evidence

  • 상향 보고 기준·권한표: 누가 어떤 상황에서 결정을 내리는지 확인할 수 있습니다.
  • 긴급 보고·지원 요청서: 추가 권한과 자원을 요청한 근거 및 대안을 보여줍니다.
  • 승인·자원 투입·인수 기록: 보고가 실제 의사결정과 지원으로 연결되었음을 입증합니다.
  • 보고 지연 검토·개선 내역: 권한·연락·계약상의 병목을 개선한 자료입니다.
  • 경영진 검토·승인 및 승인 권한 기록: 사고 심각도별 승인권자와 승인 권한의 범위, 최고경영자(CEO)·경영진의 중대 사고 대응 방향·추가 자원 승인 내용 및 이행 결과를 확인합니다.

장애가 길어질수록 신속한 서비스 재개 요구가 커지지만, 백업이나 복구 이미지에도 침해 흔적이 남아 있을 수 있습니다. 이 Control은 복구를 시작할 수 있는 조건과 결정 책임을 명확히 하여 대응 조직과 복구 조직이 동일한 근거와 제한 조건에 따라 전환하도록 합니다.

Implementation Guide

1. 사고 유형과 업무 중요도에 따른 복구 개시 조건 수립

확산 차단, 악성 요소 제거 또는 충분한 Control, 필요한 증거 보존과 신뢰할 수 있는 복구 자료 확보를 조건으로 정합니다. 업무 중요도별 승인권자와 충족 여부를 확인할 담당자를 지정합니다.

시스템별로 반드시 충족해야 할 조건과 조건부 승인이 가능한 항목을 구분합니다. 복구 담당자만의 기술 판단으로 결정하기 어려운 서비스 영향과 잔여 위험의 승인권자도 정합니다.

2. 격리·근절 결과와 사고별 전환 조건 충족 여부 확인

격리·근절 조치 결과와 남아 있는 공격 경로를 확인합니다. 확인되지 않은 자산이나 취약점이 있으면 영향과 보완조치를 기록하고 단순히 경보가 줄었다는 이유로 안전하다고 판단하지 않습니다.

확인표의 각 조건에 조사 보고서, 차단 시험과 계정 조치 등 근거를 연결합니다. 충족하지 못한 항목은 단순 미완료 표시를 넘어서 위험과 필요한 추가 조치·예상 시간을 기록합니다.

3. 백업·복구 이미지와 복구 수행 준비 상태 검증

백업과 복구 이미지의 생성 시점·무결성·악성 요소 포함 여부를 확인합니다. 복구 순서, 의존 시스템, 필요한 인력과 실패 시 되돌리는 방법을 점검합니다.

복구 자료의 시점이 최초 침입 이전인지 판단하고 자료에 악성 설정이나 계정이 포함되어 있지 않은지 확인합니다. 먼저 시험 환경에서 복원·기능 확인을 수행하고 운영 전환에 필요한 의존 서비스와 감시 수단을 준비합니다.

4. 미충족 조건과 잔여 위험에 대한 복구 개시 승인

미충족 조건이 있으면 조건부 복구의 필요성, 제한 범위와 보완조치를 결정권자에게 제시합니다. 승인 여부·사유·조건을 기록하고 중요한 위험을 실무자가 임의 수용하지 않도록 합니다.

조건부 승인이 필요하면 제한된 사용자·기능·네트워크 범위와 추가 감시 조건을 명시합니다. 위험 수용의 유효기간과 재검토 시점을 정하여 임시 복구가 검증 없이 정상 운영으로 굳어지지 않도록 합니다.

5. 승인 조건의 복구 조직 인계와 이상 발생 시 재평가

승인된 범위, 진행 중인 조사와 감시 조건을 복구 담당자에게 인계합니다. 복구 중 재침해 징후가 나타나면 중단·재격리 기준에 따라 재평가하며, 복구 개시 승인을 복구 완료 승인과 구분합니다.

인계 시 승인 범위, 유지할 차단과 중단 조건을 복구 작업 목록에 반영합니다. 복구 중 새로운 침해 근거가 발견되면 전환 결정을 다시 검토하고 격리·조사 담당자에게 즉시 연결합니다.

Evidence

  • 복구 개시 기준·확인표: 전환 조건과 확인 책임을 사전에 정한 자료입니다.
  • 격리·근절·백업 검증 결과: 해당 사고가 복구를 시작할 준비가 되었는지 판단하는 근거입니다.
  • 잔여 위험 검토·승인 기록: 미충족 조건과 조건부 복구 결정의 책임을 확인할 수 있습니다.
  • 복구 인계·재평가 기록: 승인 조건이 실제 복구 업무에 전달되었음을 입증합니다.

IEM-C-18

Control Name

사고 확산 차단과 추가 피해 최소화를 위한 격리 및 확산 방지

Security Domain

Information Security Event Management

Control Class

Common

Control Objective

사고 관련 자산·계정·통신을 격리·통제하여 추가 확산과 피해를 줄입니다. 침해된 자산·계정·통신의 활동을 제한하고 연결된 시스템으로의 이동과 추가 반출을 차단합니다. 격리의 업무 영향과 증거 소실 위험을 관리하면서도 실제 차단 효과를 확인하여 피해가 진행되는 시간을 줄입니다.

Control Statement

사고가 진행되는 동안 공격자가 다른 자산으로 이동하거나 정보를 추가로 반출할 수 있습니다. 조직은 업무 영향과 증거 보존을 고려하면서 영향받은 자산·계정·통신을 제한하여 사고의 확산과 추가 피해를 줄여야 합니다.

단말기 하나를 차단해도 공격자가 다른 계정이나 외부 연결을 계속 사용할 수 있으므로 격리 범위는 사고 분석 결과에 따라 조정되어야 합니다. 이 Control은 긴급 제한, 효과 검증과 해제 승인을 연결하여 불필요한 장기 중단과 근거 없는 조기 해제를 모두 방지하도록 합니다.

적용 조건

적용 시점

침해 또는 확산이 의심되어 긴급 제한이 필요할 때, 격리 범위를 조정하거나 해제하려 할 때 적용합니다.

적용 대상

사고 관련 단말기·서버·네트워크, 클라우드 자원, 계정·인증정보와 외부 연결에 적용합니다. 개인정보 관련 법령·고시의 의무는 해당 개인정보 처리와 법정 적용 요건에 따라 적용합니다. 정보통신망법상 침해사고 원인 분석과 대응·복구·재발방지 조치 의무는 정보통신서비스 제공자 등 정보통신망을 운영하는 자에게 침해사고가 발생한 경우 적용합니다.

관련 법령

  • 「개인정보 보호법」 제29조 — 개인정보의 유출등을 방지하기 위한 기술적·관리적·물리적 안전조치 의무.
  • 「개인정보의 안전성 확보조치 기준」 제6조 — 개인정보처리시스템의 비인가 접근 제한과 개인정보 유출 시도 탐지·대응 등 접근통제 의무.
  • 「정보통신망 이용촉진 및 정보보호 등에 관한 법률」 제48조의4 — 정보통신망 운영자의 침해사고 원인 분석과 피해 확산 방지를 위한 사고대응·복구·재발방지 조치 의무.

Implementation Guide

1. 자산·계정·통신별 격리 수단과 긴급 조치 권한 마련

단말기 네트워크 분리, 계정 사용 제한과 외부 통신 차단 등 유형별 수단을 정합니다. 긴급 선조치가 허용되는 조건, 사후 보고와 승인권자를 명시하고 조치별 업무 영향을 확인합니다.

중요 서버를 분리할 때 함께 중단되는 업무와 관리 접속의 유지 여부를 사전에 확인합니다. 자동 격리와 수동 격리의 적용 조건, 실패 시 대체 방법과 조치 취소 방법을 절차에 포함합니다.

2. 침해 범위와 증거 소실 위험을 고려한 격리 대상 결정

현재 침해 흔적과 연결 관계를 토대로 격리 대상을 정합니다. 조치 전 확보할 자료와 즉시 차단하지 않을 때의 피해를 비교하여 우선순위를 정하고 판단 사유를 남깁니다.

확인된 공격 계정과 연결된 자산을 검토하고 제한이 필요한 최소 범위를 정합니다. 대량 반출처럼 즉시 차단해야 하는 상황에서는 증거 수집보다 차단을 우선한 판단 근거와 이후 확보할 대체 자료를 기록합니다.

3. 승인된 격리 적용과 업무·접속 차단 효과 확인

승인된 대상에 제한을 적용하고 실제 통신·접속이 차단되었는지 확인합니다. 시스템 전원 종료 등 증거 소실 가능성이 있는 조치는 필요성을 검토하고 불필요한 데이터 삭제를 피합니다.

설정 변경 성공 메시지만 확인하지 않고 실제 접속과 외부 통신이 제한되는지 검증합니다. 격리 후에도 필요한 보안 관리 경로가 유지되는지 확인하고 예상하지 못한 업무 영향은 지휘 책임자에게 보고합니다.

4. 대체 계정과 우회 경로의 활동 확인 및 격리 범위 조정

대체 계정, 다른 통신 경로와 연결된 외부 시스템에서 활동이 계속되는지 살핍니다. 추가 흔적이 발견되면 범위를 확대하고 관련 업무 담당자에게 영향과 예상 조치 시간을 알립니다.

공유 인증정보와 다른 네트워크 인터페이스를 통한 접근이 남아 있는지 확인합니다. 새로 발견된 관련 자산은 격리 대상 목록과 상황 보고에 반영하고 여러 팀의 차단 정책이 서로 충돌하지 않도록 조정합니다.

5. 격리 유지 조건의 정기 검토와 승인된 해제 수행

제한을 주기적으로 검토하고 악성 요소 제거와 복구 개시 기준을 확인한 후 해제를 승인합니다. 격리는 확산을 막는 조치이므로 공격 원인 제거가 완료되었는지도 별도로 검증합니다.

해제 전 근절·패치·인증정보 교체 등 필요한 후속 조치의 완료 근거를 확인합니다. 단계적으로 제한을 완화하면서 재침해 징후를 관찰하고 이상이 다시 나타나면 즉시 재격리할 수 있도록 준비합니다.

Evidence

  • 격리 절차·긴급 권한표: 상황별 수단과 조치 권한을 확인할 수 있습니다.
  • 격리 범위·영향 판단 기록: 차단 대상과 증거 보존 우선순위를 정한 근거입니다.
  • 차단 설정·효과 확인 기록: 격리가 실제로 적용되고 확산이 제한되었음을 보여줍니다.
  • 유지·확대·해제 승인 기록: 격리 상태의 변경과 후속 근절·복구 연계를 추적할 수 있습니다.
