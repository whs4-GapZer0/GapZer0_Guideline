Information Security Event Management Security Domain의 Enhancement Control을 제공합니다.

GapZer0 프레임워크 v0.1을 기준으로 작성하였습니다. CSF 항목에는 [NIST CSF 2.0](https://nvlpubs.nist.gov/nistpubs/CSWP/NIST.CSWP.29.pdf)의 해당 Outcome을 요약하였습니다. 관련 법령은 2026년 9월 28일 시행 기준으로 확인하였으며, 개정 시 적용 요건과 이행 절차를 함께 검토합니다.

## GZ-IEM-019

### Control Name

이벤트 분석 접근방식

### Security Domain

Information Security Event Management

### Control Class

Enhancement

### Control Objective

잠재적 이상 이벤트의 관련 활동과 진행 과정을 분석하여 보안상 의미를 파악합니다.

### Control Statement

탐지된 이벤트의 의미를 이해하려면 단순한 경보 확인을 넘어 관련 활동의 전후 관계를 분석해야 합니다. 조직은 관찰 사실과 가설을 구분하여 분석하고, 추가 조사·사고 선언·종결 여부를 판단할 수 있는 근거를 마련해야 합니다.

### 적용 조건

#### 적용 시점

잠재적으로 유해한 이벤트가 탐지되거나 신고되었을 때, 연관 활동과 추가 근거가 확인되었을 때 적용합니다.

#### 적용 대상

분석 대상으로 선정된 경보·의심행위와 그 전후의 사용자·시스템·네트워크 활동에 적용합니다. 개인정보 관련 법령·고시의 의무는 해당 개인정보 처리와 법정 적용 요건에 따라 적용합니다.

#### 관련 법령

- [「개인정보 보호법」 제29조](https://www.law.go.kr/%EB%B2%95%EB%A0%B9/%EA%B0%9C%EC%9D%B8%EC%A0%95%EB%B3%B4%EB%B3%B4%ED%98%B8%EB%B2%95/%EC%A0%9C29%EC%A1%B0) — 개인정보의 유출등을 방지하기 위한 기술적·관리적·물리적 안전조치 의무.
- [「개인정보의 안전성 확보조치 기준」 제8조](https://www.law.go.kr/%ED%96%89%EC%A0%95%EA%B7%9C%EC%B9%99/%EA%B0%9C%EC%9D%B8%EC%A0%95%EB%B3%B4%EC%9D%98%EC%95%88%EC%A0%84%EC%84%B1%ED%99%95%EB%B3%B4%EC%A1%B0%EC%B9%98%EA%B8%B0%EC%A4%80/%EC%A0%9C8%EC%A1%B0) — 개인정보처리시스템 접속기록의 보관·점검과 안전한 보관을 위한 조치 의무.

### Control Owner

보안관제 및 사고대응 책임자

### Stakeholders

IT 운영·개발부서, 업무 담당자, 디지털 증거 분석 담당자, 개인정보보호 담당자, 외부 관제기관

### 매핑된 ISMS-P 항목

- 2.11.3 이상행위 분석 및 모니터링
- 2.9.5 로그 및 접속기록 점검
- 2.11.5 사고 대응 및 복구

### 매핑된 CSF 항목

- DE.AE-02 — 잠재적 이상 이벤트를 분석하여 관련 활동을 이해합니다.

### ISMS-P Limitation

ISMS-P 2.11.3, 2.9.5와 2.11.5는 이상행위 모니터링, 로그 점검 및 사고 분석을 요구합니다. 다만, 잠재적 이벤트 단계에서 연관 활동을 재구성하고 가설·근거·불확실성을 구분하는 분석 접근방식은 상대적으로 구체적이지 않습니다.

### CSF Coverage

DE.AE-02를 기준으로 잠재적 이벤트의 관련 활동을 이해하는 분석 절차를 보완합니다. 확인 질문, 활동의 전후 관계, 가설 검증과 판단 근거를 남겨 분석 결과가 사고 선언과 대응 판단에 활용되도록 합니다.

### Implementation Guide

#### 1. 분석 질문과 확인 자료 선정

이벤트가 어떤 활동을 나타내는지, 누가 어떤 자산에 접근했는지 등 질문을 정합니다. 필요한 로그·자산 정보·업무 변경 내역과 확인 담당자를 지정합니다.

#### 2. 연관 활동 재구성

이벤트 전후의 로그인, 실행, 통신과 데이터 접근을 시간순으로 연결합니다. 상관 분석 결과를 활용하되 원본과 대조하여 단순한 시간적 근접성을 실제 연관성으로 오인하지 않도록 합니다.

#### 3. 정상·악성 가설 검증

승인된 작업, 설정 오류와 공격 가능성을 각각 검토합니다. 관찰 사실·추정·자료 공백을 구분하고 자동 분석으로 확인하기 어려운 부분은 담당자 확인과 수동 분석으로 보완합니다.

#### 4. 분석 결과와 판단 근거 전달

관련 활동, 의심 근거와 필요한 추가 조치를 정리하여 사고 판단 담당자에게 전달합니다. 종결하는 경우에도 정상으로 판단한 이유를 남기고 불확실성이 크면 추가 분석이나 보호조치를 요청합니다.

#### 5. 분석 절차의 재사용과 개선

반복되는 이벤트의 확인 항목과 유효했던 분석 방법을 유형별 절차에 반영합니다. 잘못된 판단이나 분석 지연 사례를 검토하여 자료 수집과 담당자 교육을 개선합니다.

### Evidence

- **이벤트 분석 양식·절차** — 질문, 확인 자료와 판단 단계를 일관되게 운영하는 기준입니다.
- **연관 활동 분석표** — 이벤트 전후의 흐름과 근거 로그를 연결한 자료입니다.
- **가설 검증·판단 기록** — 정상·악성 여부에 대한 사실과 추정을 구분한 증적입니다.
- **추가 조사·종결·절차 개선 이력** — 분석 결과가 후속 판단과 분석 역량 개선으로 이어졌음을 보여줍니다.

## GZ-IEM-020

### Control Name

사고 선언 기준

### Security Domain

Information Security Event Management

### Control Class

Enhancement

### Control Objective

사전에 정한 기준을 충족하는 이벤트를 공식 사고로 선언하여 대응을 개시합니다.

### Control Statement

이상 이벤트와 공식적으로 대응할 사고의 경계가 불명확하면 담당자에 따라 대응 개시가 달라집니다. 조직은 사고 선언 기준과 결정 권한을 정하여 기준을 충족하는 이벤트가 일관되게 사고로 선언되도록 해야 합니다.

### 적용 조건

#### 적용 시점

사고 선언 기준을 수립·개정할 때, 분석된 이벤트의 사고 해당 여부를 결정하거나 결정을 재검토할 때 적용합니다.

#### 적용 대상

분석 결과 사고 가능성이 확인된 이벤트와 사고 선언·보류·기각을 결정하는 담당자·책임자에 적용합니다. 개인정보 관련 법령·고시의 의무는 해당 개인정보 처리와 법정 적용 요건에 따라 적용합니다.

#### 관련 법령

- [「개인정보 보호법」 제29조](https://www.law.go.kr/%EB%B2%95%EB%A0%B9/%EA%B0%9C%EC%9D%B8%EC%A0%95%EB%B3%B4%EB%B3%B4%ED%98%B8%EB%B2%95/%EC%A0%9C29%EC%A1%B0) — 개인정보의 유출등을 방지하기 위한 기술적·관리적·물리적 안전조치 의무.

### Control Owner

사고대응 책임자

### Stakeholders

정보보호 최고책임자(CISO), 보안관제 담당자, 개인정보보호·법무 담당자, 업무·서비스 책임자

### 매핑된 ISMS-P 항목

- 2.11.1 사고 예방 및 대응체계 구축
- 2.11.5 사고 대응 및 복구

### 매핑된 CSF 항목

- DE.AE-08 — 이상 이벤트가 정의된 기준을 충족하면 사고로 선언합니다.

### ISMS-P Limitation

ISMS-P 2.11.1과 2.11.5는 대응체계와 사고 대응·복구를 요구합니다. 이벤트가 어떤 조건에서 사고로 전환되는지와 선언권자·보류·기각 기록을 연결하는 구체적인 결정 절차는 상대적으로 덜 명시되어 있습니다.

### CSF Coverage

DE.AE-08에 따라 사고 기준과 판단 권한을 정하고, 기준을 충족한 이벤트를 사고로 선언하는 절차를 보완합니다. 결정 근거와 시각을 남겨 대응 계획 가동까지의 책임과 흐름을 명확히 합니다.

### Implementation Guide

#### 1. 선언 기준과 대표 사례 정의

비인가 접근 확인, 중요 데이터 변조와 업무 중단 등 사고로 판단할 조건을 정합니다. 확인 근거의 수준과 불확실한 상황의 긴급 판단 기준을 명시하고 단일 경보의 발생과 사고 확정을 구분합니다.

#### 2. 결정 권한과 기한 마련

유형·중요도별 선언권자, 대체 결정자와 판단 시간을 정합니다. 신속한 보호조치와 법정 통지·신고 판단이 내부 선언 승인 때문에 지연되지 않도록 별도 경로를 마련합니다.

#### 3. 이벤트 분석 결과 대조

분석 결과를 선언 기준에 대입하고 영향·근거·미확인 사항을 검토합니다. 판단 자료가 부족하면 필요한 추가 자료와 재검토 시점을 정하되 위험이 큰 경우 임시 보호조치를 검토합니다.

#### 4. 결정 기록과 대응 계획 연결

선언·보류·기각 결과, 사유, 결정자와 시각을 기록합니다. 사고로 선언되면 사건 번호·등급·지휘 책임자를 전달하여 사고대응 계획을 가동하고 보류 건도 담당자가 계속 추적합니다.

#### 5. 사례 검토와 기준 보완

실제 사고·오탐과 훈련 결과를 통해 선언 지연이나 과도한 선언 여부를 검토합니다. 변경된 기준을 승인·배포하고 관련 담당자에게 사례 중심으로 교육합니다.

### Evidence

- **사고 선언 기준·권한표** — 사고 판단 조건과 결정 책임을 확인할 수 있습니다.
- **기준 대조·추가 확인 기록** — 선언 여부를 근거에 따라 판단한 자료입니다.
- **선언·보류·기각 결정 이력** — 사고 판단의 일관성과 보류 건 추적 여부를 보여줍니다.
- **대응 계획 가동·기준 개선 기록** — 선언이 실제 대응과 판단 기준의 개선으로 이어졌음을 입증합니다.

## GZ-IEM-021

### Control Name

사고 보고 초기 분류 및 대응 필요성 검증

### Security Domain

Information Security Event Management

### Control Class

Enhancement

### Control Objective

접수된 사고 보고를 초기 분류하고 사실관계와 대응 필요성을 검증합니다.

### Control Statement

접수된 사고 보고에는 중복 신고, 정상 작업과 실제 침해가 섞여 있을 수 있습니다. 조직은 보고 내용을 신속하게 초기 분류하고 사실관계를 검증하여, 대응이 필요한 건을 놓치지 않고 적절한 담당자에게 배정해야 합니다.

### 적용 조건

#### 적용 시점

내·외부 사고 보고나 자동 경보가 접수되었을 때, 추가 신고로 기존 접수 건을 다시 판단할 때 적용합니다.

#### 적용 대상

임직원·고객·외부기관의 신고와 보안도구의 경보를 접수하여 조사 대상으로 배정하는 초기 처리 과정에 적용합니다. 개인정보 관련 법령·고시의 의무는 해당 개인정보 처리와 법정 적용 요건에 따라 적용합니다.

#### 관련 법령

- [「개인정보 보호법」 제29조](https://www.law.go.kr/%EB%B2%95%EB%A0%B9/%EA%B0%9C%EC%9D%B8%EC%A0%95%EB%B3%B4%EB%B3%B4%ED%98%B8%EB%B2%95/%EC%A0%9C29%EC%A1%B0) — 개인정보의 유출등을 방지하기 위한 기술적·관리적·물리적 안전조치 의무.

### Control Owner

보안관제 및 사고대응 책임자

### Stakeholders

신고 접수·고객지원 담당자, IT 운영부서, 관련 업무부서, 개인정보보호 담당자, 외부 관제기관

### 매핑된 ISMS-P 항목

- 2.11.1 사고 예방 및 대응체계 구축
- 2.11.5 사고 대응 및 복구

### 매핑된 CSF 항목

- RS.MA-02 — 접수된 사고 보고를 초기 분류하고 타당성을 검증합니다.

### ISMS-P Limitation

ISMS-P 2.11.1과 2.11.5는 신고·대응체계를 포함하지만, 접수된 보고의 중복 확인, 사실 검증, 초기 분류와 인수 확인을 하나의 초기 처리 과정으로 구체화하는 데에는 보완의 여지가 있습니다.

### CSF Coverage

RS.MA-02에 따라 접수 보고를 초기 분류하고 대응 필요성을 검증합니다. 접수·중복 연결·검증·배정·종결 근거를 남겨 단순 알림 전달 이후의 처리 누락을 줄입니다.

### Implementation Guide

#### 1. 접수 정보와 추적 번호 확보

신고 시각, 신고자 연락 방법, 증상과 관련 자산을 기록하고 접수 번호를 부여합니다. 필요한 추가 정보는 신고자에게 요청하되 악성 의심 파일을 일반 업무 환경에서 열지 않도록 안내합니다.

#### 2. 중복·관련 사건 확인

같은 자산·시간·현상을 다루는 기존 신고와 경보를 확인합니다. 중복 건은 기존 사건에 연결하되 새롭게 들어온 근거와 신고자에게 안내할 내용은 남깁니다.

#### 3. 사실관계와 긴급성 검증

실제 자산 존재 여부, 승인된 작업과 관련 로그를 확인하여 신고 내용의 신뢰도를 판단합니다. 피해 확대 가능성이 높으면 검증을 진행하면서도 긴급 보호조치와 상위 보고를 병행합니다.

#### 4. 초기 분류와 담당자 배정

조사 필요, 추가 정보 대기와 정상·오접수 등 처리 상태를 정합니다. 대응 필요 건은 근거·초기 영향·미확인 사항과 함께 분석 담당자에게 넘기고 인수 여부와 처리 기한을 확인합니다.

#### 5. 대기·종결 건 추적과 개선

정보 대기 건은 재확인 기한을 두고 확인 불가만으로 조용히 종결하지 않습니다. 종결 사유를 기록하고 이후 실제 사고로 확인된 사례를 검토하여 검증 질문과 초기 분류 기준을 개선합니다.

### Evidence

- **접수 대장·신고 원문** — 각 보고의 접수 시점과 최초 내용을 확인할 수 있습니다.
- **중복 연결·사실 확인 기록** — 관련 사건과 정상 작업 여부를 검증한 자료입니다.
- **초기 분류·배정·인수 기록** — 보고가 적절한 조사 담당자에게 연결되었음을 보여줍니다.
- **대기·종결 검토 내역** — 미처리 건과 잘못 종결된 보고를 관리한 증적입니다.

## GZ-IEM-022

### Control Name

사고 근절 범위

### Security Domain

Information Security Event Management

### Control Class

Enhancement

### Control Objective

악성 요소와 침해 원인, 공격자의 남은 접근 수단을 제거하고 그 결과를 검증합니다.

### Control Statement

감염 자산의 연결만 차단하면 악성코드나 탈취된 계정이 남아 다시 공격에 이용될 수 있습니다. 조직은 사고와 관련된 악성 요소, 재침입 수단과 악용된 취약점을 제거하고 그 효과를 검증하여 재침해 위험을 줄여야 합니다.

### 적용 조건

#### 적용 시점

격리 후 원인과 침해 범위가 확인되었을 때, 악성 요소를 제거하거나 복구를 준비할 때 및 재침입 흔적 발견 시 적용합니다.

#### 적용 대상

사고 관련 악성 파일·프로세스, 자동 실행 등 지속 접근 수단, 비인가 계정·인증정보와 악용된 취약점·설정에 적용합니다. 개인정보 관련 법령·고시의 의무는 해당 개인정보 처리와 법정 적용 요건에 따라 적용합니다.

#### 관련 법령

- [「개인정보 보호법」 제29조](https://www.law.go.kr/%EB%B2%95%EB%A0%B9/%EA%B0%9C%EC%9D%B8%EC%A0%95%EB%B3%B4%EB%B3%B4%ED%98%B8%EB%B2%95/%EC%A0%9C29%EC%A1%B0) — 개인정보의 유출등을 방지하기 위한 기술적·관리적·물리적 안전조치 의무.
- [「개인정보의 안전성 확보조치 기준」 제9조](https://www.law.go.kr/%ED%96%89%EC%A0%95%EA%B7%9C%EC%B9%99/%EA%B0%9C%EC%9D%B8%EC%A0%95%EB%B3%B4%EC%9D%98%EC%95%88%EC%A0%84%EC%84%B1%ED%99%95%EB%B3%B4%EC%A1%B0%EC%B9%98%EA%B8%B0%EC%A4%80/%EC%A0%9C9%EC%A1%B0) — 악성프로그램 방지·치료를 위한 보안 프로그램 운영·갱신과 발견된 악성프로그램 대응 의무.

### Control Owner

사고대응 책임자

### Stakeholders

IT 운영·개발부서, 계정·취약점 관리 담당자, 보안관제·디지털 증거 분석 담당자, 서비스 제공자

### 매핑된 ISMS-P 항목

- 2.10.9 악성코드 통제
- 2.10.8 패치관리
- 2.11.5 사고 대응 및 복구

### 매핑된 CSF 항목

- RS.MI-02 — 사고의 악성 요소와 원인을 제거합니다.

### ISMS-P Limitation

ISMS-P 2.10.9, 2.10.8과 2.11.5는 악성코드 대응, 패치와 재발방지를 요구합니다. 다만, 지속 접근 수단·탈취 인증정보·악용 취약점까지 사고 관련 범위 전체에서 제거하고 검증하는 근절 단계는 상대적으로 덜 구체적입니다.

### CSF Coverage

RS.MI-02에 따라 악성 요소와 재침입 수단의 제거 범위를 명확히 합니다. 격리나 서비스 복구만으로 대응을 완료하지 않고 제거 결과를 검증하여 안전한 복구 판단에 연결합니다.

### Implementation Guide

#### 1. 제거 대상과 순서 확정

조사 결과를 바탕으로 악성코드, 공격자가 남긴 자동 실행·원격 접속 수단과 탈취된 계정을 목록화합니다. 연관 자산 전체의 처리 범위와 작업 순서를 정하고 제거 전에 필요한 증거를 보존합니다.

#### 2. 악성 요소 제거와 시스템 정비

악성 파일·프로세스·예약 작업과 비인가 계정을 제거합니다. 시스템을 신뢰할 수 없으면 검증된 이미지로 재구축하고 정상 자료를 복원하기 전 감염 여부를 확인합니다.

#### 3. 재침입 경로 차단

악용된 취약점 패치, 잘못된 설정 수정과 노출된 비밀번호·키·토큰의 폐기·교체를 수행합니다. 즉시 패치할 수 없는 경우 접근 제한 등 보완조치, 승인자와 해소 기한을 정합니다.

#### 4. 범위 전체에서 제거 효과 검증

동일한 침해 흔적과 지속 접근 수단이 다른 자산에 남아 있는지 재검색합니다. 패치·설정·계정 조치 결과를 확인하고 재부팅이나 재연결 후 악성 활동이 다시 발생하는지도 검증합니다.

#### 5. 미완료 위험 인계와 재발방지 반영

미완료 항목과 잔여 위험을 복구 개시 판단에 전달합니다. 제거 완료의 근거를 기록하고 같은 경로의 공격을 탐지·차단할 수 있도록 운영 기준과 탐지 규칙을 개선합니다.

### Evidence

- **근절 대상·작업 계획** — 제거할 악성 요소와 재침입 경로의 범위를 확인하는 자료입니다.
- **제거·재구축·인증정보 교체 기록** — 실제 수행한 근절 조치와 담당자를 추적할 수 있습니다.
- **패치·보완조치·예외 승인** — 취약점 해소 여부와 미완료 위험의 관리 상태를 보여줍니다.
- **근절 검증·복구 인계 자료** — 공격 수단 제거를 확인하고 잔여 위험을 복구 판단에 전달한 증적입니다.
