Supplier Relationships Security의 Enhancement Control은 기존 ISMS-P 요구만으로 충분히 명시되지 않는 CSF 2.0 공급망 위험관리 결과를 보완합니다.

---

## GZ-SUP-009

### Control Name

공급망 위험평가·개선 프로세스의 ERM 통합

### Security Domain
Supplier Relationships Security

### Control Class
Enhancement

### Control Objective
공급망 사이버보안 위험의 식별·평가·처리·개선 결과를 전사 위험관리(ERM)와 연결하여 조직 전체 위험 의사결정에 반영합니다.

### Control Statement
공급망 위험을 구매·보안 부서 내부에서만 관리하면 전사 우선순위와 자원배분에 반영되지 않을 수 있습니다. 조직은 공급망 위험평가와 개선결과를 ERM 보고·승인·추적 체계에 통합해야 합니다.

### 적용 조건

#### 적용 시점
공급망 위험평가, 전사 위험평가·경영검토, 중요 공급자 변경 시 적용합니다.

#### 적용 대상
중요 공급자·외부 서비스 및 이와 연계된 전사 위험관리 체계에 적용합니다.


### Control Owner
구매·계약/공급자 위험관리 책임자

### Stakeholders
CISO, CPO, 법무, 업무부서, IT 운영, 재무, 감사, 공급자 담당자

### 매핑된 ISMS-P 항목
- 2.3.1 외부자 현황 관리
- 1.2.3 위험 평가

### 매핑된 CSF 항목
- GV.SC-03

### Implementation Guide

#### 1. 공통 위험기준 연결
공급망 위험등급을 ERM 영향·가능성 기준과 연결합니다.

#### 2. 위험등록부 통합
중요 공급망 위험과 책임자·대응기한을 전사 위험등록부에 반영합니다.

#### 3. 경영 보고
중요 위험·추세·미해결 개선사항을 경영진 위험검토에 포함합니다.

#### 4. 개선 추적
전사 우선순위와 자원배분 결과를 공급자 개선계획에 반영하고 효과를 재평가합니다.

### Evidence
1. **ERM-공급망 위험 기준:** 평가기준 연결을 확인합니다.
2. **전사 위험등록부:** 공급망 위험의 통합을 확인합니다.
3. **경영진 보고·결정:** 전사 의사결정 반영을 확인합니다.
4. **개선·재평가 기록:** 위험 감소 효과를 확인합니다.

### ISMS-P Limitation
ISMS-P는 외부자 현황관리와 조직 위험평가를 요구하지만 공급망 위험평가·개선 프로세스를 ERM에 명시적으로 통합하는 결과는 상대적으로 구체적이지 않습니다.

### CSF Coverage
GV.SC-03의 공급망 사이버보안 위험관리 통합 결과를 보완합니다.

## GZ-SUP-010

### Control Name

공급자 위험도 우선순위화

### Security Domain
Supplier Relationships Security

### Control Class
Enhancement

### Control Objective
공급자의 중요도·접근범위·데이터·의존도와 위험을 기준으로 공급자를 우선순위화하여 관리강도를 차등 적용합니다.

### Control Statement
모든 공급자를 동일 수준으로 관리하면 핵심 공급자에 필요한 자원을 집중하기 어렵습니다. 조직은 일관된 기준으로 공급자 중요도와 위험등급을 정하고 등급별 실사·계약·모니터링 수준을 차등화해야 합니다.

### 적용 조건

#### 적용 시점
공급자 신규등록·평가·갱신 및 중요 변경 시 적용합니다.

#### 적용 대상
조직과 관계를 맺는 공급자·제3자 전체에 적용합니다.


### Control Owner
구매·계약/공급자 위험관리 책임자

### Stakeholders
CISO, CPO, 법무, 업무부서, IT 운영, 재무, 감사, 공급자 담당자

### 매핑된 ISMS-P 항목
- 2.3.1 외부자 현황 관리
- 2.3.2 외부자 계약 시 보안

### 매핑된 CSF 항목
- GV.SC-04

### Implementation Guide

#### 1. 분류 기준 정의
업무 중요도, 정보 민감도, 권한, 대체가능성, 사고영향 기준을 정합니다.

#### 2. 공급자 평가·등급화
객관적 근거로 공급자별 위험등급과 중요도를 산정합니다.

#### 3. 차등 관리
등급별 실사 깊이, 승인수준, 계약요건, 모니터링 주기를 정합니다.

#### 4. 재분류
서비스·위험·사고 변화 시 등급을 재검토합니다.

### Evidence
1. **공급자 분류기준:** 등급 산정 원칙을 확인합니다.
2. **공급자 등급대장:** 실제 평가결과를 확인합니다.
3. **등급별 관리기준:** 차등통제 적용을 확인합니다.
4. **재평가 기록:** 변화 반영을 확인합니다.

### ISMS-P Limitation
ISMS-P의 외부자 현황·계약 관리는 존재하지만 공급자 사이버보안 위험을 체계적으로 우선순위화하는 결과는 명시성이 제한적입니다.

### CSF Coverage
GV.SC-04의 공급자 중요도·위험 기반 우선순위화 결과를 보완합니다.

## GZ-SUP-011

### Control Name

공급자 관계 전 기간 위험관리

### Security Domain
Supplier Relationships Security

### Control Class
Enhancement

### Control Objective
공급자 선정부터 계약·운영·변경·갱신·종료까지 전 수명주기에서 위험을 지속적으로 식별·평가·처리합니다.

### Control Statement
계약 시점의 일회성 보안검토만으로는 운영 중 변화와 신규 위험을 관리하기 어렵습니다. 조직은 공급자 관계의 각 단계에 위험검토와 승인·개선·종료 절차를 연결해야 합니다.

### 적용 조건

#### 적용 시점
공급자 관계의 선정·계약·운영·변경·갱신·종료 전 단계에 적용합니다.

#### 적용 대상
중요 공급자·외부 서비스와 관련 내부 담당부서에 적용합니다.


### Control Owner
구매·계약/공급자 위험관리 책임자

### Stakeholders
CISO, CPO, 법무, 업무부서, IT 운영, 재무, 감사, 공급자 담당자

### 매핑된 ISMS-P 항목
- 2.3.3 외부자 보안 이행 관리

### 매핑된 CSF 항목
- GV.SC-07

### Implementation Guide

#### 1. 수명주기 단계 정의
선정·계약·온보딩·운영·변경·갱신·종료별 보안활동을 정합니다.

#### 2. 단계별 게이트 운영
중요 단계에서 위험평가·승인·보완조치 완료 여부를 확인합니다.

#### 3. 운영 중 변화관리
사고, 소유구조, 서비스·하위공급자 변화 시 재평가합니다.

#### 4. 종료·피드백
종료조치와 잔여위험을 확인하고 결과를 다음 공급자 관리에 반영합니다.

### Evidence
1. **공급자 수명주기 절차:** 단계별 통제를 확인합니다.
2. **평가·승인 기록:** 각 단계의 위험 의사결정을 확인합니다.
3. **변경·재평가 기록:** 운영 중 위험관리를 확인합니다.
4. **종료·교훈 기록:** 잔여위험과 개선을 확인합니다.

### ISMS-P Limitation
ISMS-P 2.3.3은 외부자 보안 이행관리를 요구하지만 공급자 관계 전 기간을 하나의 연속된 위험관리 수명주기로 관리하는 결과는 명시성이 제한적입니다.

### CSF Coverage
GV.SC-07의 공급자·제3자 관계 전 수명주기 위험관리 결과를 보완합니다.

## GZ-SUP-012

### Control Name

공급망 보안 ERM 통합·성과관리

### Security Domain
Supplier Relationships Security

### Control Class
Enhancement

### Control Objective
공급망 보안활동의 성과와 위험변화를 측정하고 그 결과를 ERM 및 경영 의사결정에 반영하여 공급망 위험관리의 효과성을 지속적으로 개선합니다.

### Control Statement
공급자 점검을 수행하더라도 성과와 잔여위험을 측정하지 않으면 관리체계의 효과를 판단하기 어렵습니다. 조직은 공급망 보안 지표·점검·사고·개선결과를 분석하여 ERM과 경영검토에 반영해야 합니다.

### 적용 조건

#### 적용 시점
정기 공급자 성과평가·ERM 검토·경영검토 및 주요 사고 후 적용합니다.

#### 적용 대상
공급망 위험관리 프로그램과 중요 공급자에 적용합니다.


### Control Owner
구매·계약/공급자 위험관리 책임자

### Stakeholders
CISO, CPO, 법무, 업무부서, IT 운영, 재무, 감사, 공급자 담당자

### 매핑된 ISMS-P 항목
- 2.3.3 외부자 보안 이행 관리
- 2.3.4 외부자 계약 변경 및 만료 시 보안
- 2.3.1 외부자 현황 관리

### 매핑된 CSF 항목
- GV.SC-09

### Implementation Guide

#### 1. 성과지표 정의
평가완료율, 개선기한 준수, 사고·반복미흡, 중요 공급자 위험추세 등을 정합니다.

#### 2. 자료 수집·검증
점검·감사·사고·계약종료·개선자료를 정기 수집합니다.

#### 3. 성과·잔여위험 분석
목표 대비 실적과 반복문제·고위험 공급자를 분석합니다.

#### 4. ERM·경영검토 반영
중요 결과를 전사 위험과 자원·전략 결정에 연결하고 개선을 추적합니다.

### Evidence
1. **공급망 KPI/KRI:** 측정기준을 확인합니다.
2. **성과·위험 분석자료:** 실제 효과 평가를 확인합니다.
3. **ERM·경영진 보고:** 전사 의사결정 연결을 확인합니다.
4. **개선계획·추적:** 지속적 개선을 확인합니다.

### ISMS-P Limitation
ISMS-P는 외부자 관리활동을 요구하지만 공급망 보안성과를 측정해 ERM에 통합하고 지속적으로 조정하는 결과는 상대적으로 구체적이지 않습니다.

### CSF Coverage
GV.SC-09의 공급망 보안 관행 모니터링 및 ERM 통합 결과를 보완합니다.

## GZ-SUP-013

### Control Name

Critical Suppliers 정의

### Security Domain
Supplier Relationships Security

### Control Class
Enhancement

### Control Objective
조직의 핵심 기능·정보·서비스에 중대한 영향을 줄 수 있는 Critical Supplier를 정의·식별하고 도입 전에 위험을 평가하여 강화된 관리수준을 적용합니다.

### Control Statement
핵심 공급자를 명확히 구분하지 않으면 제한된 관리자원이 저위험 공급자에 분산될 수 있습니다. 조직은 중요 공급자 기준을 정의하고 계약·도입 전 위험평가와 강화된 승인·모니터링을 수행해야 합니다.

### 적용 조건

#### 적용 시점
신규 공급자 도입·중요도 변경·정기 재평가 시 적용합니다.

#### 적용 대상
핵심업무 중단, 중요정보 접근, 높은 기술의존성 또는 대체곤란성을 가진 공급자 후보·기존 공급자에 적용합니다.


### Control Owner
구매·계약/공급자 위험관리 책임자

### Stakeholders
CISO, CPO, 법무, 업무부서, IT 운영, 재무, 감사, 공급자 담당자

### 매핑된 ISMS-P 항목
- 2.3.1 외부자 현황 관리
- 2.3.2 외부자 계약 시 보안

### 매핑된 CSF 항목
- ID.RA-10

### Implementation Guide

#### 1. Critical Supplier 기준 정의
업무중단 영향, 정보 민감도, 권한, 집중도, 대체가능성 등 기준을 정합니다.

#### 2. 후보 식별
공급자 목록에 기준을 적용하여 Critical Supplier를 지정합니다.

#### 3. 도입 전 위험평가
보안역량·취약성·사고이력·하위공급망·복구역량을 평가합니다.

#### 4. 강화 통제 적용
추가 계약요건, 승인, 모니터링, 사고·연속성 요구를 적용합니다.

#### 5. 정기 재평가
업무·서비스·위험 변화에 따라 지정과 관리수준을 갱신합니다.

### Evidence
1. **Critical Supplier 선정기준:** 중요도 판단 근거를 확인합니다.
2. **Critical Supplier 목록:** 실제 식별결과를 확인합니다.
3. **도입 전 위험평가:** 사전평가 수행을 확인합니다.
4. **강화 계약·모니터링 기록:** 차등관리 이행을 확인합니다.

### ISMS-P Limitation
ISMS-P는 외부자 현황과 계약보안을 요구하지만 Critical Supplier를 명시적으로 정의하고 도입 전 위험을 별도로 평가하는 결과는 제한적입니다.

### CSF Coverage
ID.RA-10의 중요 공급자 식별 및 관계 수립 전 평가 결과를 보완합니다.
