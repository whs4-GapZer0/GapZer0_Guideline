Asset Management Security Domain의 Common Control은 하드웨어·소프트웨어·서비스·데이터 등 조직 자산의 식별, 우선순위화 및 수명주기 관리를 위한 공통 요구사항을 제공합니다.

---

## GZ-AST-001

### Control Name

하드웨어 자산 인벤토리 유지

### Security Domain

Asset Management

### Control Class

Common

### Control Objective

관리체계 범위의 하드웨어를 빠짐없이 식별하고 소유자·위치·용도·중요도·상태를 최신으로 유지하여, 자산의 중요도와 위험에 맞는 보호·운영·대응이 가능하도록 합니다.

### Control Statement

목록에 없는 서버·단말·네트워크 및 보안장비는 패치, 접근통제, 모니터링과 폐기 절차에서 누락될 수 있습니다. 조직은 하드웨어 분류기준을 정하고 모든 관리 대상 하드웨어를 권위 있는 목록에 등록하며, 변경과 인사이동을 반영해 책임소재와 현황을 지속적으로 확인할 수 있어야 합니다.

### 적용 조건

관리체계 범위에서 조직이 소유·임차하거나 운영 책임을 갖는 서버, PC·모바일 단말, 네트워크·보안장비, 저장장치, 설비형 장비에 적용합니다. 공급자 소유 장비라도 조직이 직접 관리하거나 조직 서비스의 보안에 영향을 주는 경우에는 관리 경계와 책임을 명확히 기록합니다.

### Control Owner

정보자산 관리책임자 / IT 자산·운영 책임자

### Stakeholders

업무부서 자산소유자, 구매·계약, 재무, 정보보호, 인프라·클라우드 운영, 개인정보보호

### 매핑된 ISMS-P 항목

1.2.1, 2.1.3

### 매핑된 CSF 항목

ID.AM-01

### Implementation Guide

1. **하드웨어 분류와 등록 기준을 정한다.** - 서버, 단말, 네트워크·보안장비, 저장장치 등 조직 환경에 맞는 유형과 관리 범위를 정의하고, 자산명·식별번호·모델·용도·위치·소유자·관리자·보안등급·운영상태 등 필수 항목을 정한다.
2. **발견·도입 단계에서 자산을 등록한다.** - 구매·임차·배치·클라우드 운영 정보와 기술적 발견 결과를 대조하여 미등록 자산을 식별하고, 사용 전에 책임자와 관리자를 지정한다.
3. **변경을 자산목록에 반영한다.** - 이동, 소유자 변경, 수리, 반출입, 구성 변경, 휴면 및 폐기 상태가 발생하면 관련 업무 기록과 자산목록을 연결해 갱신하고 승인·변경 이력을 남긴다.
4. **목록의 정확성과 완전성을 검증한다.** - 실물·관리도구·네트워크 관측 결과를 자산목록과 대조하여 누락·중복·불일치·책임자 공백을 확인하고 조치한다.

### Evidence

- 하드웨어 자산목록: 자산별 식별정보, 위치, 용도, 책임자·관리자, 보안등급과 상태를 확인할 수 있는 자료.
- 도입·이동·반출입·수리·폐기 기록: 하드웨어 상태 변경이 승인되고 자산목록에 반영되었는지 확인할 수 있는 자료.
- 자산 발견·대사 결과: 실물조사, 관리도구 또는 네트워크 관측 결과와 자산목록의 차이 및 조치 내역을 확인할 수 있는 자료.
- 책임자 지정·변경 기록: 인사이동과 조직변경 시 책임소재를 갱신한 내역을 확인할 수 있는 자료.

## GZ-AST-002

### Control Name

소프트웨어·서비스·시스템 인벤토리 유지

### Security Domain

Asset Management

### Control Class

Common

### Control Objective

조직이 관리하는 소프트웨어·서비스·시스템을 식별하고 버전·소유자·용도·지원상태·의존관계를 최신으로 유지하여, 위험에 맞는 유지보수와 보호조치를 적용할 수 있도록 합니다.

### Control Statement

소프트웨어, 클라우드 서비스와 정보시스템의 현황이 분산되면 취약 버전, 미승인 서비스, 중복 계약과 지원 종료 대상을 파악하기 어렵습니다. 조직은 기술 및 업무 관점의 목록을 연결하고 변경사항을 반영하여, 무엇이 어디에서 누구의 책임으로 운영되는지 확인할 수 있어야 합니다.

### 적용 조건

관리체계 범위에서 설치·구독·개발·운영하는 운영체제, 상용·오픈소스 소프트웨어, 애플리케이션, 정보시스템, SaaS·PaaS·IaaS 및 공통 서비스에 적용합니다. 공급자 서비스는 GZ-AST-003의 외부 서비스 목록과 연결합니다.

### Control Owner

IT 서비스·애플리케이션 관리책임자

### Stakeholders

시스템·서비스 소유자, 개발·운영, 구매·계약, 정보보호, 클라우드 운영, 개인정보보호

### 매핑된 ISMS-P 항목

1.2.1, 2.1.3

### 매핑된 CSF 항목

ID.AM-02

### Implementation Guide

1. **소프트웨어·서비스·시스템의 등록 기준을 정한다.** - 제품·서비스명, 버전, 배포 위치, 용도, 소유자·관리자, 공급자, 라이선스, 지원 종료일, 중요도와 연결 자산 등 관리 항목을 정의한다.
2. **사용·도입 현황을 수집해 목록화한다.** - 구매·계약, 배포도구, 클라우드 계정, 시스템 구성과 개발 산출물을 대조하여 관리 대상과 미승인·중복 항목을 식별한다.
3. **변경·배포·계약 절차와 목록을 연계한다.** - 신규 도입, 버전 변경, 기능 추가, 이전, 계약 변경, 서비스 종료 시 해당 목록과 의존관계를 갱신하고 책임자를 확인한다.
4. **목록의 최신성과 지원상태를 검토한다.** - 실제 설치·사용 현황을 목록과 대조하고 미사용, 미승인, 지원 종료·임박, 소유자 미지정 항목을 식별하여 조치한다.

### Evidence

- 소프트웨어·서비스·시스템 목록: 버전, 배포 위치, 용도, 소유자·관리자, 공급자, 라이선스와 지원상태를 확인할 수 있는 자료.
- 구매·계약·배포·클라우드 현황: 목록의 완전성을 교차 검증할 수 있는 원천 자료.
- 변경·배포·종료 기록: 버전과 운영상태 변경이 목록에 반영되었는지 확인할 수 있는 자료.
- 정합성 검토 및 조치 기록: 미승인·중복·지원 종료·책임자 미지정 항목의 확인과 처리 결과를 보여 주는 자료.

## GZ-AST-003

### Control Name

공급자 제공 서비스 인벤토리 유지

### Security Domain

Asset Management

### Control Class

Common

### Control Objective

공급자가 제공하는 업무위탁·외부 시설·클라우드·애플리케이션 서비스를 식별하고, 서비스 내용·책임·데이터 접근·계약상태·위험을 최신으로 관리하여 외부 의존 위험을 통제합니다.

### Control Statement

외부 서비스가 계약·구매 부서별로 분산되면 공급자의 데이터 접근, 재위탁, 서비스 종료와 보안점검 현황이 누락될 수 있습니다. 조직은 외부 서비스 현황을 일관된 목록으로 관리하고 법적 요구사항과 보안위험을 파악하여, 서비스 전 과정에서 필요한 보호대책과 관리·감독을 적용할 수 있어야 합니다.

### 적용 조건

정보시스템 개발·운영·유지보수, 보안관제, 클라우드·IDC·SaaS 이용, 개인정보 처리업무 위탁 등 관리체계 범위의 업무위탁과 외부 시설·서비스 이용에 적용합니다.

### Control Owner

구매·계약/외부자 관리책임자 및 서비스 소유자

### Stakeholders

정보보호, 개인정보보호, 법무, IT·클라우드 운영, 업무위탁 부서, 재무, 공급자 담당자

### 매핑된 ISMS-P 항목

2.3.1, 3.3.2

### 매핑된 CSF 항목

ID.AM-04

### Implementation Guide

1. **공급자 서비스 등록 기준과 책임을 정한다.** - 서비스명, 공급자·수탁자, 제공 업무, 담당부서·소유자, 이용기간, 시스템·데이터 접근범위, 처리 개인정보, 재위탁, 계약·점검 상태와 중요도를 관리 항목으로 정한다.
2. **계약·구매·기술 현황을 대조해 목록화한다.** - 계약대장, 비용 지출, 클라우드 계정, 네트워크 연결과 시스템 구성을 대조하여 비공식·미등록 서비스를 식별하고 목록에 반영한다.
3. **서비스별 법적 요구와 위험을 연결한다.** - 개인정보 처리 위탁 여부, 중요정보 접근, 서비스 중단 영향과 공급자 의존도를 확인하여 계약 보안조항, 접근통제, 점검과 종료 조치를 정한다.
4. **변경과 종료를 현행화한다.** - 계약 갱신·변경, 공급자·재위탁 변경, 접근범위 확대, 서비스 이전·종료 시 목록과 관련 통제를 갱신하고 접근회수·데이터 반환 또는 파기를 확인한다.

### Evidence

- 공급자·외부 서비스 목록: 공급자, 서비스 범위, 소유자, 이용기간, 데이터·시스템 접근과 관리상태를 확인할 수 있는 자료.
- 계약서·SLA·개인정보 처리위탁 문서: 책임, 보안 요구, 재위탁, 사고통보와 종료 조건을 확인할 수 있는 자료.
- 외부 서비스 위험평가·점검 결과: 서비스별 위험과 보호대책, 관리·감독 결과를 확인할 수 있는 자료.
- 변경·종료 기록: 접근회수, 계정 폐쇄, 데이터 반환·파기와 목록 갱신을 확인할 수 있는 자료.

## GZ-AST-004

### Control Name

자산 우선순위화

### Security Domain

Asset Management

### Control Class

Common

### Control Objective

자산의 분류·중요도·업무 의존성·가용 자원·조직 목표에 미치는 영향을 기준으로 우선순위를 정하여 보호·복구·투자 의사결정에 일관되게 반영합니다.

### Control Statement

모든 자산을 같은 수준으로 관리하면 중요한 서비스와 정보에 필요한 자원이 부족해지거나 낮은 위험의 자산에 과도한 통제가 적용될 수 있습니다. 조직은 법적 요구, 기밀성·무결성·가용성 영향, 업무 중단 영향과 대체가능성을 고려해 자산의 중요도와 보안등급을 산정하고 관련 의사결정에 사용해야 합니다.

### 적용 조건

관리체계 범위에서 식별된 하드웨어, 소프트웨어, 시스템, 서비스, 데이터·정보 및 관련 시설에 적용합니다. 우선순위는 해당 자산의 소유자와 업무 영향 정보를 근거로 정합니다.

### Control Owner

정보자산 관리책임자 / 정보보호 위험관리 책임자

### Stakeholders

자산·서비스 소유자, 업무연속성, 개인정보보호, IT 운영, 개발, 재무·구매

### 매핑된 ISMS-P 항목

1.2.1, 2.1.3

### 매핑된 CSF 항목

ID.AM-05

### Implementation Guide

1. **자산 평가 기준을 정한다.** - 법적·계약상 요구, 정보의 민감도, 기밀성·무결성·가용성 영향, 업무 목표와 서비스 중단 영향, 대체가능성 및 복구 자원을 반영한 중요도·보안등급 기준을 정의한다.
2. **자산소유자와 함께 평가한다.** - 자산목록의 각 항목에 업무 기능과 의존관계를 연결하고, 자산소유자가 근거를 확인하여 중요도·보안등급·우선순위를 승인하도록 한다.
3. **우선순위를 통제와 자원 배분에 사용한다.** - 접근통제, 패치·취약점 조치, 모니터링, 백업·복구, 공급자 관리와 개선계획의 순서 및 수준을 자산 우선순위에 맞춘다.
4. **변경 시 재평가한다.** - 업무·법규·위협·데이터·의존관계 또는 서비스 영향이 달라지면 중요도와 우선순위를 재검토하고 목록과 관련 계획을 갱신한다.

### Evidence

- 자산 분류·중요도 평가기준: 평가 항목, 등급과 판단 방법을 확인할 수 있는 자료.
- 자산별 평가·승인 기록: 자산소유자의 평가 근거와 승인 결과를 확인할 수 있는 자료.
- 우선순위가 반영된 보호·복구·개선계획: 자산 중요도에 따라 통제와 자원이 달라지는 것을 확인할 수 있는 자료.
- 재평가 이력: 변경 사유와 등급·우선순위 조정 결과를 확인할 수 있는 자료.

## GZ-AST-005

### Control Name

데이터·메타데이터 인벤토리 유지

### Security Domain

Asset Management

### Control Class

Common

### Control Objective

지정된 데이터 유형과 해당 메타데이터를 식별하고 위치·처리목적·흐름·소유자·보유기간·민감도를 최신으로 유지하여, 데이터의 전 처리단계에 적절한 보호와 법적 요구사항을 적용합니다.

### Control Statement

데이터가 어디에서 수집·저장·이용·제공·파기되는지 알 수 없으면 접근통제, 보유기간, 처리방침과 파기 의무를 정확히 적용하기 어렵습니다. 조직은 개인정보와 중요정보를 포함한 지정 데이터 유형의 목록과 흐름을 관리하고, 시스템·업무 변화에 따라 메타데이터와 관련 문서를 현행화해야 합니다.

### 적용 조건

관리체계 범위에서 조직이 보호 대상으로 지정한 개인정보, 중요정보, 업무·분석 데이터와 그 저장소·인터페이스·처리 활동에 적용합니다. 개인정보 관련 항목은 실제 처리현황과 적용 법규를 기준으로 관리합니다.

### Control Owner

데이터 거버넌스 책임자 / 개인정보보호책임자

### Stakeholders

업무부서 데이터 소유자, 정보보호, 시스템·DB 운영, 개발, 법무, 외부자 관리

### 매핑된 ISMS-P 항목

3.2.1, 1.2.2, 3.5.1

### 매핑된 CSF 항목

ID.AM-07

### Implementation Guide

1. **데이터 유형과 메타데이터 기준을 정한다.** - 데이터 유형, 항목, 처리 목적·근거, 소유자·관리자, 저장 위치, 시스템, 출처·수령자, 보유기간, 민감도·보안등급, 국외·외부 제공 여부 등 필요한 속성을 정의한다.
2. **처리현황과 흐름을 목록화한다.** - 업무 인터뷰, 시스템·DB 구조, 인터페이스, 위탁·제공 현황과 처리방침을 대조하여 수집부터 보유·이용·제공·파기까지의 위치와 흐름을 기록한다.
3. **데이터 목록과 관련 문서를 연결한다.** - 데이터 목록, 개인정보 현황표·흐름도, 자산목록, 보유·파기 기준과 개인정보 처리방침이 같은 처리현황을 반영하도록 책임자와 갱신 절차를 정한다.
4. **변화와 불일치를 검토한다.** - 신규 서비스·데이터, 목적·항목·보유기간·제공처 변경 시 목록과 흐름을 갱신하고, 실제 처리현황과 문서 간 불일치를 조치한다.

### Evidence

- 데이터·메타데이터 목록: 데이터 유형, 항목, 위치, 소유자, 목적·근거, 보유기간과 민감도를 확인할 수 있는 자료.
- 개인정보 현황표·데이터 흐름도: 처리단계, 시스템·인터페이스, 제공·위탁과 파기 흐름을 확인할 수 있는 자료.
- 데이터 처리 관련 기준·처리방침: 목록에 기록된 처리 목적, 항목, 보유기간과 공개 내용의 일치 여부를 확인할 수 있는 자료.
- 변경·정합성 검토 기록: 신규·변경 데이터가 목록과 흐름에 반영되고 불일치가 조치되었는지 확인할 수 있는 자료.

## GZ-AST-006

### Control Name

소프트웨어 수명주기 관리

### Security Domain

Asset Management

### Control Class

Common

### Control Objective

소프트웨어를 도입·개발·운영·유지보수·교체·제거하는 전 과정에서 위험과 지원상태를 관리하여, 취약하거나 불필요한 소프트웨어가 조직 자산과 서비스를 위협하지 않도록 합니다.

### Control Statement

소프트웨어의 버전, 지원 종료와 사용 상태가 관리되지 않으면 알려진 취약점과 미승인 구성요소가 장기간 남고, 교체·제거 과정에서 데이터와 설정이 방치될 수 있습니다. 조직은 중요도와 위험에 따라 소프트웨어의 변경·패치·교체·제거를 계획하고, 목록과 기술 기록을 함께 갱신해야 합니다.

### 적용 조건

관리체계 범위에서 사용하는 운영체제, 미들웨어, DBMS, 상용·오픈소스 패키지, 애플리케이션, 펌웨어와 보안 소프트웨어에 적용합니다.

### Control Owner

애플리케이션·플랫폼 운영책임자

### Stakeholders

시스템·서비스 소유자, 개발·배포, 정보보호, 구매·라이선스, 공급자 관리, 데이터 소유자

### 매핑된 ISMS-P 항목

2.9.1, 2.10.8, 2.9.7, 1.2.1

### 매핑된 CSF 항목

PR.PS-02

### Implementation Guide

1. **수명주기 상태와 판단 기준을 정의한다.** - 도입, 승인, 운영, 유지보수, 지원 종료 예정, 교체, 사용중지, 제거 상태와 각 단계의 책임·승인·보안 검토·기록 요건을 정한다.
2. **유지보수와 변경을 위험에 맞게 수행한다.** - 소프트웨어 중요도와 취약점, 제조사 지원정보를 바탕으로 패치·업그레이드·구성 변경을 계획하고 사전 영향분석, 승인, 시험, 복구방안과 이력을 관리한다.
3. **지원 종료와 노후화를 관리한다.** - 지원 종료·임박 또는 유지보수 불가 소프트웨어를 식별하여 교체·격리·기능 제한 등 처리계획을 수립하고, 지연 시 위험과 보완대책을 승인받아 추적한다.
4. **제거와 종료를 확인한다.** - 미사용·중복·승인 취소 소프트웨어를 제거하고 계정·라이선스·키·데이터·연계·저장매체를 정리하며, 목록과 운영문서를 갱신하고 제거 결과를 검증한다.

### Evidence

- 소프트웨어 수명주기 기준·목록: 버전, 지원상태, 소유자, 위험과 수명주기 상태를 확인할 수 있는 자료.
- 패치·변경 기록: 영향분석, 승인, 시험, 배포, 복구방안과 적용 결과를 확인할 수 있는 자료.
- 지원 종료·교체 계획: 노후 소프트웨어의 위험, 보완대책, 담당자·기한과 진행상태를 확인할 수 있는 자료.
- 제거·폐기 완료 기록: 소프트웨어, 라이선스·키, 데이터와 연계가 정리되고 목록이 갱신되었는지 확인할 수 있는 자료.

## GZ-AST-007

### Control Name

하드웨어 수명주기 관리

### Security Domain

Asset Management

### Control Class

Common

### Control Objective

하드웨어를 도입·배치·운영·유지보수·교체·재사용·폐기하는 전 과정에서 위험과 상태를 관리하여, 장애·지원 종료·정보 잔존으로 인한 보안 및 업무 영향을 줄입니다.

### Control Statement

노후 장비와 저장매체의 상태가 관리되지 않으면 장애와 취약점 위험이 증가하고, 수리·재사용·폐기 과정에서 개인정보와 중요정보가 유출될 수 있습니다. 조직은 자산 중요도와 위험에 따라 유지보수·교체·제거를 계획하고, 저장매체 정보가 복구되지 않도록 처리 결과를 확인해야 합니다.

### 적용 조건

관리체계 범위의 서버, 단말, 네트워크·보안장비, 저장장치와 해당 장비의 부품·매체에 적용합니다. 임차·리스 장비와 외부업체 유지보수·폐기에도 책임과 확인 절차를 적용합니다.

### Control Owner

IT 인프라·하드웨어 자산관리 책임자

### Stakeholders

자산·서비스 소유자, 정보보호, 구매·재무, 시설, 헬프데스크, 개인정보보호, 유지보수·폐기 업체

### 매핑된 ISMS-P 항목

2.1.3, 2.9.7, 1.2.1

### 매핑된 CSF 항목

PR.PS-03

### Implementation Guide

1. **하드웨어 수명주기 기준을 정한다.** - 도입, 검수, 배치, 운영, 수리, 지원 종료, 교체, 재사용, 반출과 폐기 상태별 책임·승인·보안 요구와 기록 항목을 정의한다.
2. **상태와 지원 정보를 관리한다.** - 자산목록에 제조사·모델·보증·지원 종료·위치·소유자·고장·수리·부품 교체 이력을 연결하고 중요도와 위험에 따라 유지보수·교체 계획을 수립한다.
3. **수리·반출·교체 과정의 정보를 보호한다.** - 외부 반출과 저장매체 교체 시 승인, 인계, 데이터 백업·삭제, 접근 제한과 반환 확인 절차를 적용한다.
4. **재사용·폐기 결과를 검증한다.** - 재사용 전 데이터 초기화와 보안 설정을 확인하고, 폐기 시 복구되지 않는 방법을 적용하여 담당자·확인자·방법·일자와 증적을 남긴 뒤 자산목록을 종료 상태로 갱신한다.

### Evidence

- 하드웨어 수명주기 기준·자산목록: 지원상태, 위치, 소유자, 운영상태와 이력을 확인할 수 있는 자료.
- 유지보수·교체 계획 및 작업기록: 자산 중요도와 위험에 따른 수리·교체 판단과 결과를 확인할 수 있는 자료.
- 반출·인계·저장매체 교체 기록: 외부 작업 과정의 정보보호와 반환 여부를 확인할 수 있는 자료.
- 재사용·폐기 대장과 확인증: 삭제·파쇄 등 처리 방법, 담당자·확인자, 일자와 완료 증적을 확인할 수 있는 자료.
