# Secure Configuration - Common Controls

Secure Configuration Domain의 Common Control은 승인된 보안 구성의 수립·유지와 비인가 소프트웨어·코드의 설치·실행 방지를 위한 공통 요구사항을 제공합니다.

---

## GZ-SCF-001 승인된 보안 구성의 수립·유지와 비인가 구성 변경 방지

### Control ID

내용 작성 예정

### Security Domain

Secure Configuration

### Control Class

Common

### Control Objective

하드웨어·소프트웨어·서비스·클라우드의 승인된 보안 구성기준을 수립·적용·유지하고 변경과 편차를 통제하여, 설정 오류와 비인가 변경으로 인한 위험을 줄입니다.

### Control Statement

기본 설정, 과도한 기능과 비인가 구성 변경은 공격 표면과 정보 유출 가능성을 높입니다. 조직은 자산 유형과 위험에 맞는 보안 기준선을 정하고, 구성 변경을 승인·검증하며 실제 상태를 기준선과 비교하여 편차와 예외를 관리해야 합니다.

### 적용 조건

관리체계 범위의 서버·운영체제·DBMS·네트워크·보안장비·단말·애플리케이션·가상화·컨테이너·클라우드 서비스와 관련 관리도구에 적용합니다.

### Control Owner

IT 구성관리 책임자

### Stakeholders

시스템·서비스 소유자, 정보보호, 개발·배포, 네트워크·클라우드 운영, 개인정보보호, 공급자, 내부감사

### 매핑된 ISMS-P 항목

2.9.1, 2.10.1, 2.10.2

### 매핑된 CSF 항목

PR.PS-01

### Implementation Guide

1. **자산별 보안 구성기준을 수립한다.** - 제조사·공공 가이드, 조직 정책과 위험평가를 바탕으로 계정·인증, 권한, 서비스·포트, 암호화, 로그, 원격관리, 패치와 클라우드 보안설정 등 기준 항목을 정의하고 승인한다.
2. **기준 구성을 안전하게 배포·보호한다.** - 표준 이미지·템플릿·자동화 또는 체크리스트를 사용해 승인된 기준을 적용하고, 기준 파일과 관리도구의 변경권한·버전·무결성을 통제한다.
3. **구성 변경을 관리한다.** - 변경 전 보안·성능·업무 영향을 분석하고 요청·승인·시험·복구방안·구현·검증·문서 갱신과 이력을 관리한다. 보안시스템과 클라우드 설정은 책임·권한과 예외 절차를 명확히 한다.
4. **비인가 변경과 편차를 탐지·조치한다.** - 실제 구성을 승인 기준선과 비교하여 미승인 변경, 불필요 기능, 과도한 허용과 기준 미준수를 식별하고 복구·위험평가·예외승인·개선 조치를 추적한다.

### Evidence

- 보안 구성기준·표준 이미지·템플릿: 자산 유형별 승인 기준과 버전을 확인할 수 있는 자료.
- 구성 배포·점검 결과: 실제 자산에 기준이 적용되고 편차가 식별되었는지 확인할 수 있는 자료.
- 구성 변경·영향분석·승인 기록: 변경 사유, 보안·성능 영향, 시험·복구와 검증 결과를 확인할 수 있는 자료.
- 비인가 변경·예외·개선 추적표: 기준 편차의 위험평가, 승인, 복구와 완료 상태를 확인할 수 있는 자료.
- 보안시스템·클라우드 설정 검토 기록: 정책·룰셋·권한·감사기록과 설정 적정성 검토를 확인할 수 있는 자료.

## GZ-SCF-002 비인가 소프트웨어와 코드의 설치·실행 방지

### Control ID

내용 작성 예정

### Security Domain

Secure Configuration

### Control Class

Common

### Control Objective

업무에 승인되지 않은 소프트웨어와 코드를 설치·실행하지 못하도록 예방·탐지·대응하여, 악성코드·취약 소프트웨어·라이선스 및 데이터 유출 위험을 줄입니다.

### Control Statement

사용자나 공격자가 임의로 프로그램·스크립트·확장기능을 설치·실행하면 악성코드 감염, 보안통제 우회와 정보 유출이 발생할 수 있습니다. 조직은 허용 기준과 설치권한을 관리하고 기술적 실행통제와 모니터링을 적용하며, 탐지된 비인가 항목을 조사·차단·제거해야 합니다.

### 적용 조건

관리체계 범위의 서버, 업무용 PC·노트북·가상PC·모바일 기기, 클라우드·컨테이너 실행환경과 해당 환경에서 실행되는 프로그램·패키지·스크립트·매크로·브라우저 확장기능에 적용합니다.

### Control Owner

엔드포인트·플랫폼 보안 운영책임자

### Stakeholders

정보보호, 시스템·서비스 소유자, IT 헬프데스크, 개발·배포, 인사·교육, 개인정보보호, 내부감사

### 매핑된 ISMS-P 항목

2.10.6, 2.10.9

### 매핑된 CSF 항목

PR.PS-05

### Implementation Guide

1. **허용·금지 기준과 예외 절차를 정한다.** - 업무 목적, 공급경로, 서명·무결성, 버전·지원상태와 위험을 기준으로 허용 소프트웨어·코드와 금지 유형을 정의하고 설치·실행 승인 및 예외의 책임·기한·검토 기준을 정한다.
2. **설치와 실행 권한을 제한한다.** - 일반 사용자에게 불필요한 관리자 권한을 부여하지 않고, 승인된 배포경로·응용프로그램 제어·모바일 관리·스크립트 및 매크로 정책 등 환경에 맞는 통제를 적용한다.
3. **악성·비인가 항목을 예방·탐지한다.** - 백신·엔드포인트 보안, 파일·패키지 검증, 실행 로그와 설치목록을 이용해 최신 악성코드와 미승인 프로그램·코드의 설치·실행을 탐지하고 보호기능을 최신 상태로 유지한다.
4. **탐지 결과와 예외를 조치한다.** - 비인가 설치·실행을 차단·격리·제거하고 원인·영향·사용자·확산 여부를 확인하며, 필요한 사고대응·교육·권한조정과 기준 개선을 수행한다.

### Evidence

- 허용·금지 소프트웨어·코드 기준과 예외대장: 승인 기준, 책임자, 기한과 검토 상태를 확인할 수 있는 자료.
- 단말·서버 보안정책과 기술 설정: 관리자 권한, 배포경로, 응용프로그램·스크립트 실행통제를 확인할 수 있는 자료.
- 백신·엔드포인트 보안 운영기록: 보호기능 업데이트, 악성코드 예방·탐지와 처리 결과를 확인할 수 있는 자료.
- 설치·실행 로그 및 조치 티켓: 비인가 항목의 차단·격리·제거, 영향분석과 후속 조치를 확인할 수 있는 자료.
