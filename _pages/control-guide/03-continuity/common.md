Continuity Domain의 Common Controls는 백업, 복원력, 용량, 사고복구 실행과 대외 소통을 통해 핵심 업무와 서비스의 지속성을 확보하기 위한 공통 요구사항을 제공합니다.

---

## CON-C-01

### Control Name

신뢰할 수 있는 백업의 확보와 데이터 복구 가능성 보장

### Security Domain

Continuity

### Control Class

Common

### Control Objective

중요 데이터와 시스템 설정의 백업을 생성하고 안전하게 보호·유지하며 정기적으로 복구를 시험하여 실제 사고 시 필요한 시점과 범위로 데이터를 복원할 수 있도록 합니다.

### Control Statement

백업 파일이 존재하더라도 손상·암호화·삭제되었거나 복구 절차가 검증되지 않으면 사고 시 사용할 수 없습니다. 조직은 백업 대상, 주기, 보관 위치, 보호방법과 복구 목표를 정하고 백업 결과와 복구 가능성을 지속적으로 확인해야 합니다.

### 적용 조건

#### 적용 시점

시스템·서비스를 신규 도입하거나 중요 데이터·구성이 변경될 때 적용합니다. 정기 백업, 백업 정책 검토, 복구시험 및 사고·재해 복구 시에도 적용합니다.

#### 적용 대상

핵심 업무시스템, 데이터베이스, 파일·문서, 클라우드 데이터, 시스템·네트워크 설정, 복구에 필요한 로그와 암호키 자료에 적용합니다. 관련 법령은 개인정보를 처리하는 시스템과 적용 요건을 충족하는 개인정보처리자에게 적용합니다.

#### 관련 법령

- [「개인정보 보호법」 제29조](https://www.law.go.kr/법령/개인정보보호법/제29조) — 개인정보 유출 등을 방지하기 위한 기술적·관리적·물리적 안전조치 의무를 규정합니다.
- [「개인정보의 안전성 확보조치 기준」 제11조](https://www.law.go.kr/행정규칙/개인정보의안전성확보조치기준/제11조) — 적용 대상 개인정보처리자의 재해·재난 대응절차와 백업·복구 계획 수립 등을 규정합니다.

### Control Owner

IT 운영·백업복구 책임자

### Stakeholders

데이터·서비스 소유자, 정보보호, 개인정보보호, 업무연속성, 클라우드·인프라 운영, 공급자, 내부감사

### 매핑된 ISMS-P 항목

- 2.9.3 백업 및 복구관리

### 매핑된 CSF 항목

**PR.DS-11 — Backups of data are created, protected, maintained, and tested.**

데이터 백업을 생성하고 안전하게 보호·유지하며 실제 복구 가능성을 시험하는 Outcome입니다.

### Implementation Guide

1. **백업 대상과 복구 요구사항을 정합니다.**
   - 업무 중요도와 법적·계약상 요구를 반영해 백업 대상, 주기, 보유기간, 복구 목표시간(RTO)과 복구 목표시점(RPO), 책임자를 정합니다.
2. **백업을 생성하고 안전하게 보호합니다.**
   - 자동화된 백업을 운영하고 운영환경과 분리된 저장소, 접근권한 제한, 암호화, 변경·삭제 방지와 외부 보관 등 위험에 맞는 보호조치를 적용합니다.
3. **백업 성공 여부와 보관 상태를 관리합니다.**
   - 백업 작업 결과, 누락·오류, 용량, 보유기간과 삭제 일정을 확인하고 실패 시 원인과 재수행 결과를 기록합니다.
4. **복구시험으로 실제 복원 가능성을 확인합니다.**
   - 대표 데이터와 핵심 시스템을 대상으로 정기 복구시험을 수행하고 완전성, 복구시간, 업무 기능과 미흡사항을 확인하여 절차를 개선합니다.

### Evidence

- 백업 정책·절차 및 대상 목록
- 백업 작업 결과·오류 및 재수행 기록
- 백업 저장소 접근권한·암호화·변경방지 설정
- 복구시험 계획·결과 및 개선조치 기록

## CON-C-02

### Control Name

정상·비정상 상황에서 기술 인프라의 요구 복원력 유지

### Security Domain

Continuity

### Control Class

Common

### Control Objective

정상 운영뿐 아니라 장애·공격·재해 등 비정상 상황에서도 핵심 기술 인프라가 정해진 복원력과 서비스 수준을 유지하거나 신속히 회복할 수 있도록 합니다.

### Control Statement

단일 장비나 회선, 특정 인력과 공급자에 과도하게 의존하면 작은 장애도 장시간 서비스 중단으로 이어질 수 있습니다. 조직은 핵심 서비스의 복원력 요구를 정하고 이중화, 자동 전환, 우회 운영, 백업·복구와 수동 대체절차를 함께 준비하고 검증해야 합니다.

### 적용 조건

#### 적용 시점

신규 서비스·인프라 설계, 중요 변경, 위험평가, 장애·사고·재해 대응계획 수립 및 정기 복원력 시험 시 적용합니다.

#### 적용 대상

핵심 업무를 지원하는 서버·저장장치·네트워크·클라우드·보안시스템, 외부 서비스와 운영 인력·절차에 적용합니다. 개인정보 관련 법적 의무는 해당 법령의 적용 요건에 따라 적용합니다.

#### 관련 법령

- [「개인정보 보호법」 제29조](https://www.law.go.kr/법령/개인정보보호법/제29조) — 개인정보 유출 등을 방지하기 위한 기술적·관리적·물리적 안전조치 의무를 규정합니다.
- [「개인정보의 안전성 확보조치 기준」 제11조](https://www.law.go.kr/행정규칙/개인정보의안전성확보조치기준/제11조) — 적용 대상 개인정보처리자의 재해·재난 대응절차와 백업·복구 계획 수립 등을 규정합니다.

### Control Owner

업무연속성 책임자 / IT 인프라 운영책임자

### Stakeholders

서비스 소유자, 정보보호, 개인정보보호, 재해복구, 네트워크·클라우드 운영, 공급자, 경영진

### 매핑된 ISMS-P 항목

- 2.9.2 성능 및 장애관리
- 2.9.3 백업 및 복구관리
- 2.12.1 재해·재난 대비 안전조치
- 2.12.2 재해 복구 시험 및 개선

### 매핑된 CSF 항목

**PR.IR-03 — Mechanisms are implemented to achieve resilience requirements in normal and adverse situations.**

정상 상황과 장애·공격 등 비정상 상황 모두에서 정해진 복원력 수준을 달성할 수 있는 체계를 구현하는 Outcome입니다.

### Implementation Guide

1. **서비스별 복원력 요구를 정합니다.**
   - 업무 영향과 위험을 분석하여 허용 중단시간, 필요한 서비스 수준, 복구 우선순위와 정상·비정상 상황별 운영 목표를 정합니다.
2. **복원력 확보 방안을 설계·구현합니다.**
   - 이중화, 자동 전환, 지역 분산, 백업·복구, 우회 처리와 수동 대체절차를 조합하고 단일 장애 지점을 줄입니다.
3. **운영상태와 장애 징후를 확인합니다.**
   - 가용성, 전환 상태, 구성요소 건강상태와 공급자 의존성을 모니터링하고 이상 징후와 미충족 사항을 조치합니다.
4. **정상·비정상 상황을 시험하고 개선합니다.**
   - 장애, 공격, 전원·회선 중단과 공급자 장애 시나리오로 전환·복구를 시험하고 결과를 설계와 절차에 반영합니다.

### Evidence

- 복원력 요구사항·업무영향분석 자료
- 이중화·분산·우회 구조도와 설정
- 가용성·장애 모니터링 및 조치 기록
- 복원력·재해복구 시험 결과와 개선계획

## CON-C-03

### Control Name

적정 자원 용량 확보를 통한 시스템·서비스 가용성 보장

### Security Domain

Continuity

### Control Class

Common

### Control Objective

업무량과 성장 전망에 맞는 처리·저장·통신 자원 용량을 확보하고 임계치 도달 전에 조치하여 시스템과 서비스의 가용성을 유지합니다.

### Control Statement

용량 부족은 성능 저하, 처리 지연과 서비스 중단으로 이어질 수 있습니다. 조직은 현재 사용량과 최대 부하를 측정하고 수요 변화를 예측하여 증설·최적화·부하분산 계획을 선제적으로 실행해야 합니다.

### 적용 조건

#### 적용 시점

신규 시스템 설계, 용량 변경, 대규모 행사·정기 마감 등 최대 부하 예상 시점, 정기 성능 검토와 임계치 초과 시 적용합니다.

#### 적용 대상

서버의 연산·메모리, 저장공간, 데이터베이스, 네트워크 대역폭, 클라우드 한도, 라이선스와 외부 서비스 처리용량에 적용합니다.

#### 관련 법령

- [「개인정보 보호법」 제29조](https://www.law.go.kr/법령/개인정보보호법/제29조) — 개인정보 유출 등을 방지하기 위한 기술적·관리적·물리적 안전조치 의무를 규정합니다.

### Control Owner

IT 성능·용량관리 책임자

### Stakeholders

서비스 소유자, 인프라·클라우드 운영, 개발, 정보보호, 재무·구매, 공급자

### 매핑된 ISMS-P 항목

- 2.9.2 성능 및 장애관리

### 매핑된 CSF 항목

**PR.IR-04 — Adequate resource capacity to ensure availability is maintained.**

시스템과 서비스의 가용성을 유지할 수 있도록 충분한 처리·저장·통신 자원 용량을 확보하는 Outcome입니다.

### Implementation Guide

1. **용량 지표와 임계치를 정합니다.**
   - 서비스 수준과 업무 특성을 반영해 연산·메모리·저장·통신 용량 지표, 경고·조치 임계치와 책임자를 정합니다.
2. **사용량과 최대 부하를 측정합니다.**
   - 평균·최대 사용량, 증가율, 병목과 장애 이력을 지속적으로 수집하고 데이터의 정확성을 확인합니다.
3. **수요를 예측하고 자원을 확보합니다.**
   - 성장계획, 계절성, 신규 기능과 장애 시 여유용량을 고려해 증설, 자동 확장, 최적화와 부하분산 계획을 수립합니다.
4. **임계치 초과와 계획 이행을 관리합니다.**
   - 경고 발생 시 원인을 분석하고 단기 완화와 장기 개선을 수행하며 조치 완료와 가용성 효과를 확인합니다.

### Evidence

- 용량관리 기준·지표·임계치
- 성능·용량 모니터링 보고서
- 수요예측·증설·최적화 계획과 승인기록
- 임계치 초과 알림·장애·조치 기록

## CON-C-04

### Control Name

승인되고 일관된 대외 커뮤니케이션을 통한 정확한 복구 정보 제공과 신뢰 보호

### Security Domain

Continuity

### Control Class

Common

### Control Objective

사고 복구에 관한 대외 정보를 승인된 채널과 메시지로 정확하고 일관되게 제공하여 혼선을 줄이고 고객·관계기관·대중의 신뢰를 보호합니다.

### Control Statement

확인되지 않은 복구정보나 부서별로 다른 메시지가 공개되면 법적 의무 위반, 추가 피해와 신뢰 하락이 발생할 수 있습니다. 조직은 대외 공지의 승인권자, 법적 검토, 채널, 메시지 원칙과 정정 절차를 미리 정하고 사실에 근거해 소통해야 합니다.

### 적용 조건

#### 적용 시점

사이버사고·개인정보 유출·서비스 중단의 복구 과정에서 고객, 언론, 대중 또는 관계기관에 정보를 제공하거나 기존 공지를 수정할 때 적용합니다.

#### 적용 대상

홈페이지·앱 공지, 고객 안내, 보도자료, 사회관계망서비스, 관계기관 신고·보고와 공식 대변인 활동에 적용합니다.

#### 관련 법령

- [「개인정보 보호법」 제34조](https://www.law.go.kr/법령/개인정보보호법/제34조) — 개인정보 유출 사실의 통지와 신고에 필요한 사항을 규정합니다.

### Control Owner

대외 커뮤니케이션 책임자 / 사고대응 책임자

### Stakeholders

경영진, 법무·컴플라이언스, 개인정보보호, 정보보호, 고객지원, 홍보, 서비스 소유자

### 매핑된 ISMS-P 항목

- 2.11.5 사고 대응 및 복구

### 매핑된 CSF 항목

**RC.CO-04 — Public updates on incident recovery are shared using approved methods and messaging.**

사고 복구에 관한 대외 정보를 승인된 방법과 메시지로 일관되게 제공하는 Outcome입니다.

### Implementation Guide

1. **대외 소통 기준과 승인체계를 정합니다.**
   - 공개 범위, 승인권자, 법무·개인정보 검토, 대변인, 사용 채널과 긴급 승인 절차를 정의합니다.
2. **검증된 사실과 법적 요구를 확인합니다.**
   - 사고 범위, 영향, 복구상태, 이용자 조치사항과 통지·신고 요건을 확인하고 추정과 미확인 정보를 구분합니다.
3. **승인된 메시지로 공지합니다.**
   - 대상별 템플릿을 활용하여 이해하기 쉬운 표현으로 적시에 공개하고 채널별 내용과 시점을 일치시킵니다.
4. **반응과 변경사항을 반영합니다.**
   - 문의·오해·보도내용과 복구상태 변화를 모니터링하여 필요한 정정·추가 공지를 승인받아 제공하고 이력을 남깁니다.

- 홈페이지·고객안내·보도자료 게시 이력

## CON-C-05

### Security Domain

Continuity

### Control Class

Common

### Control Objective

사고대응 과정에서 복구가 시작되면 승인된 복구계획을 적시에 실행하고 대응조직과 복구조직의 활동을 연결하여 핵심 서비스를 체계적으로 회복합니다.

### Control Statement

복구계획이 있어도 개시 기준, 지휘체계와 실행순서가 불명확하면 대응과 복구가 지연되거나 충돌할 수 있습니다. 조직은 복구 개시를 공식 결정하고 역할·연락망·복구절차·의존관계를 확인하며 진행상황과 의사결정을 기록해야 합니다.

### 적용 조건

#### 적용 시점

사고대응 과정에서 복구 개시 기준을 충족하거나 권한 있는 책임자가 복구를 결정한 시점부터 서비스 정상화와 복구 종료 전까지 적용합니다.

#### 적용 대상

사고로 영향을 받은 시스템·서비스·데이터·시설·업무절차와 복구에 참여하는 내부조직·공급자·관계기관에 적용합니다.

#### 관련 법령

- [「개인정보의 안전성 확보조치 기준」 제11조](https://www.law.go.kr/행정규칙/개인정보의안전성확보조치기준/제11조) — 적용 대상 개인정보처리자의 재해·재난 대응절차와 백업·복구 계획 수립 등을 규정합니다.

사고복구 책임자 / 업무연속성 책임자

### Stakeholders

- 2.12.1 재해·재난 대비 안전조치

사고대응 과정에서 복구가 시작되면 사고대응 계획의 복구 절차를 실제로 실행하는 Outcome입니다.

### Implementation Guide

1. **복구 개시 기준과 권한을 확인합니다.**
   - 사고 심각도, 영향, 대응상태와 복구 준비도를 검토하고 권한 있는 책임자가 복구 개시와 지휘체계를 승인합니다.
2. **복구조직과 자원을 가동합니다.**
   - 역할·연락망·공급자 지원, 복원 자산, 대체환경과 필요한 인력을 확인하고 실행 담당자에게 절차를 전달합니다.
3. **승인된 순서에 따라 복구를 실행합니다.**
   - 격리·정화, 데이터·시스템 복원, 의존 서비스 연결과 기능 확인을 수행하며 변경·예외·실패를 통제합니다.

#### 적용 시점

사고·재해의 영향이 확인되고 복구 대상을 선정하거나 상황 변화로 복구 범위와 우선순위를 다시 정할 때 적용합니다.

#### 적용 대상

- [「개인정보의 안전성 확보조치 기준」 제11조](https://www.law.go.kr/행정규칙/개인정보의안전성확보조치기준/제11조) — 적용 대상 개인정보처리자의 재해·재난 대응절차와 백업·복구 계획 수립 등을 규정합니다.

업무연속성 책임자 / 사고복구 책임자

### Stakeholders

업무·서비스 소유자, 정보보호, 개인정보보호, IT 운영, 위험관리, 공급자, 경영진

### 매핑된 ISMS-P 항목

- 2.11.5 사고 대응 및 복구
- 2.12.1 재해·재난 대비 안전조치

위험과 업무 영향을 고려해 복구조치를 선정하고 범위·우선순위를 정하여 수행하는 Outcome입니다.

### Implementation Guide

1. **복구 의사결정 기준을 정합니다.**
   - 업무 중요도, 허용 중단시간, 데이터 손실 허용범위, 법적 의무, 의존관계와 안전성을 반영한 기준을 정의합니다.
2. **사고 영향과 복구 가능성을 평가합니다.**
   - 피해 범위, 자산 신뢰성, 이용 가능한 인력·복원 자산·대체환경과 남아 있는 위험을 확인합니다.
3. **범위와 우선순위를 승인합니다.**
   - 핵심 업무와 선행 의존성을 기준으로 복구 대상·순서·담당자·예상시간과 제외 대상을 정하고 승인합니다.
4. **우선순위에 따라 수행하고 재평가합니다.**
   - 복구를 실행하면서 상황·자원·위험 변화를 확인하고 필요하면 우선순위와 범위를 다시 승인·조정합니다.

Continuity

Common

### 적용 조건

#### 적용 시점

백업·시스템 이미지·설정파일·설치매체를 실제 복구에 사용하기 직전과 정기 복구시험 시 적용합니다.

#### 적용 대상

데이터 백업, 스냅샷, 가상머신 이미지, 시스템·네트워크 설정, 설치파일, 암호키 자료와 공급자가 제공한 복원 자산에 적용합니다.

#### 관련 법령

- [「개인정보 보호법」 제29조](https://www.law.go.kr/법령/개인정보보호법/제29조) — 개인정보 유출 등을 방지하기 위한 기술적·관리적·물리적 안전조치 의무를 규정합니다.
- [「개인정보의 안전성 확보조치 기준」 제11조](https://www.law.go.kr/행정규칙/개인정보의안전성확보조치기준/제11조) — 적용 대상 개인정보처리자의 재해·재난 대응절차와 백업·복구 계획 수립 등을 규정합니다.

### Control Owner

백업복구 책임자 / 정보보호 운영책임자

### Stakeholders

시스템·데이터 소유자, 사고대응, 악성코드 분석, IT·클라우드 운영, 개인정보보호, 공급자

### 매핑된 ISMS-P 항목

- 2.9.3 백업 및 복구관리
- 2.12.2 재해 복구 시험 및 개선

### 매핑된 CSF 항목

**RC.RP-03 — The integrity of backups and other restoration assets is verified before using them for restoration.**

복구에 사용하기 전에 백업과 다른 복원 자산이 오염·변조·손상되지 않았는지 확인하는 Outcome입니다.

### Implementation Guide

1. **신뢰할 수 있는 복원 자산을 식별합니다.**
   - 자산의 출처, 생성시점, 보관 위치, 소유자와 사고 발생 전 정상상태 여부를 확인하여 후보를 선정합니다.
2. **무결성과 오염 여부를 검증합니다.**
   - 해시값·서명·백업 로그를 확인하고 악성코드 검사와 변경 이력 검토를 통해 손상·변조·감염 여부를 점검합니다.
3. **격리된 환경에서 복원을 시험합니다.**
   - 운영환경과 분리된 공간에서 복원, 기동, 데이터 일관성과 핵심 기능을 확인하고 문제가 있으면 다른 복원 자산을 선정합니다.
4. **사용을 승인하고 검증 결과를 기록합니다.**
   - 검증 담당자와 승인자가 결과와 남은 위험을 확인한 뒤 실제 복구 사용을 승인하고 증적을 보관합니다.

- 격리환경 복원시험·기능검증 결과
- 복원 자산 사용 승인 및 예외 기록

### 매핑된 CSF 항목

**RC.RP-04 — Critical mission functions and cybersecurity risk management are considered to establish post-incident operational norms.**

사고 이후 운영 상태를 정할 때 핵심 업무와 남아 있는 사이버보안 위험을 함께 고려하는 Outcome입니다.

### Implementation Guide

1. **사고 후 필수 운영기능을 정합니다.**
   - 핵심 업무, 최소 서비스 수준, 선행 의존성, 허용 가능한 수동·임시 절차와 운영기간을 정의합니다.
2. **남아 있는 위험과 제한사항을 평가합니다.**
   - 미완료 복구, 임시 계정·권한, 우회 연결, 데이터 불일치와 취약점을 확인하고 업무 영향과 함께 평가합니다.
3. **안전한 임시 운영조건을 승인합니다.**
   - 추가 모니터링, 접근제한, 기능제한, 사용 안내와 종료기한을 포함한 보완조치를 정하고 위험 수용권자의 승인을 받습니다.
4. **정상 운영 전환을 관리합니다.**
   - 남은 복구·개선과제를 추적하고 임시조치 제거, 권한·구성 정상화와 최종 확인을 거쳐 정상 운영으로 전환합니다.

### Evidence

- 사고 후 최소 운영기준·전환계획
- 남은 위험·제한사항 평가와 승인기록
- 임시 계정·연결·보완조치 관리대장
- 정상 운영 전환 점검·승인 기록
